## 1. 目标与设计权威

Mock Up 是设计源头。共有功能以当前 Mock 的布局、样式、文案和交互为基准，两模式实际调用同一套 JSX／组件和样式。Backend 额外需要的字段、权限、加载、错误和分页状态，尽量复用现有 Mock 设计元素补充。

这不改变 Backend 的真实合同、字段语义、权限、校验、写入时机与媒体生命周期。Mock 不因本轮统一被迫增加 Backend 字段或改变保存规则。存在不同业务规则时，明确由连接层提供参数或回调，不通过组件读取数据源模式暗中决定。

本轮不重新设计视觉。实施前以同一视口、相同展示状态记录当前 Mock；共有部分合并后核对布局、间距、字体、按钮及交互。新增 Backend 状态按同页已有字段／提示风格展示。

## 3. 最小组件边界

采用页面局部共享展示：公司清单、公司分区外壳／编排、基本信息共同字段、相册图片组。已有整屏文本、福利、团队、行业选择正文继续使用。仅当前消费者需要的展示参数进入组件，数据获取、草稿、授权、错误处理和写入仍在原连接层。

名称区保留模式各自的字段语义，通过少量显式槽位或局部组件组合复用字段样式；不建立字段 schema、通用表单引擎或通用权限框架。

学校／专业直接复用已有 `src/组件/教育目录候选列表.tsx`：已核对它包装的 `src/组件/目录候选列表.tsx` 与两页均使用 `src/屏幕/入职引导.module.css`，已有名称、可选副文、选中勾和分页尾行，满足本轮需求。不新增第二套教育候选组件，也不修改底层目录组件合同或其它消费者。Backend 将真实 ID 映射为键，Mock 使用当前本地名称键；组件按键回报点击，由页面取回原目录项，禁止按名称反查 Backend ID。加载／空结果／失败提示保留在页面，避免扩大现有组件责任。

比较方案：仅共用 CSS 不能消除重复 JSX；整体重建统一配置式页面会增加不必要机制；选择上述局部共享，是覆盖现有两种消费者且保留业务差异的最小方案。

### 3.1 数据与组件责任

| 边界 | 输入／输出 | 禁止承担的责任 |
| --- | --- | --- |
| 公司清单展示 | 分区状态、只读说明、点击分区回调 → 同一份列表 | 不读企业快照、不计算权限、不调用导航 hook |
| 分区页面外壳／正文编排 | 分区、字段展示值、编辑能力、保存／返回回调、行业子页与必要状态 → 标题、保存栏、正文 | 不管理第二份草稿，不复制 Backend 保存或媒体操作 |
| 基本信息展示 | 名称区、LOGO 地址与选文件回调、共同字段值／变更回调、只读能力 | 不区分数据源模式，不映射 BFF 名称语义，不上传或压图 |
| 相册图片组 | 图片稳定键与 URL、可编辑、可选上传预览、选文件／删除回调 → 图片网格 | 不读取媒体 ID 的领域含义，不发请求，不决定提交时机 |
| 教育候选展示 | 既有候选键／名称／副文／选中、加载中、还有、选定／加载更多回调 | 不查询目录，不持久化，不判断是否允许下一步 |

这些是当前两个消费者的展示边界，不是新增公共领域 API；精确局部 props 名称由 Plan 冻结。名称区可各自组合必要字段，但共同的字段容器／输入展示应复用，不能把两套完整基本信息表单作为槽位塞进同一外壳。

现有状态是唯一事实源：Backend 快照／草稿与 Mock 本地覆盖各自负责读写，组件不复制缓存。相册在途、失败、只读等状态由现有连接层提供，不为视觉统一添加新的请求或持久化字段。

## 4. 必须保持的行为

- Backend 只有有效组织关系可查看对应资料；成员只读、管理员编辑资格保持，不用 Mock 默认权限兜底。
- 常用名校验／唯一冲突、品牌名写入、工商名只读保持，缺失核验信息不从其它名称补造。
- Backend LOGO／相册继续使用权威媒体 URL 与原操作；保留预览清理、失败恢复和未发布媒体处理。Mock 继续原压图、本地 LOGO 更新及相册草稿保存行为。
- 保存失败不返回、不提示成功，草稿和错误按现有流程保留；本轮不修改请求协议或时序。
- 行业子页打开时父表单保留草稿但隐藏，返回／焦点及关闭行为保持。
- 教育 Backend 按引用 ID 选中；同名不同 ID 不误选，用户继续输入清除旧引用，点选不导致结果被重新过滤或分页丢失。
- Mock 学校／专业继续允许非空自由文本；不新增目录 ID 必选规则，不伪造城市／国家、请求延迟或服务端能力。

## 6. 验收责任

1. 结构：共有清单、字段、图片组和候选行实际共用展示组件；不只共用 CSS，也不建立按数据源分出整套 JSX 的伪共享外壳。
2. 视觉：同视口／相同数据状态下，Mock 共有部分相对改动前保持；Backend 共同行遵循 Mock 设计。核对可编辑／只读、名称错误、相册空／满／预览、学校副标题／选中／分页及窄屏溢出。
3. 行为：运行对应四页既有单元测试；按改动补能验证数据映射、权限、保存回调、媒体状态和有效引用边界的测试，不仅测试组件能渲染。
4. 浏览器：依据 `docs/testing/README.md` 选择招聘组织、公司资料及教育选择相关既有用例。实施 Plan 固定具体文件和标题；不修改其它分支正在修的基线断言来取得通过。
5. 静态：typecheck、lint、build、差异空白检查。新增或调整测试项时按现有工具生成清单，集成时协调生成文件，不手改自动区。
6. 本轮设计不包含真实 STG 执行；本地 fixture 不能冒称真实媒体／服务端权限验收通过。出现实际合同或行为变更时重新评估验证范围。

### 6.1 关键失败反例与成功标准

| 场景 | 必须可观察的结果 |
| --- | --- |
| Mock 公司名称编辑、返回与再进入 | 沿用原保存行为；没有突然出现 Backend 三名称字段，未保存草稿不被新增共享层自动提交 |
| Backend 非管理员／无有效企业关系 | 成员只读，无保存／删图入口；无关系继续组织门，不展示 Mock 企业资料 |
| Backend 常用名冲突／保存失败 | 对应字段错误与草稿保留，不显示成功或自动返回，品牌／工商名不被串写 |
| 相册空、满 3 张、在途和删除失败 | Mock 图格布局保留；Backend 上传时按原规则显示预览与限制重复添加，失败不虚构已发布或已删除 |
| 行业子页打开、选择、取消 | 父表单不重建丢草稿；已有焦点／关闭行为保持，不重复显示两份保存栏 |
| 学校同名不同 ID、点选后继续输入 | 只按 Backend ID 确定引用；继续输入使旧引用失效，不能带旧 ID 保存新名称 |
| Mock 学校／专业输入目录外文字 | 仍按原非空规则继续，不被共享组件引入必选目录项限制 |
| 目录分页、加载失败、关键词切换 | 不改变既有查询代次／分页归属，错误诚实展示；不因合并展示重复请求或混入旧结果 |

完成必须同时满足共享代码结构、Mock 视觉基准及这些行为边界；仅截图相似或仅测试通过都不足以证明目标完成。
