# 三类列表卡片统一与缺失字段占位设计

日期：2026-09-10。

状态：用户已确认设计方向；本文落盘版本待用户批准。尚未进入 Plan 或实施。

## 1. 目标与基线

统一招聘推荐、招聘在谈、求职在谈三类列表卡片：每类的 Mock 与 Backend 使用同一展示组件和同一份卡片样式，以当前 Mock 卡片的信息位置为基准。后端尚未提供或合法为空的展示字段保留位置，显示明显的未知文本或中性图片占位，便于产品后续规划后端补数据。

代码基线为 `origin/main@b93436e956dcd133ca909c06939e3416f2f3ad24`；本工作分支已 rebase 到该基线，另有历史审计文档提交 `15db7dd1a3fcf86a2cb13a0e22946eac730224fc`。历史审计描述旧基线，不能替代当前源码。

已确认的产品方向：

- 三类卡片各自统一，不做一张覆盖所有业务的万能卡。
- 以当前 Mock 布局为基准；缺值保留信息位置，不再整行收起。
- 文本未知、图片空白占位、匹配分未知；不得以假数据补齐。
- 接口、权限、分页、轮询、真实提交逻辑继续由外层负责。

最新主线已删除筛选入口/筛选层，并调整候选详情、匿名简历与编辑岗位。本任务不得恢复已删除功能，也不覆盖这些页面的最新产品裁定。

## 2. 最小方案与非目标

采用「分别准备展示数据与操作回调 → 每类一个共享卡片」。现有页面级 Mock/Backend 分支可以保留；本任务消除卡面 JSX/CSS 的重复，不要求消灭所有模式判断。

三类卡片已有真实重复，招聘两类也重复消费候选摘要，因此小范围复用卡面、候选信息主体及分数占位有当前依据。无需新增全局状态库、请求框架、配置开关、占位 schema 引擎或服务端接口。

比较过的方案：只共用 CSS 无法消除结构漂移；把三类合成万能卡会混入不同点击模型及过多可选项。选择三类具体组件，必要的候选信息主体可局部共用。

非目标：

- 不修改后端、BFF schema、严格解码规则、现有请求 URL/query/body 或增加逐卡请求。
- 不重写 Provider、业务状态机、排序/范围规则、缓存及本地持久化。
- 不统一列表容器的分组、分页、加载/错误/空态，不改页面路由。
- 不改历史卡、已筛卡、Case 详情、匿名简历、市场卡、个人资料、代理详情及初始化页。
- 不补真实公司资料、匹配分、扫描进度或代理接入；相关旧审计问题另行处理。
- 不恢复筛选功能，不新增卡片上的决策按钮或公司跳转。

未来只在对应后端公开合同实际提供字段且明确授权与语义后，另行接入真实值；不得通过本次占位设计推断新接口已获批准。

## 3. 展示边界

共享卡片接受仅供展示的数据、按钮状态与回调，不读取应用 Context、Mock fixture、localStorage、BFF raw DTO 或环境变量，不调用请求、路由和业务派发，不自行计算业务分数。

Mock 调用方负责原型字段组合和本地分数计算。求职在谈原 `use适配分` 保留在 Mock 卡片连接层，不在 map 内直接调用 hook，不把其模拟简历计算路径带进 Backend。

Backend 调用方只对已有合法快照进行展示投影：

- 招聘推荐继续经 `从P4招聘候选` 与 `映射招聘候选摘要` 取摘要、P4 匹配分及委托状态。
- 双端在谈继续经 `映射P5列表项`，先处理正常/契约错误联合，再调用共享卡片。
- 每张卡的真实 ID、所属范围、导航目标由调用方捕获，卡片不接一个通用 ID 后自行猜路由。
- 占位是最后一步展示规则，不落入原始快照、保存草稿、查询条件、写入参数或服务端。

允许提取三类具体卡片、招聘候选信息主体、局部分数位和在谈阶段区；不强制为每个字段创建一个组件。内部文件组织及精确 props 在 Plan 冻结。

## 4. 缺失值规则

### 4.1 什么可以显示占位

只对接口合法解码、页面范围/主体有效的卡片应用占位：合同没有提供的展示字段、合法 null、展示文本 trim 后为空、没有可显示项的标签数组。

展开列表必填的 `candidate_summary` 键缺失仍是协议错误；未知枚举、非法状态矩阵、无效必填职位数据仍走现有错误处理。请求失败、未登录、无权限、未加载不能被变成一张字段全未知的正常卡。

相同展示输入在 Mock/Backend 下应用完全相同的占位规则。

### 4.2 文本与复合字段

| 信息位置 | 缺失时可见文案 |
| --- | --- |
| 公司名称 | 公司信息未知 |
| 公司简介 | 公司简介未知 |
| 候选经验年限 | 经验未知 |
| 候选学历 | 学历未知 |
| 候选求职状态 | 求职状态未知 |
| 工作信息行 | 工作经历未知 |
| 教育信息行 | 教育经历未知 |
| 招聘亮点区 | 亮点信息未知 |
| 求职在谈标签区 | 标签信息未知 |

后端合法的经验年限 `0` 继续按现有摘要映射显示「不满 1 年」，真实匹配分 `0` 仍为 0 分；不得用真假值判断把零变成未知。Mock 有值时保留其当前格式，不在本任务统一业务文案算法。

工作/教育沿用现有复合行的真实非空部分：例如公司已知、岗位未知时显示已知公司，不凭空加职业；两部分均空时显示整行占位。本次不扩大摘要协议来追踪每个子字段的缺失原因。字段缺口表仍记录组合行各自的来源，方便后端规划。

空标签数组的占位表示「没有可展示的亮点/标签信息」，不声称真实世界中没有亮点，也不补入旧匹配理由、学历标签或其他域的数据。已有非空标签保留顺序、重复项及原来的语义。

### 4.3 图片、性别与匹配分

- 求职在谈公司字标位置维持当前 `34×34`、圆角 `10px`。Backend 当前无公司图片/字标依据时使用本地 CSS 绘制的中性空白块，带可访问名「公司图片未知」；不加载空 URL、不请求外部占位图片、不按未知名称命中静态公司标。
- Mock 已有公司字标照旧。招聘两类卡当前没有头像位，不为了占位新增人物头像。
- 性别已知继续使用现有 `性别图标`；未知时原图标位置用 `16×16` 灰色 `?` 标记，可访问名和 title 为「性别未知」，不造男女图标。
- 分数已知复用原 `适配环` 的 40px 展示；未知时原位置使用相同 `40×40` 容器，显示「—」和短文案「分数未知」，可访问名「匹配分未知」。不绘制进度弧，不传入 0/NaN，不使用表示低分或成功的颜色。
- 未知分数的说明置于该 40px 容器内部，不额外把求职在谈薪资向下推一行。实际排版需在浏览器核验可读性。

### 4.4 未披露与未知

只有当前权威数据明确说明未披露时才显示「未披露」。本次列表摘要只给可空字段而无逐字段缺失原因，不能仅凭 null 认定是隐私原因，统一使用上述未知规则，不添加新的缺失原因基础设施。

对于当前接口无法区分的情况，缺口表标记「原因不可区分」；不从其他 Case、匿名简历、旧缓存或 Mock 查出内容补回去。

## 5. 三类布局与状态

### 5.1 招聘推荐卡

视觉基准：`src/屏幕/候选推荐.tsx` 的当前 Mock `推荐卡` 及 `候选推荐.module.css`。

固定阅读顺序：性别/经验/学历/求职状态 + 右侧匹配分 → 工作图标行 → 教育图标行 → 亮点标签行 → 来源、收藏、详情和委托操作区。

两模式使用同一候选信息主体、DOM 顺序和样式。空字段保留行与对应图标。卡面仍不显示候选真名、代号或薪资关系。

底部行为：

- 卡主体和详情箭头只调用详情回调；收藏只调用收藏回调，不能触发整卡导航。
- 未委托显示去聊按钮；提交中禁用；存在委托状态时显示原权威状态文案。失败/拒绝不是成功，不以「已委托」布尔值推断成功。
- P4 六态、进度未知、拒绝原因、提交锁、本次进屏暂留和滑动淘汰继续由现有调用方负责。
- 保留滑开后的点击限制，外层白卡不可形成嵌套 button。

### 5.2 招聘在谈卡

视觉基准：`src/屏幕/企业在谈候选.tsx` 的当前 Mock `候选卡` 及其 CSS。

候选主体顺序同现有 Mock；右侧始终是匹配分位置，Backend 当前为未知分占位。阶段区位于标签下方。删除原 Backend 单独卡面及其不再使用的样式，不更改 P5 历史页仍依赖的展示。

匹配分与待办表达互不替代：原 Backend 头行待办徽标移入阶段区，阶段区规则见 §5.4。收藏、委托、淘汰按钮不新增到在谈卡，整卡点击仍去本 Case 详情。

### 5.3 求职在谈卡

视觉基准：`src/屏幕/在谈首页.tsx` 的当前 Mock `在谈卡` 及其 CSS。

固定阅读顺序：公司图位 + 公司名称/简介 + 右列匹配分/薪资 → 职位名 → 标签 → 阶段区。

Backend 继续展示 P5 冻结职位名与薪资，薪资搬入 Mock 对应的右列；P5 城市与技能组成标签区，城市在前、技能随后，保留已有真实事实，不再保留 Backend 旧的城市/薪资独立事实行。不得把技能改称岗位福利或为缺失岗位属性补事实。

当前 P5 不提供公司名、简介、图片与匹配分，它们分别显示占位。不得从当前 owner Job、推荐缓存或 Organization 额外补齐。真实接口以后补字段由后续任务处理。

### 5.4 两类在谈卡的阶段区

两种模式均使用同一在谈阶段区：阶段标签 → 可选归属徽标 → 下一步/状态文本 → 详情箭头；注意说明单独放在这一行下方。

- Mock 保留原阶段名称、阶段颜色、待办呼吸点及下一步文字；不额外新增归属徽标。
- Backend 保留既有 P5 阶段标题原文：匿名初筛、简历提交、差异协同、意向确认。按四阶段语义使用对应 Mock 色系，不根据显示文本反查或改写业务状态。
- Backend 原待办徽标完整保留：「需要你」优先，其次有注意说明时「需注意」，否则「代理处理中」；仅改变到阶段区的位置。
- Backend 的状态文本继续使用既有 P5 状态文案，而非占位「下一步未知」；它是已知状态，不能抹去。现有 attention 安全说明原样保留，不造重试/决策动作。
- 用显式展示参数表达标题、阶段色系、待办、徽标文案、状态文本和注意说明。卡片内不写 mock/backend 判断；不同业务状态允许产生可选节点。

## 6. 布局稳定与共享组件影响

完整 Mock 数据保持原信息位置、字号、卡片 padding、边距及按钮位置；新增占位只影响原来缺信息的情形。两类在谈的正常卡分别以自己的 Mock CSS 为基准，不统一成新的第三种风格。

占位字体使用现有次要文字色，不用错误红色。工作/教育图标行与标签区域始终存在；未知不会导致后续行上移。已知长文本沿用省略规则，完整字段值保留可访问内容。

候选头行在正常内容下保留原单行；占位串过长时允许头行文字在左列最多两行，右侧 40px 分数位不能被挤出或遮住。两种模式执行相同换行规则。无需把所有卡固定成同一总高度；标签数量、必要注意说明和长文本可以改变高度。

已有 `src/组件/候选头行.tsx` 服务详情和匿名简历，当前默认隐藏空项。本任务可通过调用方预格式化文本复用它，或增加默认行为不变的可选展示参数；不得修改默认行为导致非目标页面长出占位。不能复制第三份同语义头行而不给复用理由。

`适配环` 原有消费者行为不变。优先由三类卡片共用的局部分数位处理 number/null，避免把未知展示扩散到所有详情页。

## 8. 行为保护与验收

必须保持：

- Mock 零新增后端请求；Backend 零 Mock fixture 兜底、零本地模拟成功。
- 原有 recommendation/job/case ID 导航语义、切岗位/切意向/换账号范围隔离、迟到响应丢弃。
- 收藏失败不假成功，委托 accepted/evaluating 不显示已开案，失败/拒绝不变成功。
- P5 契约错误行、未加载/失败/空态、分页、轮询、注意状态继续由现有列表处理。
- 新主线无筛选入口的事实不变；历史、详情、已筛及市场卡不因共享组件默认改变而改版。

验收层次：

1. 展示/映射测试：三类 Mock/Backend 相同展示输入使用同一组件结构；完整、全空、部分空、真实零值、长文本、重复亮点及刷新从有值变空均覆盖。占位不得残留旧事实，不出 NaN、undefined、破图或假 0 分。
2. 既有页面集成测试：招聘推荐、企业在谈候选、在谈首页、P5 MatchCase列表，核验点击/滑动、状态、范围、错误及新占位。调整旧「空摘要收行」断言为本 Spec，不删除真实请求与协议隔离断言。
3. 浏览器布局：在现有移动视口及窄屏（至少 390px、320px 宽）查看三类卡的完整/缺失/长文状态；两栈用等价展示内容检查卡内各区位置，容许亚像素差异 ≤1px，无横向溢出、遮挡或按钮不可点。不同内容不强求全页像素相等。
4. 现有 Mock 视觉回归继续保护基准；增加针对三类 Backend 卡面的 Playwright 覆盖或等价现有工具验证，不搭建新全站视觉平台。HTTP fixture 只能证明前端展示和请求边界，不能冒充本地后端验收。
5. backend+local 实际验收参照 `docs/dogfood/真实后端行为验收.md`，选择涉及推荐/委托/在谈的必要流程，记录真实 URL、前后端 revision、接口响应的字段存在性和截图；不为纯展示任务无条件运行所有业务组合。已有真实数据不足时用合规合成数据补足或标记未完成，不能借 Mock 截图宣布通过。

实施前安装锁定依赖，按 repository 当前入口执行适用的 typecheck/lint、定向测试和视觉验证。规划阶段不为估时运行重测试。当前工作区此前缺 vitest，本 Spec 不宣称测试或视觉验收通过。

## 9. 完成标准与交付边界

- 三类卡片分别只有一套被 Mock/Backend 实际调用的展示 JSX/CSS；保留的连接层不得重新实现一份卡面。
- 后端缺展示数据时位置保留、占位明确；接口错误与未知字段的边界不变。
- 上述字段缺口表随实施核实，可记录事实纠正，但不得自行新增后端读取或产品功能。
- 现有状态、操作、权限及最新主线裁定不回归；适用自动化与浏览器验证有明确结果及限制。
- 本 workflow 后续交付单份 Plan、异构文档 review 及双宿主执行 prompt。实现由新实施 session 执行，本规划 session 不写业务代码。
