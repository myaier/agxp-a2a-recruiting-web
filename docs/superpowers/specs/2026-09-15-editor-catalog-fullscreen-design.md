本次统一五个入口的容器与进入/退出方式，另修复用户追加的两项问题：现有 onboarding 学校/专业选择闪烁及再次点选候选消失；热门城市静态名称与目录名称不一致。成功标准是五个字段均能在完整应用内容区域选择，关闭后回到原编辑上下文，已有合法值与提交边界不受损；既有学校/专业全屏页可稳定重复选择，热门与目录同一城市名称一致。

## 2. 方案与最小化取舍

比较三个方案：

1. 只把现有抽屉高度拉满：无法覆盖学校/专业的内嵌输入，也没有统一返回栏与父表单隔离，不满足全部范围。
2. **采用：共用轻量全屏外壳，嵌入各字段已有目录正文及查询适配。** 学校/专业改为独立选择子视图；职业和行业沿用已有可用目录逻辑。追加缺陷只修复对应状态流与城市静态名称，不扩展为全站重写。
3. 全站统一查询、目录树、单多选事务与全部选择器：会扩大到已经全屏的城市、期望职位、onboarding 学校/专业等，当前不需要。

允许新增的共享能力只有一份轻量全屏选择外壳，服务本次五个真实消费者：标题、返回、可滚动内容、必要的焦点边界。业务目录、选择值、API、路由和持久化不进入外壳。精确文件名及接口在获批后的 Plan 冻结。

继续复用 `教育目录候选列表` / `目录候选列表`、`岗位职业分类正文` 的分类正文、`行业分类列表` 及现有行业查询钩子。不以“统一”为由强迫公司行业迁移到另一套目录深度、模拟选项或查询协议。公司行业的既有内容可适配为该入口两模式共用的展示正文；不要求与简历行业共享所有内部实现。

## 4. 全屏布局与生命周期

### 4.1 进入与视觉

- 五个入口都是字段点击行，显示当前值或明确占位，右侧进入箭头。
- 打开后占满应用内容区域；桌面若有设备外框，以设备内容区域为边界，不覆盖整个桌面窗口。
- 顶部返回按钮与字段标题固定可达。标题分别为“职位类别”“选择学校”“选择专业”“所属行业”“选择行业”。
- 无半屏抓手，不露出下方可操作的原表单；长候选在选择正文内滚动。
- 分类两栏各自滚动可保留；普通候选列表采用单一列表滚动区，避免整页和列表同时滚动。
- 学校/专业保留搜索输入；公司行业保留搜索能力；不顺带为岗位职位类别或简历行业新增搜索功能。
- 短屏、横屏及键盘弹起后，返回与当前结果均可达。打开时先聚焦返回或标题，不自动强制弹出键盘；用户点搜索框后正常输入。

### 4.2 同页子视图

采用当前编辑页面中的本地全屏子视图，不新增路由、隐藏 history 条目、全局草稿存储或 URL 参数。参考岗位城市现有同页子视图方式。

父编辑实例及其草稿保持挂载。选择期间父表单隐藏且不可交互，不进入键盘 Tab 顺序或读屏可访问区域。不能靠纯视觉覆盖冒充隔离。

返回按钮与 Escape 关闭本次选择界面，恢复原字段焦点和父表单滚动位置。浏览器后退沿当前页面已有路由行为离开；不承诺把系统后退改造成子视图关闭。刷新沿已有页面恢复能力，不新增保存保证。

打开、搜索、展开、翻页及关闭不得触发业务保存。关闭后请求响应不能修改已关闭的选择或另一个条目的草稿；重新打开以当前父草稿初始化。

### 4.3 选定与退出

本次五个入口均为单选，采用**点中合法候选即回填父草稿并关闭**。不新增“确定”步骤；这是本次最小方案对先前讨论中“全屏点选后再确定”备选建议的明确取舍。

未点候选时返回，保留父草稿原值。选定仅回填字段，不提交岗位、简历或企业档案；整个表单仍通过原“完成/保存/发布”流程提交。

学校/专业的搜索词改为本次选择局部状态：输入不会先清除父草稿的已有名称或目录引用。当前旧文本可用作搜索初词，但不能按名称自动生成 ID 或自动选择第一条结果。

Backend 的选定原子回填显示名与真实目录引用；同名不同 ID 按 ID 区分。Mock 仍使用本地模拟数据与既有文本/模拟键语义，不产生真实写入。

## 5. 各入口具体边界

### 5.1 岗位职位类别

修改 `src/组件/岗位职业分类正文.tsx` 的承载外壳及 `src/屏幕/发布岗位.tsx` 的接线。保留左右两栏、父节点导航、可选候选点选、目录分页与版本/迟到响应守卫。

保留当前选择语义：左栏负责导航；右栏可选项点选，不可选但有子项时继续展开。不借此改成求职侧的多选网格或重写分类树。

### 5.2 简历学校与专业

继续使用 `教育目录候选列表`，学校保留地理副信息，专业保留名称列表。沿用当前搜索防抖、分页、真实目录引用及保存校验；查询只随正在打开的对应字段搜索，不让学校搜索词驱动专业查询。

Mock 新选择也必须点候选；原有 Mock 演示值及历史已填文本保持，不因改成选择行清空。Backend 历史无引用文本继续提示用户选择目录，不自动修补引用。

学位、起止年月、另一字段与教育条目身份始终保留；关闭不退出教育编辑，切换学校不会清掉已选专业，反之亦然。学校或专业成功选定后，仍由教育表单“完成”及上层既有保存路径处理。

onboarding 独立的 `毕业院校.tsx`、`选专业.tsx` 本来已全屏，布局和下一步流程保持；本轮按 §5.5 修复候选状态，不额外统一整个 onboarding 选择器或改变其 Mock 自填规则。

### 5.3 简历所属行业

将 `src/组件/简历行业选择正文.tsx` 改为全屏承载，保留 `行业分类列表` 和 `use行业目录`。

保持单选、可选/可展开分离、多根展开/收起、缓存、分页、重试、目录换版和现有深度边界。开关选择界面不丢失公司、职位、年月、工作内容、项目、实习标记及隐私开关。

### 5.4 公司档案行业

修改 `src/屏幕/公司档案分区编辑.tsx` 基本信息分区，把行业改成进入选择的字段行。Backend 与 Mock 均进入同一全屏外壳和该入口共用的展示正文。

Backend 保留真实 industry 查询、搜索和按节点属性导航；Mock 保留现有 `行业池` 可选值，将其适配为可选节点。允许目录内容和层级由数据决定，不能保留两种不同的容器交互，也不能为了凑层级伪造新行业 ID。

进入、搜索、选定、取消规则相同；不添加 Mock 独占自由输入。已有值照实回显，不能仅因不在当前查询页而清空。搜索中、空结果、错误及加载更多通过共用展示状态表达；失败不能显示成成功空列表。

Backend 只读/无编辑权限时不能打开可编辑选择器。选中只修改公司档案本地草稿；权限、保存校验、revision 与企业媒体处理沿原逻辑。公司名、品牌、LOGO、规模、融资阶段、地址和其余分区保持原有行为。

### 5.5 现有学校/专业全屏页的闪烁与候选消失

用户复现路径：搜索 → 点候选 → 屏幕闪一下；候选再次出现后，再点同一候选 → 内容消失。

定位证据：`毕业院校.tsx` 与 `选专业.tsx` 的 Backend `选候选` 同时回填完整名称并执行 `设候选项([])`；搜索 effect 又依赖该名称。第一次从搜索短词变为完整名称时，候选先清空，再进入 250ms 防抖与重新查询，产生列表消失/重现。第二次点击同项时名称相同，不再触发 effect，但候选仍被清空，搜索状态还保持 success，页面错误地显示“没有匹配结果”。

定向诊断在真实 React 页面组件上注入目录 fixture，分别验证学校和专业：首选后列表为空并进入 loading，第二次查询后结果恢复；再次点同一项后列表为空、出现错误的无结果提示，等待超过防抖时间也没有第三次请求。两项诊断通过，证明当前错误状态流；不是修复通过，也不是浏览器视觉验收。临时诊断文件运行后删除。首次学校诊断 fixture 缺 location 的错误已修正后重跑，不计为产品缺陷。

Mock 专业还存在独立收起分支：`已点选` 将候选隐藏，且过滤掉与完整输入相同的名称，需一并消除“已选项无法在候选中重选”的差异。学校选中标记当前按名称判断，同名不同 ID 必须改为真实引用 ID 判断。

修复合同：

- 搜索查询词与选定答案分别管理；点候选可继续把输入展示为完整名称，但不得把程序回填当成用户重新搜索。
- 点选保留当前成功结果列表及其查询词/分页上下文，显示正确已选状态；重复点同一项保持稳定，不清空、不重查、不误显示无结果，也不丢滚动位置。
- 用户真实修改输入时，才切换搜索词并作废旧引用、游标与在飞请求；下一步继续依赖真实引用有效性。清空、搜索失败、无结果仍各自如实表达。
- 加载更多必须使用该列表对应的原搜索词，不能使用已回填的完整名称混合旧游标。新输入后旧页不可追加；点选不会触发整页重挂载。
- 学校和专业两页均覆盖 Mock/Backend；Mock 保留现有自由文本可继续规则与预填，但不因点选主动隐藏所有候选。
- 保留建档草稿写入、预填 eligibility、保存成功后确认分区及下一步跳转顺序；不把 onboarding 改为点选后直接离页。
- 新增简历学校/专业子视图仍按 §4.3 点选关闭，重新打开必须能看到已选项并再次搜索/重选，不复制上述清空与查询耦合。

### 5.6 热门城市名称与权威目录对齐

根因：`src/数据/城市精选.ts` 固化 `北京`、`上海` 等展示别名；四个入口直接使用它，分省/搜索目录则使用接口的 `display_name`。同 ID 会显示两套名字，已选标签还可能随选择来源变化。

- 集中核对并更新 12 个国内与 10 个海外精选项的显示名。按已有 canonical ID 对照真实目录，不按字符串普遍追加“市”，不修改 ID、国家码、精选数量、顺序或港澳台排除范围。
- 用户指出的北京、上海应显示为“北京市”“上海市”；其他项以同 ID 的目录 `display_name` 为准。海外也按权威名称核对，不根据中文别名猜译名。Plan 阶段需完成名称表核对并记录数据版本/来源；无法核对的项目明确列出缺口，不声称已对齐。
- 当前源码注释引用的 `dogfood-output/2026-09-14-city-ids/` 证据目录在此工作区不存在，因此既有 ID 测试不作为本次名称已核验的证据；使用可用的后端目录快照或只读真实目录响应确认名称。
- 一份配置覆盖 `选工作城市.tsx`（onboarding / 意向）、`选择城市.tsx`（备选城市）、`引导问答.tsx`（城市补问题）、`发布岗位.tsx`（岗位城市）；不逐页维护别名副本，不改全屏结构和选择上限。
- Backend 继续按 ID 关联热门、分组、搜索、已选；同城市不能重复计数。已有引用的旧显示名在选择界面回显时可由对应静态 ID 规范名称，不主动持久化或批量重写历史意向/岗位。
- Mock 当前以城市名为选择键，必须同步适配这 22 个已知精选项在默认列表、搜索、当前/历史、已选及已有草稿中的名称/键，保留演示预填并使简称与正式名称对应同一个选项。采用本次有限映射，不做全站任意地名归一化，也不遍历重写历史存储。
- 不在产品首载时新增 22 次目录请求，不新增后端精选 API、名称同步服务或运行时全目录下载。权威核对只发生于开发/验收。

## 6. 数据与非目标

不新增或修改后端接口、schema、目录 ID、权限、保存时机和草稿持久化。Mock 默认演示数据保留；Backend 失败不回退 Mock。

本次明确不改：公司选择、城市选择的容器/目录请求机制、求职期望职位、期望行业多选、向导题序、学历按钮、薪资/日期/数值滚轮、招聘类型、公司规模/融资选项、职业分类搜索、全站按钮或目录查询架构。
