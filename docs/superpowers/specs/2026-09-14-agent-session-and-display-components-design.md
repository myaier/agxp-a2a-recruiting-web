# 双端固定 AI 代理入口与展示组件整理 Spec

状态：待用户审阅批准。用户已确认产品方向与页签规则；本文件的最终版本尚未批准。批准后才编写实施 Plan、进行异构文档 review 并生成新实施 Session 的执行提示词。

## 1. 目标与边界

本任务覆盖求职端与招聘端的两项工作：

1. 为 Backend 消息列表补回固定的 AI 代理入口，并完成可见但暂不可发送的聊天页面外壳。
2. 将现有 Mock“问 AI 代理”的重复展示整理成由数据与回调驱动的组件，为未来后端提供解释文本和结构化业务结果留出展示边界。

本轮所称“固定 Session”指用户可反复进入的同一个代理页面入口，不表示已在服务端创建了助手会话。用户无需先产生真人会话才能看到它；不提供删除、新建或清空 Session 功能。不增加会话存储、会话 ID 或历史读取。

成功标准是：Backend 的 AI 入口不再随真人收件箱为空而缺席；列表分类遵循现有 Mock；聊天外壳清楚表达未开放能力；Mock 外观和交互保持；提取的组件可通过更新 props 改变内容，且不会读取 Mock 数据、操作全局业务状态或自行产生业务成功结果。

## 3. 方案选择与最小性

比较过三个范围：

- 只加入口并继续使用原导航页：成本最低，但不满足用户确认的聊天外壳与可见禁用输入栏。
- **固定入口 + 禁用聊天外壳 + 现有展示组件分离：采用。** 不需要助手 API，即可补全用户可见结构，同时让已有展示摆脱模拟数据与业务操作。
- 预建完整助手 Session / 消息框架 / 结果注册平台：依赖未冻结的契约，超出本轮需要，不采用。

保留两个页面的 Backend / Mock 容器。消息列表继续使用已有展示组件；新提取只针对已存在的气泡、快捷操作、简报与建议，不增加助手服务层、通用 Mock 适配器、配置平台或全局聊天状态。

## 4. 固定 AI 代理列表入口

### 4.1 分类、顺序与搜索

两端、两种数据源模式遵循同一产品规则：

| 页签 | AI 代理行 | 其他行 |
| --- | --- | --- |
| 全部 | 搜索命中时固定为第一条会话行 | 现有真人 / 直聊行按当前来源顺序展示 |
| 通知 | 搜索命中时显示 AI 代理行 | 本轮不增加其他通知来源 |
| 仅会话 | 不显示 | 保持现有真人 / 直聊集合与门控 |

“置顶”指列表顺序，不是滚动时吸顶；不新增置顶按钮或排序状态。筛选仍先按页签、再按 trim 后关键词对标题 / 副标题 / 摘要做现有包含匹配。不做跨来源内容补齐、远程搜索或模糊搜索。搜索不匹配时 AI 行可以隐藏；清空搜索后恢复。

Backend 真人行保持服务端顺序、分页与权威已读语义；固定入口不加入 P7 快照，不占分页条数、不改变游标、不参加真人未读统计。Mock 现有未读与“点击后派发读消息”行为保持。

### 4.2 外观、展示数据与导航

复用已有 `会话行` 和代理头像，保持 Mock 列表形式；用户所称“问 AI 代理”入口沿用列表现有名称：

| 字段 | Backend 求职端 | Backend 招聘端 |
| --- | --- | --- |
| 标题 | AI代理动态 | AI代理动态 |
| 副标题 | 你的求职AI代理 | 你的招聘AI代理 |
| 摘要 | 聊天暂未开放，可查看代理功能 | 聊天暂未开放，可查看代理功能 |
| 时间 | 空，不伪造最近活动 | 空，不伪造最近活动 |
| 未读 | 无数字、无红点 | 无数字、无红点 |
| 点击 | `路径.问AI代理`（`/agent`） | `路径.企业问AI代理`（`/hr/agent`） |

Mock 标题、副标题、时间、摘要、未读数和点击已读剧情保持原样，不换成 Backend 文案。Backend 的固定行由连接层直接构造展示数据，不使用 `从Mock消息行`、X-01 / H-01 或模拟未读。可以有仅用于 React 列表的稳定键，与真人行键区分；它不是会话坐标，不进请求、路由参数或持久化。

两种模式都不提供删除、清空、新建 Session 操作；本轮不新增对应菜单或禁用菜单项。无需为不存在的删除 API 建立防删除机制。

### 4.3 加载、失败、空态与生命周期

- 固定行在消息页获准挂载后即可展示，不等待真人会话首读；P7 空页、失败、重试、缓存替换和加载更多不得移除它或重复追加它。
- 现有应用登录 / 角色 / 初始化门不绕过；“固定”不意味着未登录也展示受保护页面。
- 全部 / 仅会话继续展示真实收件箱加载、错误、重试和分页信息，错误与已有行可共存。固定行为第一条会话行；现有前置状态提示仍可位于会话行之前。
- 无搜索且 P7 成功空页时保留“还没有真人会话”。全部页可同时有 AI 行与该提示，文字明确仅描述真人集合；仅会话仍为空态。
- 通知页签展示固定行，不再无条件显示“还没有通知”；P7 的加载、错误和加载更多不在通知页签显示。原有收件箱可见范围登记 / 注销与首读机制不变，不因固定入口新增请求。
- 有搜索词且当前可搜索集合没有可见行时，使用现有“没有匹配的会话。换个关键词，或者切到「全部」看看。”提示；有 AI 命中时不能同时宣称无匹配。通知集合是本地完整集合，可立即判断；真人集合仍在首读且没有缓存时不把“未读入”判为搜索无结果。失败提示不能被空态替换。
- 重入、刷新、切换角色后，依据当前页面角色展示其对应入口。Backend 点击不调用真人已读、Mock 读消息或 Session 创建操作。

## 5. Backend“问 AI 代理”聊天外壳

保持现有白底次级页、标题、代理身份、更多入口和单一消息展示滚动区；补上可见禁用输入栏。结构顺序为：返回栏 → 代理能力说明区域 → 真实导航操作行 → 禁用输入栏。

- 标题继续是“我的求职AI代理” / “我的招聘AI代理”。`⋯` 仍进入对应代理详情，不变成会话管理菜单。
- 能力说明由页面提供并沿用当前真实口径：求职端指向市场 / 在谈 / 规则库，招聘端指向推荐 / 在谈 / AI 代理设置；明确“当前 Backend 模式暂不提供自由对话、日报和漏斗”。这是页面说明，不存入消息数组，不附加消息 ID、时间或模拟历史。
- 真实导航按钮保持：求职端“去市场 / 看在谈 / 规则库”；招聘端“看推荐 / 看在谈 / AI代理设置”。原 Tab / 子视图派发、替换跳转和 canonical 路径不变。
- 输入栏复用 `真输入条`，值为空，提示“AI代理聊天暂未开放”；textarea 与发送按钮都使用真实 `disabled`。不能输入、粘贴成草稿、按 Enter 或点发送生成消息；Backend 不持有可发送草稿，不绑定 Mock 发送函数。
- 不展示今日简报、漏斗、快捷问句、Mock 会话历史或正在思考动画；真实导航不是快捷问句，不触发模拟回复。
- 现有其他页面 Backend 代理横幅仍使用“查看代理功能 ›”，不扩大修改其文案。

本节是用户明确批准的范围调整：替代旧真实性约束中的“Backend 完全不渲染输入控件”，改为“展示禁用输入，但没有发送能力”。不据此放松零 Mock 会话 / 回复 / mutation 约束。

## 6. 展示组件与数据 / 状态 / 操作分离

### 6.1 提取与复用粒度

展示实现放在 `src/组件/问AI代理/`；具体文件拆分与签名在获批后的 Plan 明确，不要求把每个小块拆成独立文件。

| 展示单元 | 调用方提供 | 用户操作边界 |
| --- | --- | --- |
| 代理气泡 | 文本、现有两端外观差异；复用 `代理标` | 无业务操作 |
| 我方气泡 | 文本、头像 URL 或首字 | 不从 Context 读姓名或头像 |
| 快捷操作行 | 文案及回调 | 只调用回调；Mock 是发送，Backend 是导航 |
| 简报展示 | 标题、更新时间文字、统计名称 / 数值 / 强调、正文分段、脚注、建议展示、可选漏斗 | 不读取 fixture，不生成日报或更新时间 |
| 建议展示 | 标题、现有正文与两处强调数值、按钮文案、处理文案 | 维持 / 放宽回调；不自设操作成功 |
| 漏斗展示 | 名称、人数、宽度百分比、可选动作和读屏说明 | 只有调用方提供动作的档可点；不按名称找路由或算转化 |
| 输入栏、页面基础控件 | 使用已有 `真输入条`、返回栏、次级页外壳 | 继续用现有受控输入与 disabled 能力，不新建输入系统 |

简报统计、漏斗行等可以作为文件内小组件；共享重复结构即可，不建立动态消息渲染器。两端必要的外观选择只选择 CSS，不决定数据源、权限或业务动作。

### 6.2 受控更新语义

组件输入是前端内部展示模型，不是未来后端 DTO；不扩展 `代理对话条` 为新协议，不冻结助手事件类型或动作状态机。

必要接口示意仅表达已有建议的控制边界：

```ts
type 规则建议属性 = {
  标题: string;
  正文前: string;
  数值1: string;
  正文中: string;
  数值2: string;
  正文后: string;
  维持文案: string;
  放宽文案: string;
  处理文案: string | null;
  维持: () => void;
  放宽: () => void;
};
```

处理文案为空时显示两枚按钮，非空时显示传入文案。点击只调用对应回调；父组件没有改变 props，展示组件就不能自行变为“已处理”。规则原文、来源及 mutation 载荷留在容器闭包，不透传给建议卡。

同一组件实例收到新文本、统计、建议、漏斗值或处理文案后，直接展示新 props；不能只在初始挂载时复制到内部 state 后不再更新，也不要求调用方换 key 强制重挂。“数据更新 / 刷新 UI”指这一受控更新，不是引入刷新 API、轮询或刷新按钮。

现有文本按 React 文本渲染，强调样式保持既有分段；本轮不引入 HTML / Markdown 消息解释器。头像失败、输入高度等纯 UI 状态可由已有基础组件处理，业务处理状态归容器。

### 6.3 容器保留的 Mock 行为

- 两份既有模拟数据文件保留。页面显式选择展示字段，不把包含操作载荷的整份 fixture 交给组件，不为一次字段选择新增适配层。
- 会话初始值、草稿、关键词优先级与回复文案、550ms 回复定时器集合、消息编号、滚动 effect 都留在对应 Mock 容器。不抽通用 `useChat` 或模拟会话服务。
- 求职端姓名 / 薪资读取与现有 52K 兜底、招聘端头像 / 姓名读取仍在页面，气泡只接收结果。
- “维持红线”处理状态从简报组件提升到对应 Mock 容器；仍只在本次页面实例内有效，不改任何规则。
- 求职端“改成可谈”继续派发 `新增规则`、留在本页、提示“已记成规则”。招聘端“放宽薪资带”继续派发 `企业新增规则` 并跳企业代理设置。不把放宽动作改为统一确认流程，也不自动进入“已维持”状态。
- 企业漏斗只有“硬性匹配”可点，打开初筛记录，其余四档仍不可点。保持 button 内 span 与现有可访问名称。
- 快捷句直接发送；普通发送 trim、忽略空白、立即追加用户文本、清空草稿、延迟回复。卸载 / 切 Backend 取消全部排队定时器，重新挂载恢复初始演示。
- 模拟成功文案继续只由 Mock 容器提供。相关注释不能暗示这些动作已由后端确认，文案不作为未来真实业务结果约定。

### 6.4 强制隔离边界

两页默认导出继续按 `数据源模式` 在任何 Mock state/effect 挂载前分流。禁止先运行 Mock hook 再隐藏 UI；禁止因空数据、请求失败、登出或水合失败回退 Mock。

展示目录不直接读取模拟数据、API、全局业务 Context、路由、存储或规则操作层；不自行派发、持久化、生成模拟回复、计算业务权限或宣布操作成功。列表固定行也只能是本地展示入口，不注入真实会话域。

Backend 可复用气泡、快捷操作行与禁用输入栏，不能因此挂载 Mock 容器或持有模拟规则动作。允许现有真实导航所需的 Tab / 子视图派发，不把“无 Mock mutation”误写成“无任何派发”。

## 7. 视觉保护与已有业务组件

保持当前各端外观，不重新设计、不强行把两端 CSS 合为相同数值。代码中的真实差异包括：求职气泡按内容收缩、招聘气泡伸展；正文分别为 13.5px / 1.45 与 14px / 1.7；简报宽度、标题头、时间标、统计字号不同；求职快捷行单行横滑，招聘快捷行换行。旧“同构、像素一致”注释不能覆盖实际基线。

Mock 的建议仍在简报正文后、脚注前；共享提取不把它变成独立消息。Backend 新增禁用输入栏带来的空间占用是预期变化，其余布局沿用本端现有样式，保留单一消息区滚动及底部控件可见。

现有业务结果组件已核对，暂不接入助手消息：

| 现有能力 | 后续复用原则 |
| --- | --- |
| `组件/列表卡片/求职在谈卡`、`招聘在谈卡`、`招聘推荐卡` | 已按展示数据和回调分离；结果语义匹配时复用。不为普通岗位结果伪造在谈阶段；推荐卡固定来源 / 委托语义不能套到任意结果 |

| `看市场.tsx` 内 `市场卡` | 仍调用 `use适配分`，不是可直接搬入助手的纯展示卡；无当前调用需求，本轮不动 |

## 8. 修改范围与非目标

实施范围：两端消息连接页面、`P7/Backend会话列表.tsx`、必要的已有消息展示 / 映射边界、两端问 AI 页面及对应 CSS、新提取的问 AI 展示组件，以及直接相关测试。消息列表已有共享 JSX/CSS优先原样消费，不另建同类列表或全局通知层。

不修改 P7 DTO / decoder、会话 API、Provider、全局状态或持久化规则；不重构真人聊天详情、市场、候选、Case 或规则管理页面。代理详情仅保留现有导航关系，不顺便整改该页其他历史问题。

不实现：真实助手聊天、流式输出、Session 创建 / 删除 / 清空 / 持久化、Agent 记忆、工具调用、后端接线、自动刷新、通用卡片引擎、动态注册、复杂 Schema、批量预建结果卡或助手操作状态机。

## 9. 验证与验收标准

测试针对用户可见边界，不为样式搬移建立大量类名 / DOM 结构快照。

1. **列表规则：** 两端 Backend 在 P7 未开始 / 加载 / 成功空页 / 失败 / 有数据时都可看到且仅有一条固定 AI 行（页签与搜索允许时）；全部第一行、通知有、仅会话无；搜索命中 / 不命中 / 清空正确；真人顺序、分页与重试仍成立。固定行无假时间 / 未读，点击去正确代理页面，零 P7 已读或 Mock mutation。
2. **禁用聊天：** 两端 Backend 输入与发送按钮可见且 disabled，说明和真实导航存在；键盘与点击不生成消息或模拟业务修改。排队 Mock 回复在切 Backend 和卸载时确实取消，不能只以卸载后 DOM 不可见证明清理。
3. **受控展示：** 使用自造 props，不挂应用 Provider；更新文字、统计、漏斗与处理文案能就地更新同一实例；按钮只调用对应回调，父级不更新时不自行显示成功；可点 / 不可点漏斗语义正确。
4. **Mock 保持：** 两端简报、头像、输入与快捷句、550ms 回复、薪资口径、维持 / 放宽差异、退出重进恢复 fixture 保持；消息分类与原未读剧情保持。
5. **视觉与整页：** 浏览器在 320px / 390px 检查两端列表和问 AI 页的 Mock / Backend；比较相同输入数据的重构前后展示，检查长文本、滚动、快捷行、简报顺序、底部输入及禁用可访问语义。列表复用一份样式，不要求不同内容等高。

最小开发验证使用现有两端消息列表、Backend 列表、两端问 AI 测试，加提取组件的少量行为测试。保留 `看市场.test.tsx` 中求职改成可谈的跨页断言；如改消息映射或共享展示，则运行对应现有测试。最终运行适用类型检查、lint、构建及聚焦浏览器验收，具体命令与责任在 Plan 明确。

旧两页测试的“Backend textbox / 发送按钮不存在”应替换为“存在但禁用且无发送副作用”；旧 Backend 通知空态应替换为本 Spec 的固定行与搜索规则。不能为了通过新测试删除 Mock 隔离、真实导航、P7 已读与门控断言。

本轮没有新的服务端能力，真实后端发布 / 全量 dogfood 不是证明组件重构或本地固定入口的必要条件；HTTP fixture 验证须明确标注边界，不宣称完成真实助手接线。

## 10. 等待后端决定的接线事项

以下不阻塞本轮前端整理，也不由前端自行猜测：

- 助手 Session 的身份、归属、历史、消息顺序与生命周期，以及是否永久保留的服务端规则。
- 解释文本格式、与结构化结果的关联、数据缺失 / 失败的展示含义。
- 岗位、候选人和 Case 结果的权威字段、资源坐标、匿名边界及可执行 / 可导航能力。
- 动作权限、是否二次确认、处理中 / 失败 / 成功的权威依据、未知结果的处理。
- 助手规则建议与现有 Agent 规则提案的关系、如何取得提案及确认结果。
- 真实简报 / 漏斗统计口径、更新时间、助手最近消息和未读来源。

契约明确且出现真实调用需求后，再在容器中把后端结果映射到现有展示组件；数据缺失时保持未开放外壳，不用 Mock 补齐。只有多个实际接线场景反复出现普通组件组合无法合理解决的重复，才重新评估通用机制。
