## 2. 最小方案与取舍

选择“保留连接层 + 两个具体页面展示层”：独立职位详情共用页面外壳、正文、底部操作及更多菜单；双端消息共用列表外壳、搜索/页签和会话行。加载/错误状态及操作能力通过显式参数表达，业务动作由外层提供回调。纯 UI 状态可留在展示层，但不改变当前搜索/页签生命周期。

只共用 CSS 不能消除当前重复 DOM；跨所有详情和聊天建立通用页面框架会扩大依赖并与未合并分支冲突。两个具体展示层覆盖已有重复，是满足本次需求的最小方案。具体文件和 props 签名由批准后的 Plan 冻结。

新增展示层不读取 Context、运行模式、Mock fixture、localStorage 或 raw BFF DTO，不调用请求、路由、业务派发或计算匹配分。两种来源先分别准备展示数据，再调用共享组件。相同展示数据、状态、能力使用相同结构，不要求不同权限或不同数据量的整页像素相同。

不新增全局 ViewModel 框架、占位 schema 引擎、状态库、配置开关或请求基础设施。删除迁移后的重复 JSX 和确认无消费者的 CSS，不保留无人使用的旧实现。

### 2.1 Mockup 视觉基准与 CSS 约束

用户补充要求：最终视觉效果与当前 Mockup 一致，谨慎修改 CSS。以规划基线三页实际 Mock 渲染及其已有视觉基线为准，不以旧 Backend 页面或重构后的新截图替代基准。相同既有 Mock 场景下，信息顺序、字号/字重、颜色、行高、换行/截断、卡片尺寸、padding/margin、圆角、头像/分数位、按钮位置、滚动留白和弹层布局均须保持。

- 优先迁移或复用原 Mock CSS 声明，不顺便调值、统一设计令牌、替换布局方式或调整 DOM 标签的默认样式。移动文件后也须检查选择器作用范围、继承及级联，文本相同不等于视觉相同。
- 共用 JSX 应适配 Mock 结构；不能为容纳 Backend 内容反向改变 Mock 的正常排版。新增缺失状态样式限制于对应占位节点，长文处理沿用既有规则，不向完整 Mock 场景传播。
- Backend 专用旧卡面样式可随对应重复结构删除或调整；先按选择器及实际消费者核实，不能仅凭文件名含 Backend 或样式曾用于 Backend 就删。加载、错误、重试等仍有用途的样式保留或等价迁移，不以删除行数作为目标。
- 求职/招聘消息 CSS 当前有效声明一致，差异仅为注释；合并时保留声明值即可，无需重新设计。职位详情的共享 CSS 还服务兼容正文入口，纳入视觉保护范围。
- §3.2 的缺失规则不授权给既有 Mock 场景增添行或改变其截图。实施前须对照实际 fixture 检查缺失槽；若规则应用会改变已有 Mockup，先提出具体差异修订设计，不静默更新基线。不得通过新增按数据源选择的两份 CSS/JSX 掩盖冲突。

## 3. 独立职位详情

### 3.1 固定结构与展示归属

范围是 `src/屏幕/职位详情.tsx`、其 CSS、测试及本页专用展示/映射文件。正常页面保留：返回/更多栏 → 职位名与薪资 → 匹配度分析 → 职位详情与职位要求 → 公司 → 发布人 → 浮动操作条。不得恢复已删除的职位标题下标签。

保留当前 Backend 对岗位事实和补充说明的准确标题、事实行及顺序，不把结构化设置变成已确认匹配证据。Mock 原有完整内容、字号、间距和操作位置保持；缺失信息只改变原缺失状态。

将当前 `职位正文` 中的数据准备、Mock 详情/公司档读取、真实简历核对及导航准备移到连接侧。匹配算法不修改；展示仅消费算好的分数、核对行、分析和状态文案。Backend 使用已有 P4 投影，不新增 Company/Job/Resume 查询来补数据。

保留 `职位正文` 导出的兼容入口与当前调用方式，保护 `src/屏幕/直聊会话.tsx` 的嵌入消费者；无需修改该消费者。通用 `公司区块`、`匹配分析块` 等组件不改变默认行为或公共接口，本页使用其现有显式数据接口。Mock 公司资料在连接侧准备，Backend 不触发静态档读取。

### 3.2 缺失规则

只有成功取得合法职位数据后才能显示字段占位。未加载、404、无权限、契约错误和普通读取失败沿用当前独立状态，不能变成全占位的正常详情。

| 位置 | 本次规则 |
| --- | --- |
| 匹配分 | 已知含 0 保留真实环；直取详情无推荐分时保留当前分数位尺寸，显示中性“—”及“匹配分未知”，不绘制进度、不传 0/NaN |
| 匹配依据 | 保留已确认、尚未核对、无推荐批次等现有语义；缺依据不生成核对行、通过项或分析，不能以占位冒充核对完成 |
| 职位详情/职位要求正文 | 合法空正文保留原标题及“职位详情未知”/“职位要求未知”；已有真实岗位事实继续显示，不能用事实行的存在掩盖 JD 正文缺失 |
| 公司区 | 保留名称、介绍和当前公司元信息位置；已知事实照常显示，缺介绍显示“公司简介未知”，缺融资/规模/行业/成立/地址分别显示对应未知，不额外请求公开企业补数 |
| 公司图位 | Backend 无真实图源时在原 40px 图位显示中性空白占位及“公司图片未知”的可访问名；Mock 已有字标保留，不根据未知名称猜标志 |
| 发布人卡 | 原位置始终保留；缺姓名、职务、公司分别显示“发布人姓名未知”“职务未知”“企业信息未知”；缺头像保留原尺寸中性图位，缺备注在原备注区显示“发布人备注未知” |

部分字段已知就展示已知部分，不把整个对象降为未知。文本 trim 后为空视为缺失；零值不按真假值判断。未知文案只用于展示，不写回任何模型、请求或草稿。null 不自动解释为“未披露”。已有明确枚举的“不限”、否定值及未确认状态不改称未知，也不把 Backend 合法省略的办公地点、年薪月数等事实行强制扩成新字段表。

公司跳转仅由真实 organization ref 或原 Mock 导航回调提供。发布人的“直接聊”保留现有能力规则：Mock 且非嵌入隐藏状态可用；Backend 无直聊坐标时不新增按钮或模拟成功。保留发布人信息位置不等于补齐操作能力。

### 3.3 业务保护

- 保留推荐缓存命中、单 CandidateJob GET、当前意向推荐坐标恢复、404 收口及安全返回；不同意向不借坐标。
- 不感兴趣仍服务端先行，失败原地提示；无推荐坐标不可委托或不感兴趣。
- Backend 委托仍先读取附件库、按现有规则选择简历、每次披露确认后提交准确 file/version 坐标；取消和范围换代不复用授权，迟到结果照旧丢弃。
- 保留委托六态、进度未知、禁用规则及成功后不跳 P5 的行为。Mock 一次点击入谈的现有原型行为保留，不增加确认步骤。
- 举报 target 仍取成功解码的 job ID，保留无推荐坐标可举报及失效目标重读，不用路由参数猜 target。
- 现有确认层、附件选择层、举报层由连接层驱动，不借展示统一重构其协议或生命周期。

## 4. 双端消息列表

范围是 `src/屏幕/消息列表.tsx`、`src/屏幕/企业消息.tsx`、`src/屏幕/P7/Backend会话列表.tsx` 及对应 CSS、测试和专用展示文件。三条实现实际调用同一列表展示和会话行，使用一份主样式；两端现有样式差异先逐项核对，保留必要角色文案，不形成按角色复制整页的结构。

固定结构：消息标题/搜索聚焦按钮 → 全部/仅会话/通知 → 搜索框 → 状态区/会话行 → 按能力显示加载更多。行结构保持头像 → 标题、副标题、时间 → 摘要、未读标记。行上不加独立业务按钮，整行回调负责导航。

### 4.1 字段和缺失

- Backend 候选端标题取职位、副标题取地点；招聘端标题取候选代号、副标题取职位，保留已有映射，不自行恢复真名。
- context 不可用继续显示“会话信息暂不可用”，副标题留空但保留结构；不加入会被误当身份的未知姓名。消息摘要仍可显示。
- last_message=null 保留“已建立真人会话”，这是已有会话状态，不换成“消息未知”。时间沿用现有短格式，不重写时区算法。
- Backend 头像继续使用当前中性“会”标志，不从姓名或 Mock fixture 派生；Mock 原有代理标、字标和底色保留，均在同一头像容器内。
- 不为没有业务意义的空副标题、无未读或空列表填装饰占位；本页重点是共用结构，不制造假会话或假通知。

### 4.2 未读、筛选和导航

共享行接收明确的“无标记 / 红点 / 数字”展示状态，由连接侧映射。Mock undefined 为已读、0 为红点、正数为数字；Backend unread_count=0 为无标记，正数为数字，不误套 Mock 0 语义。

Mock 点击仍派发对应角色读消息后导航；Backend 点击只去 conversation ID 参数路由，已读等待会话页权威回执，不本地清零。Mock 招聘端 S3 意向确认门控保持，不能因为数据统一让 S1/S2 真人行提前出现。

保留当前页签顺序和搜索匹配字段。Mock 通知为 AI 动态，Backend 通知为明确空态；Backend 全部/仅会话使用相同的已加载真人会话集合。搜索只筛已加载项，保留服务端顺序，不增加远程搜索或声称覆盖全部。

保留 Backend 可见范围登记/注销、force 首读刷新、分页游标、重试及错误恢复。错误与缓存行可以同时可见，不强行压成一个互斥状态而丢失已有消息。加载、成功空列表、搜索无结果、通知空态分别保留原文案和语义。
