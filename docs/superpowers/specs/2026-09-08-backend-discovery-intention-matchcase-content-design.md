## 4. 同名意向的唯一业务坐标

### 4.1 选择与范围

Backend 的 `当前意向编号` 是唯一当前业务坐标；`当前意向` 只作显示，不得反查请求 ID、决定当前项或进行业务筛选。

- 顶部选中判断为条目 ID 等于当前 ID，同时保持“全部意向”档不高亮任何胶囊。点击同时写入该条的名称和 ID，沿用切回“当前”范围的动作语义。
- 当前 ID 只有在服务端快照及页面列表都存在该条、且状态为 active 时有效。没有有效 ID 时保持既有空／未就绪状态，P4 与“当前”P5 零请求；不得把 null 当作用户选了全部。
- “当前”档：市场 P4 请求、在谈 P5 请求、P5 内存快照键、市场横幅、待办统计必须引用同一有效 ID。保留现有主体归属检查、分页完整性判断和快照隔离。
- 用户显式选择“全部意向”时，P5 列表和横幅继续使用全部 scope（null），不改变为某个 ID；市场 P4 始终以当前有效 ID 查询。这是现有产品筛选行为。
- 市场横幅仍只消费已有 P5 快照，不新增订阅、请求或预取；直达市场无对应快照时继续显示既有加载文案，不拿第一条意向或 Mock 待办数填补。
- 切到第二条后，第一条的缓存或迟到结果不能填入第二条视图。复用现有按 ID 的 key 与代际隔离，不新建请求管理机制。

### 4.2 胶囊内容

只在 Backend 生成区分文字，使用现有胶囊按钮和样式：

1. 职位名称不重复：保持职位名，例如“产品经理”。
2. 职位名重复：加现有标题中的非空城市，例如“产品经理 · 上海”“产品经理 · 北京”。
3. 城市仍相同或缺失导致重名：对仍重名的组再附加已有非空薪资说明；最终仍相同的显示文字加当前列表内同组序号，如“产品经理 · 上海（1）”。序号只是列表位置提示，不代表业务属性、不持久化、不作为业务坐标。

不展示 `int_...`，不猜测城市／薪资，不新增办公方式字段、组件、tooltip 或样式。重复判定和标签 helper 限于本页面需求，不建通用标签框架。

### 4.3 新增、编辑、删除与重新水合

Backend 继续由真实接口的返回快照统一水合：优先保留仍有效的当前 ID；否则取返回列表中的第一条 active 真实 ID；一条也没有则 ID 为 null、展示名为空。ID 和名称必须取自同一条。

- 编辑第二条时，只更新它的显示名；编辑同名第一条不能改变第二条选择。
- 删除非当前项不影响当前选择；删除当前项回退剩余 active 项；删除最后一条清空选择。
- 新增不抢占仍有效的选择；从无有效意向变为有意向时选择首个有效项。
- 不使用 `I-xx` 本地编号或名称兜底填入 Backend 当前 ID。保留仅由 Mock 保存／删除分支触达的旧 reducer 动作，测试应通过真实 Backend 操作接线或 Backend 水合验证，不能为了修改用户列出的文件而重构 Mock。

### 4.4 浏览器刷新恢复

刷新验收指同一浏览器标签页内完整 Provider 卸载重建／页面重载，不仅是内存中的再次水合。

复用已有 sessionStorage 账号资料缓存，加入可选的候选选择 ID 字段；旧缓存没有该字段仍合法。不写标题、城市、意向列表、服务端 DTO、P4/P5 快照或 PDF URL。只在 Backend 候选角色按环境和 subject 隔离读写。

恢复值仅是待验证偏好，不能由通用 `水合账号资料` 直接写入可请求的当前 ID。候选角色首次服务端水合成功后，在现有主体／会话代际保护内验证它确实属于本次 active 列表，再与名称一起落状态。正常重新水合优先保留当前有效选择，不让旧缓存覆盖用户新选择。

恢复期间不能先请求第一条再切回第二条，不能把初始化的 null 或默认第一条提前写回覆盖已存第二条。水合失败沿用现有错误反馈，不把缓存当服务端成功结果；保留偏好供重试验证。服务端成功返回且恢复 ID 已删除、归档或不属于当前主体时，回退首个有效项并更新偏好；空列表则清空。

退出登录、401、角色切换和主体切换必须复用现有内存清理／代际边界，不让 A 的选择或迟到写入进入 B 的缓存／scope。招聘角色不恢复或覆盖候选选择；已有缓存其他字段保持其语义。存储不可用或内容损坏时不中断页面：使用服务端有效选择，刷新记忆能力相应降级。无跨设备、跨标签页或关闭浏览器后恢复保证。

## 5. Case 中的本人简历附件

- candidate 点击调用 `操作.读取简历PDF('candidate', caseId)`；recruiter 继续调用对应 recruiter 路径。保持现有数据源角色参数与 Case 授权读取，无新接口。

- 复用既有 PDF 弹层、对象租约、单飞防连点与轻提示。段内有时间线或叮嘱时附件入口仍存在。

- 请求失败保留当前页面，沿用已有轻提示，不跳转、不生成模拟文件、不触发披露／递交动作。

## 6. MatchCase 可见文本

### 6.1 隐藏意向 ID

删除状态行可见的“意向 {intentionId}”内容，不新增替代组件或异步意向名称查询。保留内部详情模型的 intentionId、现有路由／归属／动作坐标。沿用冻结职位标题、城市和薪资作为业务上下文。

不改动状态行或其他组件的样式值；内容槽的调整仅服务隐藏内部 ID。Case 加载、轮询、动作提交、PDF 读取和会话跳转的语义不变。

### 6.2 终局时间

在 `src/数据/MatchCase展示映射.ts` 内增加任务内聚的小型格式化函数，`映射终局摘要` 的 `定格于` 改为显示值。内部 DTO 仍保留原 RFC3339，不改 decoder 的严格校验。

使用 `Intl.DateTimeFormat('zh-CN', ...)`，包含年、两位月／日／小时／分钟，24 小时制（午夜为 00），不设置固定产品时区，使用用户运行环境本地时区。通过格式化结果的 parts 组成稳定的 `YYYY-MM-DD HH:mm` 显示，例如 Asia/Shanghai 下 `2026-08-29T03:00:00Z` 为 `2026-08-29 11:00`。不得硬编码加八小时。

若异常值绕过 decoder 抵达 mapper，显示“时间待确认”，不抛出破坏页面的格式化异常，也不返回原文。此兜底不放松后端时间契约。不处理本轮范围外的其他时间字段或 Agent 自由文本。

## 7. 市场／推荐委托流程对齐 Mock Up

### 7.1 成功判据与文案

唯一成功判据是服务端投影确认 `state === 'case_started'` 且 `case_id` 为有效非空字符串。POST 发出、HTTP 成功、accepted、evaluating 均不是开案成功。推荐 GET 的权威 delegation 摘要也可以恢复成功事实，不依赖浏览器内尚未恢复的回执表；已有摘要／回执关联校验与失败原因映射保持严格。

case_started 缺失、空白或非法 case_id 时不得显示成功状态标或按成功过滤；沿用契约错误／安全提示，不再显示“已创建真实在谈”这种未经坐标确认的成功断言。不能从 job_id、recommendation_id、delegation_id、别名推导 case_id，也不能单凭卡片 delegated 状态或 delegation 非空判断成功。

| 页面 | 未委托文案（现有 Mock） | 成功文案／形态 |
| --- | --- | --- |
| 招聘端推荐候选卡 | 让AI代理去聊 | AI代理已接触；现有不可点击状态标 |
| 求职端看市场岗位卡 | 让AI代理去谈 | AI代理已接手；现有不可点击状态标 |
| 招聘端匿名在线简历 | 让AI代理去谈 | AI代理已接手；现有不可点击状态条 |
| 求职端职位详情 | 让AI代理去谈 | AI代理已接手；复用 Mock 现有禁用主键与已委托样式，无跳转 |

成功槽不再出现“查看进展”按钮，也不绑定点击／键盘 Case 导航。只复用本页 Mock 已有元素形态、CSS 类和图标用法，不统一各页文案、不修改样式定义、不新增产品组件。职位详情的 Mock 成功控件本身是 disabled button，本轮保持该不可操作形态，不另设计 span 布局。

卡片原有“查看职位详情”“查看候选画像”和正文点击仍按原岗位／推荐坐标查看资料，不转成 Case 入口。详情直取无 recommendation_id 时继续不可委托，不为恢复成功而增加猜测请求。四个入口成功后均保持当前页面；不复制 Mock 详情中的本地入谈／自动导航动作。

accepted、evaluating、needs_user、refused、failed 保留现有安全文案、失败恢复与重试语义。它们不显示上述成功文案、不因本需求过滤；网络未知不转成成功。该文案只表示 AI 代理接手任务，不表示双方已联系、确认意向、完成后续阶段或建立真人会话。

### 7.2 当前进屏暂留与再次进入过滤

Backend 两个列表增加页面内、按当前主体＋角色＋岗位／意向 scope 隔离的最小本次操作记录，复用 Mock 集合思路，独立于 Mock 集合和 reducer：

- 当前进屏发起委托时可记录用户操作的业务 pair，供随后异步回执关联；记录本身不授权成功。只有同一有效页面周期中的权威成功投影到达，才把该卡视为“本次成功暂留”。POST 直接成功和 accepted/evaluating 后轮询成功均覆盖。
- 卡片显示顺序不因委托成功改变；本次成功卡暂留原位显示状态标，不强制刷新推荐列表使它立即消失。正常收藏／搜索／不合适等用户主动操作仍遵守原过滤语义，不要求绕过用户自己的筛选。
- 进屏时已经成功的卡从待选流过滤；不把首载 GET 读到的历史成功批量加入本次集合。上次已发起、这次进屏才轮询到成功的卡也不冒充本次点击暂留。
- 离开列表再返回、卸载重挂或岗位／意向 scope 切换，结束该次暂留周期；切回旧 scope 是新周期，不恢复其暂留集合。打开资料详情再返回也属于重新进入列表。
- 浏览器刷新后本次集合自然为空，由权威推荐摘要恢复成功过滤。已有缓存仅作为真实接口快照复用，不把失败加载解释为未委托；需要重新读取时沿用现有加载与重试，不以空初始值放开重复委托。
- 列表过滤只是渲染投影，不删服务端推荐、不删 P4 资料详情快照、不归档／结束 Case、不终止委托；不将成功集合或推荐快照持久化。

范围切换／主体切换后迟到的 Promise 即使返回 case_started，也不能往新页面暂留集合写入、提示成功或改变导航。沿用 P4 会话／scope 栅栏；页面回调同样校验本次周期，不能仅因 Promise resolve 就添加成功。

### 7.3 防重复与其他卡片可操作

保留操作层 candidate-intention-job／recruiter-job-recommendation 的单飞、幂等键和轮询节拍。页面将委托忙态限定到同一业务 pair，重复点击同卡只产生一次请求；等待单卡 POST 或轮询时，其他卡可浏览、收藏和发起委托，不沿用整页反馈中作为委托总锁。

候选侧附件选择／披露确认仍使用现有单个弹层；用户确认关闭后，无须等该卡 POST 完成就可操作其他卡。单卡正在进行或已成功时不重复提交。共享资源确有既有互斥的反馈操作仍保留其锁，本需求不扩展为整个反馈／请求系统重构。

### 7.4 开案后的 P5 工作区刷新

在操作层收到并通过主体／scope 校验的成功回执时，令同角色对应意向／岗位的 P5 open 工作区及“全部”open 工作区缓存失效。创建直接返回成功与轮询成功使用同一失效规则；两侧详情委托也必须触达，不能只接列表点击回调。

采用最小的现有缓存清除＋读代际失效方式，使下一次进入在谈时 `加载工作区` 不命中旧成功快照而真实 GET；不额外导航、不在市场注册 P5 scope，也不需要立刻在后台重读全部列表。轮询的 scope 从与 delegation_id 匹配的已有卡片／详情坐标获取，不能用用户已切到的新 scope 或不可靠的候选回执 recommendation_id 猜测。关联到多个实际缓存 scope 时逐个失效；缺少关联时至少使同角色全部范围失效，不猜一个岗位／意向。

失效必须让已有在飞列表读／追加结果过期，防止旧空列表随后重新落成成功缓存。失效限于匹配主体和角色的工作区；不清 P5 动作幂等意图、Case 详情或其他角色数据，不另建全局事件总线或通用缓存框架。相同 delegation 的相同成功重复回执不反复触发刷新风暴。

进入在谈后，卡片和详情只能由 Workspace／Case API 读取。开案成功不说明 Case 仍属于 open；服务端已 ended／completed 则按对应 lifecycle 列表合同处理。新 Case 暂未出现在权威列表时不插入伪卡、不推测阶段。

加载失败显示现有错误和重试入口；已有成功空缓存后刷新失败，也必须显示错误，不能被 `视图们.length > 0` 挡住而仅呈现正常空态。保留有旧条目时只读显示与重试行为，沿用错误行组件和样式。

## 8. 发布新岗位后的当前选择

该项与委托文案独立，沿现有发布返回链实施，不新增全局状态系统：

- Backend 创建数据源保留 POST 响应的真实非空 job_id，随既有权威岗位重读结果返回；岗位操作向发布页面返回这个精确 ID。允许为该实际消费者调整前端内部创建结果类型及发布操作返回值，不改变 wire 接口或把创建结果字段加到所有岗位读取／更新响应中。
- 正常新建完成且发布页面／主体／角色和本次选择意图仍有效时，在按既有流程返回企业主壳之前用现有 `切当前岗位` 动作选中新 ID，同时保证其对应的服务端岗位已经水合。标题、胶囊、推荐请求和“当前岗位”在谈 scope 同源；该动作既有的范围切换语义保留。
- 不用页面组装的 `P-xx`、岗位名称、数组第一项、列表前后差集或发布时间猜新岗位。Mock 发布返回与 reducer 行为不变。
- 发布过程中用户离开页面、切换主体／角色或选择其他岗位后，迟到响应不得覆盖后来的选择，也不得拉用户回发布成功页／主壳。离开再回来或岗位 A→B→A 也属于旧意图失效，不能只比较最终 ID 是否相同。复用既有生命周期／选择代际；缺少时只增加这次发布所需的局部有效性保护。
- 同主体仍有效的创建事实可以通过权威列表刷新体现，但自动选择和导航要单独受有效性限制；旧主体迟到结果不水合到新主体。
- 发布失败不执行自动选择或成功导航。POST 已成功但后续岗位重读失败，沿现有错误恢复提示，不假定整条发布返回链已完成，不通过本地造岗位填补。
- 新岗位推荐加载时只消费新 ID 的 scope：显示现有加载态，不展示旧岗卡片作为新数据；成功返回空推荐显示新岗位正常空态。保留组织／身份门禁，不以自动选中绕过推荐资格。
- 编辑岗位仍按原流程保存返回；注册首发岗继续现有初始化去向，不新增页面或改变导航视觉。
