# 双端在谈详情展示统一与完整缺失布局设计

日期：2026-09-10。

状态：设计方向已确认；本 Spec 待用户审阅批准，尚未编写 Plan 或实施。

## 1. 目标、基线与批准边界

在求职端「在谈详情」和招聘端「候选详情」中，让 Mock 与 Backend 实际调用同一套展示组件与 CSS。以当前 Mock 的信息顺序和视觉布局为起点，完整保留页面信息区；Backend 缺少展示数据时在原位置明确显示缺失状态，方便后续补数据。

本地代码基线：`b93436e956dcd133ca909c06939e3416f2f3ad24`。目标分支为 `main`；实施及合入时重新核对 target，不以规划基线代替最终基线。

本次只覆盖两条详情路由、它们的控制逻辑、展示组件和必要测试。历史列表打开同一详情时也遵守终局只读行为。路由地址、Case 坐标和已有 Mock 深链语义不改变。

用户已确认：

- 一份 Spec、一份 Plan，只做双端在谈详情；Plan 总计 8–10 个顶层 Task，包含恰好一个 final gate。
- 两端都保留第二个 Tab：求职端「职位详情」、招聘端「在线简历」。缺数据不得隐藏整个 Tab 或整个信息区。
- 缺失保留位置，不填假值、不用 Mock 数据补 Backend；数据和控制与展示分离。
- 与 `audit-frontend-data-wiring` 列表统一任务并行，按第 9 节约定文件和依赖边界。

前序 P5 设计 `docs/superpowers/specs/2026-08-29-recruitment-p5-frontend-wiring-design.md` 中“Backend 独立整页、Mock 原页面保留”的展示选择被本 Spec 替代。原有严格解码、真实动作、授权、轮询、原始 PDF、会话移交和禁止跨域补齐约束继续有效。前序源码中的“Mock JSX 逐字保留”不阻止本次删除重复展示。

## 2. 当前问题与最小方案

入口 `src/屏幕/在谈详情.tsx`、`src/屏幕/候选详情.tsx` 目前按模式切换整页。Backend 双角色共用 `src/屏幕/P5/MatchCase详情.tsx`，Mock 保留各自顶栏、Tab、阶段映射和动作卡。

已有 `阶段对话流`、`真输入条`、确认层、PDF 层可以复用。Backend 的 `详情主体`、`阶段动作区` 仍同时读取 raw 快照、处理业务动作并渲染 UI；把它们原样改名不能算完成分离。

选择“现有控制连接层 + 小型详情展示投影 + 共用业务展示组件”：

1. Mock 连接层读取原型数据、计算已有模拟匹配依据、执行 reducer 和原型导航。
2. Backend 连接层读取合法 P5 视图和动作所需的 typed 数据，执行原有操作、轮询和授权。
3. 共用展示层只接收页面数据、业务状态、输入值与回调。可在展示层保留 Tab、折叠、滚动定位等纯 UI 状态；业务提交草稿、请求生命周期和权限判断留在控制层。

展示层不读 Context、fixture、localStorage、环境变量或 BFF raw DTO，不自行推导动作权限、计算业务匹配分、请求数据或拼路由。详情展示数据不得写回服务端模型、持久化草稿或原型 reducer。

不采用只共用 CSS：仍会留下两份 DOM。也不把 Backend 转成完整 Mock 在谈单/候选：会强迫填分数、公司、剧情和本地决策字段。小型投影仅覆盖本页真实区块，不建立全站 ViewModel 框架、adapter 注册表或通用缺失 schema 引擎。

## 3. 固定布局与两端差异

### 3.1 页面外壳与顶栏

两种来源共用返回栏 → Tab 行 → 当前 Tab 滚动内容 → 底部输入/只读状态区。Tab 默认是「代谈进度」；切 Tab 不改变 URL、不产生历史记录。切换 Case 或角色后重置 Tab 和本地 UI 状态，不能沿用上一个人的内容或弹层。

求职端保留职位、公司上下文及原右侧适配/薪资位置；已知职位与薪资来自 P5 冻结职位。公司缺失显示「公司信息缺失」，适配分缺失为「—」并有「匹配分缺失」说明，不画假的进度或低分警示。Mock 原有阶段相关标题/薪资规则仍由投影表达。

招聘端遵守当前去名裁定：顶栏是性别、年限、学历、求职状态与副标题信息，不恢复真名或 candidateAlias。Backend 详情目前没有这些结构化画像字段，保留各位置并显示「经验缺失」「学历缺失」「求职状态缺失」等文案；性别位为中性未知标记，不猜性别。冻结职位、城市、薪资仍有单独可读的岗位上下文，不丢失当前 Backend 已知事实。

P5 待办徽标、步骤说明、轮次和注意说明保留在「代谈进度」的状态区，不占用或替代匹配分位置。Mock 没有的轮次等字段显示该项缺失，不编造轮次；仅在存在真实注意说明时显示注意提示，不人为制造错误。

### 3.2 代谈进度

两端、两种来源都展示四个阶段，继续使用 `阶段对话流`：阶段分节 → 状态/摘要 → 清单和消息 → 附件 → 当前阶段动作。未到达阶段保留折叠段及“尚未进入该阶段”，不能标成接口缺失。进入详情定位当前阶段；从第二个 Tab 返回时须能访问当前阶段，不能因条件挂载丢失节点定位。

阶段标题和状态文案由各自合法投影给出；Backend 保留现有 P5 的阶段与业务状态用语，不从文本反推枚举。S0 Agent 问答、候选私有总结、时间线与叮嘱回执顺序沿用现有投影。没有消息时显示“暂无对话记录”，不能生成一段模拟代理对话。

缺失状态保留到区块/信息槽级，不模拟任意数量的经历、消息、项目或动作卡。未来阶段无需提前摆出全部决策按钮。无权威动作时给“等待当前流程推进”等符合现有状态的说明；不能根据阶段名新造服务端未提供的动作。

### 3.3 求职端职位详情 Tab

按现有 Mock 阅读顺序保留：匹配分析 → 职位详情 → 职位要求 → 公司信息 → 对接人。

- 匹配分析保留分数/分析区与缺失说明；没有对齐证据时不列假通过项、假清单或 AI 判断。
- 职位详情与职位要求各有独立标题和正文位置；Backend 当前显示“职位详情缺失”“职位要求缺失”，并说明“当前在谈详情数据未提供”。冻结职位名、城市、薪资和技能可在岗位摘要位置如实展示；技能不冒充完整 JD 或福利。
- 公司保留图片、名称、介绍、融资阶段、规模、行业、成立和地址位置，以及公司标签区。每个缺项显示对应缺失；未知图片用本地中性占位，不加载外部占位图。
- 对接人保留头像、姓名和职务位置。缺失不生成姓名/首字，不冒充已认证或已披露。
- 无合法公司导航坐标时保留公司区和导航入口位置，入口禁用并解释“公司详情暂不可用”。不能用公司文本推 opaque ID。

Mock 已有真实演示内容保持其格式；Mock 本身缺项也走相同缺失布局，不再按来源隐藏对接人等区块。

### 3.4 招聘端在线简历 Tab

完整保留现有简历正文的信息顺序：匿名画像/职位行 → 匹配依据 → 个人优势 → 求职期望 → 工作经历 → 项目经历 → 教育经历 → 专业技能 → 披露/沟通状态说明。项目为空也保留标题与空状态；不新增证书、年龄概览或已经删除的人像/姓名头区。

Backend 当前 P5 detail 不提供结构化在线简历；以上每个信息区分别显示缺失状态，不能以一条“简历尚未同步”替代整页。求职期望未知时不展示真实数字或“薪资带已进入初筛/一致”等无依据承诺；岗位薪资不是候选求职期望，不能代填。

现有 `匿名在线简历.tsx` 的 `简历正文` 可提取/委托给共用纯展示，以便两种来源实际共享同一正文，而非新增 Backend 占位专用整页。其其他消费者的默认行为保持不变；完整缺失布局由详情调用显式选择，不顺便改独立匿名简历页面。

S1 授权的原始 PDF 和结构化在线简历是两项能力。PDF 入口继续在阶段流附件位；存在合法附件时按当前角色授权读取真实 PDF。PDF 已可读也不能推断结构化简历已提供，不能解析 PDF 在前端补字段。

## 4. 缺失、空态、失败与披露规则

| 情况 | 显示与控制 |
| --- | --- |
| 详情尚未加载 | 可展示中性壳/加载骨架，显示“正在加载”；不得渲染一份正常的全缺失 Case，也无可执行动作 |
| 首次读取失败或无效坐标/无访问权限 | 保留错误/不可用语义和已有恢复入口；不转换成字段缺失，不展示旧 Case 内容 |
| 严格解码失败 | 沿用契约错误视图，动作表为空；不能为获得完整布局放宽协议或展示部分不可信数据 |
| 合法详情存在，当前接口没有某展示字段 | 保留该区，显示“某信息缺失”，配“当前在谈详情数据未提供”的区块级说明 |
| 合法 nullable 字段为空且原因不明 | 显示“某信息缺失”，不猜未填写、未披露或尚未接线原因 |
| 合法列表无内容 | 区块保留，显示“暂无工作经历/项目经历/对话记录”等；不声称真实世界中不存在 |
| 权威状态明确未授权/未披露 | 显示“尚未披露”，保留披露门，不把权限问题标成接口缺失 |
| 刷新失败但有同范围有效旧快照 | 保留旧内容和刷新错误/重试说明，沿用既有只读保护；不把旧值清成缺失，也不制造成功动作 |
| 从有值刷新为合法空值 | 立刻回到对应缺失/空态，不残留旧字段、图片或旧事件回调 |

状态原因只在已有合同和请求状态可证明时区分。无原因证据时使用“缺失”，不新增获取缺失原因的接口或全局原因系统。

缺失使用现有次要文字色，不用错误红色/通过绿色。数值 0 是合法数值时显示 0；缺失显示“—”和可访问文案，不传入 0、NaN。长说明可换行，完整布局不要求所有数据量有相同高度；不得横向溢出、遮挡按钮或把后续信息区因缺值彻底移除。

## 5. 动作与输入分离

共用具体业务展示单元：补充事实问题、简历邀请/选择/确认、初筛决定、协调决定、意向确认、终局/会话移交，以及输入条。输入/按钮的标签、说明、禁用原因和回调由控制层提供。已有动作卡内部的多按钮关系保持，不把所有命令揉成可自由配置的通用表单引擎。

Backend 动作仍只来自现有 actions 和 typed 业务条件；清单、对话自由文本、缺失字段不能产生权限。当前已提供的动作若缺必需数据、正在提交或受权限限制，保留该动作位置并禁用解释；协议不合法时整页走错误，不保留可点击动作。

必须保护：

- S0 补充事实绑定当前 promptId；回答成功才清草稿，失败可继续编辑；当前 Case 在飞锁不能因动作卡卸载而丢失。
- S1 当场选择文件和版本 → 本 Case 本次披露确认 → 真实提交。取消/遮罩/Esc 不提交，不能复用上次授权；替换和校验仍使用现有绑定坐标。
- S1 招聘方通过/不合适、S2 当前 issue 接受/拒绝、S3 本端确认/婉拒保留现有语义与必要确认。不能将 Mock “接受条件”直接视为 Backend 任意动作。
- P5 提交失败不本地推进阶段；成功后的权威重读和并发规则保留。切 Case、切角色、切账号、卸载时丢弃迟到结果，关闭弹层并清理对应局部状态。
- 叮嘱保持当前 Case 的真实发送；Tab 切换不把草稿发送给另一个 Case。终局时保留底部区域并显示“当前在谈已结束，仅可查看”，输入禁用且无发送回调；Mock 同类终局也只读。
- 终局摘要保留已有内容。completed + pending 显示正在创建会话且“开始私聊”禁用；ready 时只按真实 conversation_ref 导航。pending 继续现有轮询，不造前端超时终态。
- PDF URL 租约只在弹层生命周期存在，关闭/换 Case/换角色/换账号/卸载回收；迟到租约立刻回收。保留防连点，不缓存或把真实文件内容写入 fixture。
- Mock 的“拿不准/记成规则”演示仍在 Mock 控制层；Backend 不新增规则写入。相应演示入口如显示在同一动作区，Backend 明确禁用并说明“暂不支持记成规则”，不能声称已生效。

展示完整不等于提前展示所有未来/他方动作。状态区、阶段区、资料区保留；权限和生命周期仍决定本次提供哪些业务动作。

## 6. 字段缺口清单

本表是当前源码消费的合同事实，不断言每个运行账号均缺数据，也不授权补接口。

| 信息位置 | 当前 Backend 权威来源 | 本次处理 |
| --- | --- | --- |
| 职位名/城市/薪资/技能 | P5 detail 的 job，经 `映射P5详情().职位` | 如实显示冻结摘要，不用其他域覆盖 |
| 求职顶栏公司及第二 Tab 公司各项/图片/对接人 | 当前 P5 detail 未提供 | 按 §3.3 逐项保留并标缺失；公司入口不可用 |
| 两端匹配分、匹配分析证据 | 当前 P5 detail 未提供 | 分数未知，分析区保留缺失说明；不读取推荐分或重算本人简历 |
| 招聘顶栏性别/经验/学历/求职状态 | 当前 P5 detail 未提供；open 的 candidate_summary 不等于 detail 合同 | 各项保留缺失，零额外 open 查询补齐 |
| 招聘顶栏称呼 | detail 有 candidateAlias，但最新视觉不显示称呼 | 不显示，不解析成身份，不以“缺少姓名”占位恢复姓名区 |
| 在线简历各结构化区、求职期望和匹配一致性 | 当前 P5 detail 未提供 | 各区保留缺失；无假薪资/一致性结论 |
| 阶段状态、步骤、轮次、待办、注意说明 | 现有 state 与 `映射P5详情` | 完整保留真实值和当前安全文案 |
| S0 问答与私有总结 | 现有 typed 阶段投影 | 保持角色可见性和原序，不跨角色补齐 |
| S1 原始附件 | 当前角色阶段投影中的附件及现有 Case PDF 操作 | 合法附件才可读；不把附件 null 直接认定为未披露 |
| 当前动作/事实问题/协调问题/意向决定 | actions、补充问题与现有 typed 阶段块 | 控制层依照原合同提交，展示不判断权限 |
| 终局与私聊坐标 | 现有终局摘要/handoff/conversation_ref | 只读、pending/ready 原语义不变 |

实施可在本表纠正已证实的字段来源，实质增加字段消费、公开能力或跨域查询需修订批准设计。无需另建缺口报告或后端任务文件。

## 7. 非目标与以后重启条件

不改推荐/在谈列表、跨流程选择器、onboarding、招聘名片、岗位管理、发岗、简历管理附件库、初始化扫描计数。审计发现的岗位在谈人数错误留给相应任务，不带入本次。

不改 BFF schema、请求 URL/query/body、解码白名单、角色授权、状态机、数据库或持久化；不新增 Company/Job/Resume/P4 查询来填 Case 详情，不把 open candidate_summary 引入 detail 请求。保留现有每个动作需要的附件读取等请求。

不重新设计品牌视觉、不恢复筛选、姓名头区、年龄概览等已删除功能；不统一独立匿名在线简历/职位详情全页。共享组件变更只能默认兼容其他消费者，必要时提取纯展示与旧调用适配，不复制整份正文。

未来只有服务端提供与该 Case/角色绑定、语义和披露条件明确的字段时，另行接入缺口；只有本页以外出现同类明确需求时，才考虑提升局部展示模型为跨页面抽象。

## 8. 验收与完成标准

每个实现 Task 自带对应测试，不把全部测试推给收尾。沿用 Vitest、现有数据源模式 Playwright、视觉回归和真实后端 dogfood 入口，不新建测试平台。规划阶段不运行重测试估时；当前依赖和运行耗时未验证。

必须覆盖：

1. 双端两种来源以等价展示输入渲染同一组件、同一信息顺序和 CSS；共用展示不需 Provider，不导入 Mock fixture 或 Backend raw DTO。删除被替代的重复 JSX 和无人使用样式。
2. 第二 Tab 始终可访问；完整、全缺、部分缺、真实零值、合法空数组、长文本、刷新有值变空都保留相应区块，无 NaN、undefined、破图或残留事实。
3. 区分初次加载/请求失败/契约错误与合法字段缺失；无权限/无效 Case 不出现一份可操作的全缺失详情。Backend 不发额外跨域补齐请求，Mock 不发 P5 请求。
4. 两端 S0–S3 动作、邀请选择和披露取消/确认、替换、回答失败与在飞换单、叮嘱、终局、pending/ready 私聊移交、PDF 回收均保持原控制语义。等效整理不能删掉这些保护断言。
5. 390px 和 320px 浏览器布局：两种来源用等价数据比较顶栏、Tab、四阶段、动作区和第二 Tab 的区块位置；允许亚像素差异，不强求不同内容整页等高。完整缺失时所有约定区块可见、说明可读，无横向溢出和交互遮挡。
