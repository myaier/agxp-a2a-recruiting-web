# 招聘数据源切换与真实后端接入设计

状态：设计已确认，等待书面规格审阅

日期：2026-08-24

## 1. 背景

当前项目是 PM 使用的招聘产品原型，基于 React、TypeScript 和 Vite。页面和交互已经过设计确认，数据主要来自 `src/数据/模拟数据.ts`、`src/数据/企业端模拟数据.ts`，以及少量组件内静态数据。

项目虽然已有 `src/数据/接口层.ts`，但它目前只定义了候选人侧的模拟数据源，且没有成为页面的统一入口。`src/状态/应用状态.tsx` 和多个页面仍直接导入模拟数据。因此，接入真实后端不能只替换一个导出，需要先把可由后端支持的数据收口到统一数据源，同时保留当前 Mock 模式的 DOM、交互和视觉表现。

真实接口以 `~/agxp-monorepo` 中 `apps/recruitment-bff` 的公开 Mobile API 为准。前端只访问 Recruitment BFF，不直接访问内部 Recruitment Service。

本次设计参考的后端契约基线为：

- STG 集成分支：`integration/stg-recruitment-91a4e19@91a4e19`
- 补充接口参考分支：`integration/recruitment-resume-files-s1@42e4b506`
- OpenAPI：`apps/recruitment-bff/openapi/mobile-v1.yaml`
- STG Origin：`https://recruitment-stg.agxp.ai`
- 本地 BFF Origin：`http://127.0.0.1:8097`

上述分支仍可能演进。实施时应再次对照目标 BFF 分支的 OpenAPI；如果契约不同，应先更新本设计或实施计划，不在映射层中猜测字段。

## 2. 目标

本次改造的目标是：

1. 增加两个环境变量，独立控制数据源和真实后端环境。
2. 默认继续使用 Mock，确保 PM 原有体验不变。
3. Backend 模式下，由统一的数据源调用 Recruitment BFF；失败时不得偷偷回退到 Mock。
4. 仅接入当前 BFF 已经提供完整使用链路的招聘数据，缺少接口的原型内容继续明确使用演示数据。
5. 不改变任何页面设计，包括布局、文案、样式、加载效果和错误展示形式。
6. 将接口请求、字段映射和运行配置集中管理，页面不直接调用 `fetch`。

## 3. 非目标

本次不包含：

- 修改 `~/agxp-monorepo` 或部署后端。
- 为缺失的后端能力设计新接口。
- 把所有静态演示内容强行持久化到后端。
- 增加全局状态库或请求框架。
- 增加新的 Loading、骨架屏、错误页、重试按钮、数据源徽标或环境标识。
- 修改 GitHub Pages 或 Capacitor 的发布架构；真实后端模式只用于本地 Vite 开发。
- 重做现有页面组件、CSS、路由结构或产品交互。

## 4. 运行配置

新增两个 Vite 环境变量：

```dotenv
VITE_DATA_SOURCE=mock
VITE_BACKEND_ENV=stg
```

### 4.1 `VITE_DATA_SOURCE`

允许值：

- `mock`：使用当前模拟数据和当前 PM 体验。
- `backend`：对已支持的业务域调用真实 Recruitment BFF。

缺省值为 `mock`。

### 4.2 `VITE_BACKEND_ENV`

允许值：

- `stg`：通过 Vite 开发代理访问 `https://recruitment-stg.agxp.ai`。
- `local`：通过 Vite 开发代理访问 `http://127.0.0.1:8097`。

缺省值为 `stg`。该变量仅在 `VITE_DATA_SOURCE=backend` 时生效。

### 4.3 校验原则

运行配置由新增的 `src/配置/运行配置.ts` 集中解析。缺省值按以上规则补齐；显式填写未知值时应立即报错，不应静默选择其他环境。启动时可以在开发者控制台输出一行数据源摘要，但不得把环境信息加入页面。

建议为仓库增加或更新 `.env.example`，只记录上述非敏感变量和允许值，不提交凭据。

## 5. 开发代理与会话约束

前端始终请求同源路径 `/api/v1`，不在业务代码中拼接 STG 或本地完整地址。`vite.config.ts` 根据运行配置选择代理目标：

| 后端环境 | Vite 代理目标 | 请求调整 |
| --- | --- | --- |
| `local` | `http://127.0.0.1:8097` | 保持浏览器 Origin 为 `http://localhost:5173` |
| `stg` | `https://recruitment-stg.agxp.ai` | 将代理请求的 Host 和 Origin 改写为 STG Origin |

本地 BFF 应配置：

```dotenv
RECRUITMENT_BFF_ENV=test
RECRUITMENT_BFF_PUBLIC_ORIGIN=http://localhost:5173
```

当前 BFF 只在 `test` 环境允许 loopback HTTP Origin，因此本地联调必须使用上述兼容配置。开发者必须用 `http://localhost:5173` 打开前端，而不是 `http://127.0.0.1:5173`。这是因为 BFF 对变更请求执行精确 Origin 校验。

所有 BFF 请求均使用 `credentials: 'include'`，让浏览器管理 HttpOnly 会话 Cookie。前端不读取、复制或持久化该 Cookie。

## 6. 视觉和交互不变约束

这是本次改造的硬约束：Backend 模式不能引入任何新的视觉设计。

- 不新增 spinner、骨架屏、“正在加载”文案、占位卡或页面遮罩。
- 不新增错误面板、空状态、重试按钮、来源标记或环境提示。
- 不修改 CSS、字号、颜色、间距、动效和页面结构。
- 保留现有 `use模拟加载`、既有骨架效果和路由的 `路由加载中`；它们不因接入后端而重新设计。
- 必须等待登录或角色切换请求完成时，保留当前页面并在逻辑层阻止重复提交，不新增按钮状态样式。
- 请求错误只复用项目现有的轻提示能力，不新增展示组件。

默认 Mock 模式下，页面 DOM、文案、交互顺序和模拟加载节奏应与改造前一致。

## 7. 验证码约束

登录页继续保留当前 4 格验证码，不改为 6 格，也不修改视觉或输入交互。

当前 BFF 契约/发布配置按 6 位固定 OTP 工作。因此，Backend 模式的登录有一个明确的外部前提：目标 Local 或 STG BFF 必须先支持 4 位 OTP。本项目不通过截断、补位或写死映射来规避后端校验，也不在本次工作中修改后端。

在该前提尚未满足时，Mock 模式仍完全可用；Backend 模式的验证码登录失败应按普通认证错误，通过现有轻提示反馈。

## 8. 总体架构

采用“运行配置 + 统一数据源 + 映射层 + 现有 Context 异步编排”的最小架构：

```text
页面 / 现有交互
       |
       v
应用状态 Context 的异步动作
       |
       v
统一招聘数据源接口
   |              |
   v              v
Mock 数据源     HTTP 招聘数据源
                  |
                  v
              后端映射层
                  |
                  v
             /api/v1 (Vite proxy)
```

### 8.1 `src/配置/运行配置.ts`

职责：

- 读取和校验两个环境变量。
- 暴露类型化的 `数据源模式` 和 `后端环境`。
- 保证默认值分别为 `mock` 和 `stg`。

### 8.2 `src/数据/接口层.ts`

职责：

- 定义页面所需的招聘数据源能力，而不是暴露后端 DTO。
- 提供 Mock 数据源和 HTTP 数据源的统一选择入口。
- 不再让已接入业务域的页面直接导入模拟数据。

接口按业务能力拆分，例如会话、角色、简历、求职意向、招聘职位和目录，不创建一个无边界的通用请求方法。

### 8.3 `src/数据/HTTP招聘数据源.ts`

职责：

- 封装 `/api/v1` 请求、Cookie、状态码和响应解析。
- 为写请求生成 Idempotency-Key。
- 对需要并发控制的更新携带 ETag/If-Match。
- 将传输层错误转换为项目内部可识别的错误类型。

### 8.4 `src/数据/后端映射.ts`

职责：

- 在 BFF DTO 与现有中文页面模型之间做纯函数转换。
- 统一处理 catalog ID 与页面显示文案的对应关系。
- 不在 React 组件中散落字段重命名、默认值或协议判断。

### 8.5 `src/状态/应用状态.tsx`

继续使用现有 Context 和 reducer，不引入新状态库。Context 增加最少量的异步动作：

- Backend 模式启动时恢复会话，并拉取当前角色所需的可用数据。
- 保存简历、意向或职位时先调用数据源，成功后再把服务端结果写入 reducer。
- Mock 模式继续执行现有同步初始化和动作，避免 PM 流程发生变化。

页面只调用 Context 动作，不直接选择环境，也不直接调用 HTTP。

## 9. 数据归属和接入范围

当前 STG BFF 并未覆盖原型中的所有招聘页面。本次用显式的数据归属防止“部分真实、失败后又变成假数据”的混乱。

| 业务域 | Mock 模式 | Backend 模式 | 说明 |
| --- | --- | --- | --- |
| 登录、会话、退出 | Mock 现状 | 真实 BFF | 保留 4 格验证码；后端需先支持 4 位 OTP |
| 当前角色 | Mock 现状 | 真实 BFF | 登录和角色切换成功后再导航 |
| 地点、分类等目录 | Mock 现状 | 真实 BFF | 页面仍显示现有文案，内部保存 catalog ID |
| 候选人简历 | Mock 现状 | 真实 BFF | 支持字段由服务端权威保存 |
| 求职意向 | Mock 现状 | 真实 BFF | 通过映射层转换 |
| 招聘方职位 CRUD、当前职位 | Mock 现状 | 真实 BFF | 使用真实 ID、ETag 和幂等键 |
| 市场职位发现列表 | Mock 现状 | 显式演示数据 | 当前公开 API 无完整发现列表 |
| 候选人/招聘方匹配列表 | Mock 现状 | 显式演示数据 | 当前 STG 缺少双方完整、稳定的列表链路 |
| 评价与匹配详情 | Mock 现状 | 暂留演示数据 | 虽有部分端点，但缺少本原型可用的端到端发现链路 |
| 消息、规则、AI 简报、会话和历史 | Mock 现状 | 显式演示数据 | 当前 BFF 不提供对应能力 |

“显式演示数据”是产品原型的数据归属，不是接口失败时的兜底。它只允许出现在上表标记的未支持业务域。已接入业务域一旦选择 Backend 模式，网络或接口失败不得退回 Mock。

为避免新增页面徽标，数据归属通过代码模块边界、README 说明和开发控制台启动摘要表达，不进入 UI。

## 10. 初始化与操作数据流

### 10.1 Mock 模式

1. 按当前方式同步加载模拟数据。
2. 保持当前页面初始内容、现有 localStorage 行为和交互节奏。
3. 不发起 Recruitment BFF 请求。

### 10.2 Backend 模式启动

1. 解析运行配置并选择 HTTP 数据源。
2. 调用会话接口恢复登录状态。
3. 未登录时保持登录流程；已登录时读取当前角色。
4. 按角色拉取目录及该角色已支持的权威数据。
5. 映射为现有页面模型后写入 Context。
6. 未支持业务域继续使用其固定演示模块，不参与请求失败兜底。

初始化过程不得增加新的 Loading 视觉。若现有路由切换必须等待异步模块，可复用当前完全相同的 `路由加载中`，不创建新的变体。

### 10.3 写操作

1. 页面沿用当前表单和按钮。
2. Context 将页面模型转换为 BFF 请求。
3. 调用真实接口；逻辑层阻止同一操作重复提交。
4. 成功后用响应中的真实 ID、版本和规范化字段更新状态。
5. 失败时保留最后一次服务端确认的数据，并复用现有轻提示。

## 11. 字段映射与前端附属数据

### 11.1 Catalog 字段

后端使用 `category_id`、`location_id` 等稳定 ID，当前页面主要显示中文名称。映射层维护 ID 与显示名的对应关系：

- 拉取数据时把 ID 转成当前页面需要的显示值，同时保留隐藏 ID。
- 提交时优先使用已保留 ID。
- 对 Mock/旧缓存中只有显示值的数据，在提交前通过已加载 catalog 做精确匹配。
- 无法唯一匹配时终止提交并使用现有轻提示，不能猜测或提交错误 ID。

### 11.2 招聘职位

页面字段映射到 BFF 的 Job Create/Update 模型，包括：

- 职位名称、招聘类型、类别、地点、办公地点和工作方式。
- 薪资、年薪月数、校招届别、实习月份、每周到岗天数。
- 经验、学历、职位描述、任职要求。
- `职位关键词` 映射为后端 `keywords`。
- `筛选要求` 映射为后端 `private_screening_preferences`。

当前页面中的 `加分关键词`、`实习转正` 暂无对应后端字段。为了不删除、不隐藏页面字段，也不把数据静默丢弃，它们保存在前端附属存储中，以“后端环境 + 真实职位 ID”为键，读取职位时再合并进页面模型。

附属数据只服务本地原型，非后端权威数据，不跨浏览器或设备同步。README 必须说明这一限制；后端增加正式字段后应删除对应附属存储和合并逻辑。

职位卡片的“在谈数”目前来自演示候选数据。真实职位 ID 与演示数据无法对应时显示现有模型的安全默认值，不伪造后端统计。

### 11.3 简历

BFF 支持个人资料、摘要、技能、经历、教育和证书。上述字段由服务端权威保存。

当前原型中的作品集链接、上传文件名等没有稳定的对应 DTO，继续沿用现有前端本地缓存，不发送到后端。它们与职位附属数据一样是原型附属信息，不应被描述为已上传或已同步。

保存简历时，Context 对比最后一次服务端快照，按 BFF 能力依次更新相关分区。任一步骤失败后重新读取服务端权威简历，避免把半完成状态伪装为整体保存成功；UI 只使用现有轻提示。

## 12. 错误与一致性处理

错误处理不新增视觉组件，统一转换为现有轻提示可消费的信息：

| 情况 | 行为 |
| --- | --- |
| `401 invalid_session` | 清理内存中的后端会话数据，回到现有登录流程 |
| `403` Origin 或角色错误 | 保留当前确认数据，提示配置或角色不允许 |
| `409` 版本冲突 | 重新读取对应权威资源，不覆盖服务端新版本 |
| `409 idempotency_in_progress` | 遵循 `Retry-After`，使用同一个 Idempotency-Key 继续确认原操作 |
| `422` 校验错误 | 尽可能映射到当前表单语义；无法定位时显示通用轻提示 |
| `503 operation_outcome_unknown` | 遵循 `Retry-After`，使用同一个 Idempotency-Key 做受控重试；随后重新读取资源确认结果，绝不换新 key 重复创建 |
| 网络错误 | 保留最后确认数据；只允许对幂等读取做有限重试 |

任何错误都不得触发已接入业务域的 Mock 回退。写请求的重试必须遵循 BFF 契约并复用原 Idempotency-Key；结果仍不确定时重新读取可寻址资源，不用新 key 重复创建资源。

## 13. 测试与验收

### 13.1 运行配置测试

- 两个变量都缺失时得到 `mock + stg`。
- `backend + local` 和 `backend + stg` 选择正确代理目标。
- 未知枚举值立即失败。
- `VITE_BACKEND_ENV` 不改变 Mock 模式行为。

### 13.2 数据源和映射测试

- Mock 数据源维持当前返回模型和关键交互。
- HTTP 数据源始终带 `credentials: 'include'`。
- 写请求正确处理 ETag/If-Match 和 Idempotency-Key。
- DTO 与页面模型双向映射覆盖 catalog、简历、意向和职位。
- 未支持字段正确进入附属存储，且不会被提交成错误后端字段。
- Backend 请求失败时不调用 Mock 数据源。

### 13.3 Context 行为测试

- Backend 会话恢复后按角色加载正确数据。
- 登录和角色切换在服务端成功前不导航。
- 保存成功后使用服务端响应更新状态。
- 冲突、部分简历保存失败和不确定结果会重新读取权威数据。
- 重复点击不会产生重复写请求。

### 13.4 零视觉改动验收

- 默认 Mock 环境的关键页面 DOM、文本和交互与改造前一致。
- 登录页仍为 4 个验证码输入格。
- 不新增或修改 CSS、视觉组件、加载组件和错误组件。
- Backend 模式不出现新的 Loading、环境标签或来源徽标。
- 只复用已有轻提示和既有路由加载表现。

### 13.5 人工联调

- Local：以 `RECRUITMENT_BFF_ENV=test` 启动 `127.0.0.1:8097` 的 BFF，并将 Public Origin 配置为 `http://localhost:5173`。
- STG：通过 Vite 代理验证 Cookie、Origin 改写和真实登录。
- 分别验证候选人和招聘方的登录、角色恢复、简历/意向或职位读写。
- 验证接口断开、401、409 和 503 时没有 Mock 回退或重复写入。

## 14. 最小改动边界与后续工作

本次只为已经存在的页面接入可用后端能力，不预先建设通用 SDK、缓存框架、数据同步引擎或全站错误系统。

以下工作延后，待后端具备明确契约后再做：

- 市场职位发现列表。
- 候选人和招聘方完整匹配列表及其详情链路。
- 消息、规则、AI 简报、会话和历史的持久化。
- 将职位和简历的前端附属字段迁移为正式后端字段。
- 非 Vite 开发环境下的真实后端部署与跨域方案。

后续接口可用时，应扩展统一数据源和映射层，而不是在页面中增加直接请求。任何需要改变当前视觉或交互的后续工作都应单独评审，不包含在本次接入中。

## 15. 完成标准

设计对应的实现只有同时满足以下条件才算完成：

1. 两个环境变量按约定工作，默认值为 Mock 和 STG。
2. 默认 Mock 模式的 PM 体验没有变化。
3. Backend 模式可通过 Vite 代理使用 Local 或 STG BFF。
4. 已接入业务域使用真实数据，失败时绝不回退 Mock。
5. 未支持业务域继续使用清晰隔离的演示数据。
6. 登录页保持 4 格，且文档明确记录后端 4 位 OTP 前提。
7. 没有新增或改动任何视觉设计和 Loading 效果。
8. 自动化测试和 Local/STG 人工联调覆盖关键读取、写入与错误路径。
