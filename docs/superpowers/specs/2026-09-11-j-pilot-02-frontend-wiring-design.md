## 2. 范围与最小方案

页面范围是两条现有候选路线及其内部选择／编辑层：完善资料（学生分流）、基本信息、求职状态、学历、学校、专业、就读时间、工作／实习经历及其教育／项目／证书等编辑层、引导问答的薪资段与偏好段、披露说明、头像；同时覆盖完善资料打开的职位／城市子页。保留 `src/流程/onboarding配置.ts` 的学生／社招题序、原路由和现有按钮推进方式。

采用现有页面控制与数据源，加必要的局部共用展示和本轮草稿：

- 已经使用同一 JSX／CSS 的页面直接复用，不为结构整齐强行重拆所有页面。
- 职位、城市、目录候选行等确有两份展示的部分提取为一份；两种模式的控制方准备显示值、选择状态、请求状态和回调。
- 继续使用现有简历、意向、隐私、附件、头像和目录 API。补齐本轮输入及有限未结算命令的恢复，不另造总提交接口。

比较方案：仅调 CSS 不能消除后续结构漂移，也不满足用户要求；整体重写向导和状态框架会扩大已真实接线部分的风险。按实际分叉收敛展示、沿现有操作修复保存与恢复，是满足本次要求的最小方案。

非目标与延期边界：

- 不新增页面向导框架、全站展示模型、组件注册表、全局请求框架、离线队列、跨设备草稿平台、服务端进度游标或 `completeOnboarding`。
- 不改招聘方 onboarding、J-PILOT-01 的委托／投递／Case 生命周期；不创建岗位、推进 S0／S1 来完成02。
- 不重设计日常意向编辑、多意向管理、注册后多附件管理、自动选择默认 PDF、解析取消、总事务或回滚。
- 不实现定位、真实扫描进度、作品集抓取／自动披露、Highlights 候选确认／编辑、私有诉求的模型改写／矛盾裁定。
- 后端已有合同为本轮依赖；真实解析根因修复另行立项。只有发现现有接口确实无法满足已确认流程的具体证据，才提出受影响的合同增量，不由 Plan 自行增加后端工作。
- 只有新增明确产品需求或接口已提供相关数据时，才重新考虑上述延期能力；本轮不预建支持它们的抽象或配置。

## 3. 展示与控制边界

### 3.1 共用规则

每个目标页面／区块两模式共享同一展示实现与样式，以规划基线 Mock 的标题位置、分区顺序、留白、控件、滚动容器、底栏和弹层层级为准。展示差异通过输入数据与状态表达，不保留 Backend 专属整页 return 或第二份卡面／列表 JSX。共享展示不得通过整页 ReactNode 槽重新塞回旧页面。

新提取的展示组件不读取数据源模式、应用业务 Context、BFF DTO、fixture 或浏览器持久化，不发请求、拼路由或派发业务动作。纯展开、滚动等 UI 状态可以留在展示组件；会影响刷新恢复的输入、当前问题、目录选择和业务在途状态由控制方持有。页面级控制可按模式选择数据／动作，不要求消灭所有模式判断。

Mock 使用原型数据和模拟控制；Backend 使用本人合法快照、真实目录和真实动作。空值不补演示姓名、城市、职位、生日、教育、公司、分数或解析结果；输入框为空／待填写，展示说明缺失时使用中性文案。两模式接收同样展示输入时应有相同 DOM 与样式表现。

加载、空结果、错误、分页、待核对、禁用等是允许的状态差异，放在共用组件的既有区块内；不能用另一套 Backend 页面承载。必要错误提示和公司消歧沿原型组件风格最小接入，不因视觉对齐删掉真实错误、权限限制或可访问性。

### 3.2 职位与方向

分别保留完善资料子页、向导题的各自 Mock 布局；本次不强制把两个原本不同的入口做成同一张万能页面。每个入口内部 Mock／Backend 必须共用展示。

向导保留分类栏、说明卡、方向细选层、已选条；Backend 的根／子目录、搜索、分页和层级来自真实 job-categories。只把 `selectable` 允许的节点写为意向引用，层级导航依据当前合同的 `has_children`／`parent_id`，不得仅凭名称或固定层数猜叶子。所需 DTO 兼容和查询接线在本轮范围内，不能为了适配旧四字段类型忽略已公开的层级事实。

目录没有 Mock 的行业说明时保留说明位置并显示“暂无说明”；不复用 Mock 行业描述补给不同目录，也不把导航分类当用户选择。Backend 文案使用真实职位分类语义。搜索命中、已选项移除、去重均按稳定 ID；同名项不能互相误删。只有选择顺序中的第一个职位参与首次意向，保留现有多选上限，不批量创建。

### 3.3 城市、学校、专业和行业

城市保留当前定位、热门城市、行政区分组、搜索结果和已选条布局。当前定位按用户批准的缺失态显示且不可假选上海。Backend 用 Location 目录默认推荐顺序为热门区提供有 ID 的条目，分组使用返回的国家／行政区字段；未知行政区在真实国家或中性“其他地区”组显示，不编造省份。按已有分页增量加载并保留加载更多，不为凑完整省份墙预加载全球目录，不把当前页视为全部目录。搜索仍调用真实目录；热门区不宣称实时求职热度排名。

学校／专业／行业候选行共用样式与组件。学校等同名结果保留真实地点等必要辨别信息，放入同一候选组件的说明槽；没有附加信息不编造。输入改变后清除旧引用，只有用户选择真实结果才能形成可提交引用。没有结果、请求失败与加载中分别呈现，不能靠无限“加载中”掩盖失败。

职位／城市子页也被日常意向编辑使用：共用展示的必要消费者适配允许，但其来源参数、原单选／多选规则、返回位置与保存归属必须保持，不把本轮首次意向逻辑带入日常编辑。

### 3.4 公司屏蔽与其他页面

屏蔽公司沿现有卡片、输入、列表和开关视觉承载。Backend 的简历公司名称只能作为搜索提示，不能默认显示为已屏蔽，也不能因社招默认开关或名称匹配自动写入。用户通过真实组织结果明确选择后才提交，正在提交／失败／已确认屏蔽分别显示；“一键”表达不得绕过真实组织选择。Mock 控制可演示，但共享展示不自行实现默认屏蔽逻辑。

资料、经历编辑层、PDF 授权／等待层、披露说明和头像优先复用现有组件。Summary 与作品集仍在既有输入位置；候选 onboarding 与本人简历页不增加 Highlights 标签区。新增“暂无经历”通路或保存提示时使用现有控件和布局，不新建确认页。初始化展示是本轮明确保留的例外。

## 4. 输入、建议与资料保存

### 4.1 必填和可选

完成必须有本人必要资料和至少一条完整教育：学校、学历、专业、入学时间、毕业时间；在读填写预计毕业时间。学生、社招均可暂无工作／实习经历；已填写条目沿现有字段与日期校验。教育的毕业时间完成门槛仅用于本轮，不修改日常简历中其他合法“至今”规则。

PDF、头像、Summary、作品集、技能、证书和额外排除诉求均可空。姓名、求职身份、职位／城市目录、办公方式、求职类型及其条件字段沿已确认产品与现有校验。未明确确认的生日、年份和身份不从滚轮初始位置或 Mock 默认值写入。所有选填内容有“已保存、未保存、结果未知或明确放弃”的准确事实，不默默丢弃后完成。

### 4.2 PDF 分支

用户选文件并同意处理后，按附件库权威状态创建或主动替换；multipart 发送恰一个 file 及操作要求的字段，许可 part 为字面字符串 `true`。上传许可不等于后续投递授权。取消未发送的选择不发请求、不删除旧文件。

本轮无文件可手填；存在本轮已上传／可准确识别的唯一文件时显示它，用户可以明确继续使用并激活本轮建议，或主动替换。对旅程外多个 active 文件，不能按 `items[0]` 随意激活／覆盖；不新增多附件选择器，可继续手填，并保持已有附件不变。

沿现有预填操作管理 file_id／version_id／parse_id 精确来源、主体／角色／会话代际、单次读取和迟到保护。浏览器只观察真实 not_started／pending／processing／succeeded／failed 状态，不以计时器宣布解析成败。成功后读取准确来源建议；GET 失败仅重读该来源，不新建模型任务。显式解析重试仅用现有允许状态和接口。

选择手填使本轮建议不再应用，保留文件，不宣称取消后台 worker。换文件或来源失效后旧结果不可回填；Case 已绑定的旧 PDF 版本不由02修改。

建议只在本人已保存值与本轮手填值均未占用的字段上提供初值；只有用户确认才写在线简历。列表不按下标合并，不伪造目录引用。建议原始正文不进浏览器持久化；用户已编辑／确认到表单的值属于本轮输入，可按第7节恢复。

### 4.3 分区与条目

复用 GET resume 和现有 profile／summary／skills／experience／project／education／certificate 操作；仍按资源分阶段保存，不新增整体事务。每个写口用自身 revision，不能把 aggregate_revision 当 profile 或条目 revision。

尚不完整的教育／经历作为草稿跨屏保留，不发送假完整条目。用户确认的完整条目才落盘；创建回执必须保留准确 entry ID／revision，并将本地草稿身份关联到该回执。教育、经历、项目、证书同样遵守，不能用回读列表差集或数组位置猜新 ID。父经历已成功而项目失败时保留父身份和未保存项目，重试不再新建父经历。

已保存部分不回滚、不伪装成未提交。成功回执后的 GET 失败只影响回读确认，不能丢掉已知创建身份。409 先读取对应资源，保留当前修改并提示冲突；用户重新确认新修改才以新 revision 写入，不盲目覆盖远端变化。已删除条目只因明确删除动作发请求，恢复草稿缺项不能被解释为删除服务器条目。

### 4.4 作品集 URL

通过 profile 的 `portfolio_url` 保存，两个既有输入入口共享同一份本轮值及修改状态，最终刷新能从 GET resume 回显。

- 前端规范化：trim；空输入显式清空为 null；无 scheme 补 `https://`。提交前校验绝对 http／https、非空且含点的 hostname、无空白、最多2048字符，并保持后端最终校验。
- 请求省略表示保留，显式 null 表示清空，字符串表示设置。未修改链接的普通 profile 编辑省略该字段，不能每次带回旧链接覆盖其他写入。
- 链接单独变化也必须触发有效 profile 写入，并遵守 profile 的完整旧字段语义和 profile_revision；不能为了只写链接清空姓名等既有资料。
- 读兼容 string／null；旧 BFF 缺字段按 null 处理。明确维护读写类型的差异，不用新增必返读字段强迫所有旧写携带 null。
- 不保存到 Summary／项目结果，不抓取、不检查远程可达性／所有权、不扩展账户导出、解析预填或招聘披露合同。

## 5. 私有诉求、组织隐私与首次意向

### 5.1 私有文本

保留卡片和自定义输入，在既有下一步动作提交。内置按固定卡片顺序生成：

| 卡片 | 文本 |
| --- | --- |
| 大小周 | 不接受大小周 |
| 纯外包 / 乙方 | 不接受纯外包/乙方 |
| 全现场办公 | 不接受全现场办公 |
| 频繁出差 | 不接受频繁出差 |

选中内置文本按上述顺序排列，自定义文本按输入顺序原样保留，各段用换行连接；仅空内容不生成段，不在原文前加“其他排除”或统一否定，不改写已包含否定、一般偏好或矛盾内容。每次从当前卡片与输入重新形成文本，不在上次结果上追加。长度超出既有接口限制时保留输入并提示，不截断。

新建首次意向的 `alternate_weekend_work`、`outsourcing_only`、`onsite_only`、`frequent_travel` 均为 `unspecified`，诉求只进 `private_preferences`。不清洗历史意向，不扩大日常意向编辑映射的规则。卡片和自定义全空表示未额外提出诉求，允许继续，不解释为接受全部条件。原“代理直接挡掉、不来问人”等与已确认语义冲突的本轮文案／注释需要校准，初始化例外不扩大到这些文字。

### 5.2 公司屏蔽

复用组织搜索、现有隐私写入和 GET privacy；以用户明确选择的 organization_id 写 `source=manual`，成功按回执与权威回读展示。显示名不是身份；同名结果按接口实际提供的辨别信息展示，不自动猜对应组织。没有结果／无法辨别时不报成功。

已保存屏蔽从隐私快照回显；删除已保存项沿现有解除屏蔽规则，不取消非 manual 来源所需风险确认。失败保留选择并允许合法重试，或用户明确放弃未成功的可选动作继续；未知结果先核实，不能仅靠本地开关宣布完成。组织屏蔽不拼进 private_preferences，也不增加对其他组织的隐式修改。

### 5.3 首次意向身份与恢复

保留 Summary 成功后再保存首次意向的顺序；Summary 为空合法，其成功独立记录。正常新建按第一个职位及用户确认的类型、城市、办公、薪资和条件字段构造完整 IntentionWrite，薪资周期按既有合同派生，不新增 wire 字段。

发送前保留本轮精确创建请求体、原幂等键和主体归属；201 返回的 OwnerIntention／intention_id 即为已知命令结果，先保存该关联，再 GET 指定意向核实内容。列表水合可随后进行，但不能因列表失败丢失201回执，不能以列表非空代替本轮成功。复用 HTTP 客户端已有显式幂等键能力，不新增通用命令查询 API。

返回修改遵守现有导航，不新增锁步：有本轮明确 ID 且用户再次确认变化，更新该同一资源；未改变则不重复写；结果未知时先核实原命令，再接受新的提交，不能给未知 create 换 key，不能把修改后 body 塞进旧 key。复用历史资源时不清除其旧排除规则，不把它伪称为本轮新建。

退出重登后无原键／回执时，读取本人已保存资源；可以准确确认的既有意向可复用，但不称它必然是旧命令的回执。列表空不证明未受理；多个无法唯一归属的候选不随机选择／删除／创建，保持待核对。新注册且没有历史未知请求的空账号正常创建，不让该异常规则阻止所有新用户。

## 6. 头像、完成与回访

头像沿现有 JPG／PNG、大小限制及上传入口，可跳过；失败不显示已更新。头像未知命令重放必须保留原图片、原 key 和原 If-Match，因为 revision 也是幂等身份；不能先 GET 后换新 revision 冒充原命令。

完成按钮执行本人资源核对：资料必填满足、第4节完整教育至少一条、首次意向有明确身份且与已确认输入一致；本轮已填选项有保存或明确放弃事实，没有关键未结算写入。GET 失败／未水合不是空资源；完成提示、清理和导航不能先于核对成功。推荐读取不是该判定的输入。

核对成功后清理本轮草稿、命令恢复信息与预填轮，沿现有初始化页进入首页。不改固定862和动画，不以其计时结果触发／证明任何后端保存、扫描、匹配或委托。头像可选、说明是 UI，不新增服务端签署或当次投递授权。

回访按事实分流：

- 同标签有未完成草稿：水合本人资源后恢复中断页面、向导段和题目，先核对在途未知命令。即使必需资源已保存，也不能跳过本轮尚未处理的修改或可选步骤。
- 无本轮草稿，资源完整且能准确确认已完成者：进入既有首页，不重复创建，不要求永久客户端 complete 标记。
- 无草稿且确实未完成者：从现有入口重走并复用已保存资源，不自动造新教育或意向。
- 直接打开后续 onboarding URL：按同一完成／恢复规则处理，缺必要前置定位到现有相应步骤；不借直达跳过保存。
- 登录／角色／水合失败：留在对应真实状态与现有恢复入口；不把候选直接无条件送首页，也不影响招聘端独立登录恢复。

## 7. 同标签草稿与有限请求恢复

当前 sessionStorage 只覆盖部分偏好和预填坐标，不能满足已批准的“全部本轮输入与中断步骤”承诺。本轮扩展已有草稿机制；必要的版本化记录仅服务候选 onboarding，不建立通用离线机制。

保存范围：当前合法路由及向导段／题目、打开的业务编辑层及其未确认输入、基本资料／教育／经历／项目／技能／证书／Summary／作品集本轮输入、目录精确引用和选择顺序、卡片／自定义文本／公司待选状态、已知资源ID及所需revision、当前PDF来源／预填模式、本轮未结算请求的必要原始参数与回执。用户明确取消编辑恢复既有值，普通前后导航或刷新保留输入；滚动位置和无业务输入的瞬时动画不要求精确恢复。

服务端快照与本轮草稿分开：草稿不是服务器已保存数据，恢复不直接派发为权威简历；水合不得擦掉未提交字段；远端 revision 改变时显示冲突并保留输入，而非把旧草稿自动写回。预填建议原文不缓存，但已进入用户表单的输入按草稿恢复。

记录按模式、后端环境、subject 和 candidate 角色隔离，并沿现有会话代际阻止旧请求／旧存储写回新主体。退出、切换账号、切换到不允许的角色或完成时按归属清理，不把A状态写到B键下。新标签／换设备无恢复承诺；即使浏览器复制了会话存储，也必须重新核实主体、资源和原命令，不能复制出自动提交。

不得存 token、Cookie、凭据、PDF／头像字节、原始解析全文、跨角色原始快照。文件刷新后字节可能丢失：保留必要坐标并先权威核实，必要时提示重新选择原文件；没有字节不能宣称自动重放 multipart。JSON 未知命令只在具备完整原请求身份时由用户明确动作按该操作合同重放；普通挂载不自动执行整条写入流程。

存储不可用／空间不足／记录损坏时保留当前内存输入并明确提示无法保证刷新恢复；只拒绝当前归属的无效记录，不回退 Mock，不声明已持久化。路径／题目恢复只接受当前候选流程白名单，不拿存储值任意导航。

有限命令记录覆盖本轮真实可发生的创建与未知结果，包括首次意向和简历条目；单例 CAS、组织屏蔽、附件、头像按各自合同核实。已有 HTTP 单次受控重试继续保留，但跨刷新恢复不增加全局自动 retry。原命令丢失且无法确认时如实待核对，不扩展人工处理平台。

## 8. Highlights 与后端兼容依赖

候选端不调用 Highlights PUT 暗中确认，不展示／编辑标签，不从 Summary 生成标签。后端自动 PDF 标签通过既有招聘推荐／Case 摘要消费；02只在已获授权的独立招聘会话、已有合法场景里检查可见性与来源，不为验证创建岗位或推进01。

推荐标签依据唯一 active 文件的当前可用解析；Case 按既有冻结 file／version／parse 来源。无合法标签可以为空，基础设施错误不能假报合法空；隐私与有效投递条件继续生效。候选作品集不因此自动进入招聘材料。

FE 必须兼容 portfolio_url 的新增与旧响应缺失，及本轮真实目录层级字段。后端依赖版本必须包含上述实现；仅有合同文件不算可用运行环境。后端 BFF／Service 严格解码与存储 JSONB 回滚兼容遵守合同发布边界：旧 BFF 不能直接配新增字段 Service，新 Service 写入后旧 Service 回滚亦需能容忍该键。本文不执行部署、不设计新版本协商；发布前按实际版本核实，不能由前端忽略字段掩盖后端不兼容。
