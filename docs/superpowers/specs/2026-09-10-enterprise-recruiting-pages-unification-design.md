# 企业公开页与招聘名片双栈展示统一设计

## 1. 状态与目标

- 日期：2026-09-10。
- 设计安排已获用户确认：企业公开页与招聘名片纳入同一份 Spec、同一份 Plan；沿用 Mock 布局，共用展示，缺字段显示明显占位。企业身份移到后部；没有岗位列表能力时保留真实数量，不提供虚假入口。
- 本文件状态：待用户审阅批准。此前聊天中的设计确认不等于本文件已获批准；批准前不编写 Plan。
- 规划源码基线：`b93436e9`，工作分支 `plan/enterprise-recruiting-pages`。其他工作区的并行实现不是本设计依赖。

当前两个页面各有 Mock/Backend 独立展示，数据来源变化同时改变信息结构。目标是让每个页面各自只剩一套实际使用的展示 JSX/CSS，数据、权限、请求与保存仍由外层连接逻辑提供。

成功标准：相同展示数据、状态与能力使用相同布局；合法缺字段保留位置并明确说明缺什么；真实事实和操作不被 Mock 数据或模拟成功替代。附录字段表供后端补数规划，占位不写回接口、缓存或业务状态。

## 2. 方案与边界

选择两个具体的页面展示组件，分别接收页面所需数据、业务状态与回调。展示组件不读取数据源模式、不查询全局业务状态、不读取模拟数据表、不发请求、不根据含混 ID 拼接路由。Tab 和弹层开关等纯展示状态可留在展示组件内。

只统一 CSS 或零散小区块无法消除整页 JSX 分叉；创建通用页面引擎又需要配置表和模式开关。本方案只提取当前确实重复的两套页面，不增加通用表单框架、全站占位系统或新基础设施。公共 props 的精确签名在批准后的 Plan 冻结。

主范围是 `src/屏幕/企业详情.tsx`、`src/屏幕/招聘名片.tsx` 及其 CSS、测试和新提取的页面展示/映射文件。迁移完成删除旧重复卡面、表单 JSX 与确认无人消费的样式；Backend/Mock 连接函数可保留，不以删除函数名作为完成标准。

非目标：公司档案编辑与分区编辑、独立职位详情、公司区块、在谈详情、列表卡片、认证流程、发岗流程改版；不改 BFF schema、接口、状态系统和后端能力，不恢复已删除的代理核对区及“谁在替这家谈”。不修复审计中其他页面的问题。

只有后端公开契约增加了真实字段、岗位列表或导航能力，才重新考虑相应占位和操作；只有出现更多实际复用消费者才考虑上移通用抽象。

## 3. 统一的缺失与来源规则

1. 区分合法空值、接口未提供、真实零值与整页读取失败。成功取得合法资料后才使用字段占位；不存在、停用、请求失败或契约错误沿用原有处理，不能生成一张看似成功的全占位企业页。
2. 缺失文本显示字段含义明确的文案，例如“企业文化未知”。不推断“未披露”“无福利”“无任职经历”；接口明确表达的已知值、零值及否定值正常显示。
3. 占位采用既有次要文字色和中性背景，保持可读，不使用认证、成功或警告色。缺图保留固定尺寸的空白图位及可访问说明，不用姓名首字、企业字标或外部示例图片冒充照片/LOGO。企业头图保持 50×50、圆角 16；招聘头像保持 52×52 圆形及上传角标。相册空态保留一格与实际照片相同尺寸的占位。
4. 文本缺失保留区块和标签，不要求长短不同的真实内容具有相同高度。未知数量不按 0 渲染，未知统计不绘制有数值含义的图形。
5. 核验文案必须绑定对应事实来源：企业身份核验不能延伸为文化、福利或工商所有字段均已核验。Mock 可保留已有 fixture 明确提供的核验展示，Backend 不从静态档或私有组织资料补齐。页脚和弹层说明也服从该规则。
6. 占位只用于展示或输入提示。可编辑 input 的 value/defaultValue 仍为真实字段或空串，“未知”不参与校验、保存或上传。不得把全局文案替换当作缺失判断；合法枚举的未知语义由页面映射明确处理。

## 4. 企业公开页

### 4.1 页面结构

统一使用以下顺序，布局与已有 Mock 的字号、间距、卡片及弹层样式一致，除本设计列出的变化外不重新设计外观：

1. 返回栏、公司头部：名称、固定尺寸 LOGO/空白图位、融资/规模/行业信息行。
2. 公司自述：保留“公司简介／企业文化／发展历程”三 Tab、三行截断和“读全文”。主营业务保留在同一卡片下方，增加明确的主营业务标签，缺失时显示占位。
3. 公司相册：有图横向滚动，无图保留一格空白图位并标注“公司相册未知”。
4. 作息与条款：摘要和可打开的全文层。
5. 办公地：地址、地址补充和导航能力位置。
6. 在职者反馈：有真实/fixture 数据才画统计条，未知时只有“在职者反馈未知”，不画空百分比或虚构计数；不显示无依据的匿名评价来源说明。
7. 工商与企业身份：复用原 Mock 工商区的位置及行样式，保留原工商条目，并容纳 Backend 的法定名称、展示名称、核验时间、已核验在招岗位数。
8. 来源页脚、固定底部岗位数量/操作区。

不为两种模式各写一份上述布局。已核验状态、可点击性、可编辑性和数据缺失属于业务状态差异，可以在共用结构内条件渲染。

### 4.2 全文与条款

公司自述全文层固定展示公司简介、企业文化、发展历程、产品介绍、团队介绍五部分。产品/团队沿用 Mock 的全文层位置，Backend 现有内容在此完整可达，不丢字段；页面不再保留 Backend 独有的产品/团队独立卡。每个部分缺失都显示对应占位，团队成员已知姓名、职务、简介分别保留，缺子字段分别说明。

简介按现有段落展示；历程有年份/事件时用现有时间线，无数据时显示文字占位而不造年份。切换 Tab 不改变事实来源，“读全文”即使选中项未知也可打开全部内容。

作息与条款层保留作息、代理已核对、公司自述三处信息位置。Backend 福利标签是企业自述，不赋予“已核”标记；接口没有代理核对结果时显示“代理核对信息未知”，不能写“0 条已核”来宣称已完成检查。福利说明缺失显示“条款说明未知”，不套用静态福利池说明。已知福利列表可显示“已提供 N 条条款”；空列表无明确否定语义时显示“福利信息未知”。无作息信息显示“作息信息未知”。不向 Backend 展示要求用户操作尚未接入代理能力的指引。

### 4.3 身份和可执行入口

工商与企业身份区保留 Backend 的四项真实信息，不把 `legalName` 当成一份完整工商注册档案。Backend 缺完整工商资料时在“工商资料”位置显示“工商资料未知”，保留独立的企业身份核验说明。Mock 原有工商条目保留；没有法定名称、核验时间等明确数据时不按公司展示名或其他条目猜测，显示对应未知。来源不同的行数可以不同，行容器与排版规则共用。

岗位数量与岗位列表能力分开表达。Backend 当前 `activeVerifiedJobCount` 是真实已核验在招数，0 也显示；底部显示“N 个已核验在招岗位”及“岗位列表暂不可用”，无可触发的虚假查看操作。Mock 保留原有岗位层、在谈/市场岗位导航和已有原型说明，其路由回调由外层准备。不能把数量当作列表权限，不能按公司名读 Mock 岗位补足 Backend 列表。

办公地的导航位置按能力处理：Mock 保留原有原型提示，Backend 没有导航回调时显示“导航暂不可用”且不可点击，不新增地图接入。统一后的只读能力提示不能伪装成可用按钮。

### 4.4 数据与错误边界

Backend 保留以 route param 原样作为 opaque organization ID 调用 `读取公开企业`、读取对应缓存并通过 `从BFF公开企业` 投影的链路；不拿 slug 兜底，不新增额外公开/私有请求。Mock 保留静态公司档、当前公司自述覆盖和本地岗位组合的现有归属。

本次不重构既有加载/不可用状态模型：缓存未到、404、停用、普通错误仍走当前不可用分支，同一 ID 后续成功可以恢复。不得把这些状态伪装成合法字段缺失，不要求借展示提取新增完整错误基础设施。

## 5. 招聘名片

### 5.1 共用表单与预览

共用返回栏、标题、52px 头像上传预览、姓名和“职务 · 公司”预览、姓名/职务/公司区域、公司主页资料入口与主按钮。保留既有无框就地输入样式。

姓名区域根据业务属性显示可编辑公开名或实名只读值；认证标记仅在明确个人认证状态允许时显示。公司区域根据当前任职关系、可选/不可选关系和公司声明状态呈现，不能用“公司未知”替换选择关系这一必要流程。关系列表与声明输入可以是同一区域中的不同业务状态，不按数据源换整份页面。

预览缺值分别显示“姓名未知”“职务未知”“企业信息未知”；输入提示分别为“请填写姓名”“请填写职务”“请填写公司名称”，不改变原有必填校验范围。无头像显示中性空白图位，保留上传入口。真实图片和暂存预览的优先级不变。

### 5.2 保留已有操作语义

- Mock：编辑失焦/非输入法合成态回车收笔后落全局；空白收笔不覆盖旧值；职务现有“技术 VP”默认行为保留，不借本次改变原型预填。选图仍压缩为 data URL 并落全局。底部仍为“保存 · 去发岗位”，按原注册流标记跳转。往返公司资料页后已收笔字段不丢失。
- Backend：公开名/职务/公司输入继续由外层受控管理并按原权威数据水合同步；实名只读不导致 public_name 被擅自替换成实名姓名；无当前关系时保留原公司声明校验，关系不自动按第一项猜选。
- Backend 保存顺序继续是公司声明（适用时）→ 档案 PATCH → 有暂存头像时头像替换。头像续用 PATCH 响应 revision，不提前宣告成功，不添加额外自动提交。
- 保存锁与“保存中…”禁用保留；注册流成功后“保存并继续”去发岗，普通编辑保存后停留并提示成功。失败保留输入、文件及预览，保留现有安全错误文案。
- PNG/JPEG 与 10 MiB 校验、换图/unmount 的 object URL 回收、账号变化时清理未保存头像均保留；Backend 不走 Mock 头像写入动作。

共用输入行须支持外层提供的原有受控或收笔语义，不能为统一代码强制两栈采用同一持久化时机。布局组件不拥有保存成功状态或上传事务。

## 7. 预期视觉变化与验收

完整字段且能力相同的内容沿用 Mock 布局、字号、间距、输入和弹层交互。明确允许的 Mock 变化是：缺图字标改为空白图位；原先隐藏的缺字段区块出现占位；工商区改名并容纳身份行；主营业务加标签。不得把这些已批准差异之外的换行、按钮位置或尺寸回归静默接受。数据量与权限不同导致的内容行数变化不要求像素相同。

实施阶段至少验证：

- 两种模式实际消费同一企业页面和同一名片展示；展示文件无运行时模拟数据导入、数据源模式判断或请求逻辑；原重复 JSX 与无人使用样式清理。
- 企业完整资料、合法缺字段、真实 0、长文本；三 Tab、全文五部分、条款层、相册；身份核验范围和未知反馈无虚构图形；Backend 无岗位/导航能力不可执行，Mock 原岗位跳转保留。
- 企业 opaque ID、不调用静态档、404/停用/普通失败与后续恢复沿用现有回归覆盖。旧测试“Backend 不出现文化/历程/反馈”改为出现占位，不以删除测试替代新行为断言。产品/团队断言在打开全文后执行。
- 名片保留 `src/屏幕/招聘名片.test.tsx` 对实名只读、任职关系、公司声明、单飞保存、PATCH revision、头像格式/大小、预览回收、失败重试、注册流/普通编辑及 Mock 收笔/选图的覆盖。补验“未知”不进入提交数据，输入法回车不误提交。
- 320px 与 390px 浏览器检查两页主屏和弹层、长企业名/成员信息、未知及只读状态，保证无横向溢出、内容遮挡、失效焦点和按钮嵌套。
- 复用现有 `npm test`、typecheck、构建、视觉回归和数据源 E2E 入口；精确选择与命令由 Plan 根据消费者确定。已有 `recruiter-card` Mock 视觉场景需要检查，企业公开页按现有框架补适用场景，不新建测试基础设施。
- 真实本地后端验收按 `docs/dogfood/真实后端行为验收.md` 选择适用加载/名片行为及企业公开页操作，验证保存后重新进入页面读取真实结果。HTTP fixture 和 Mock 截图不冒称真实接线通过；缺环境记录未完成责任，不隐去。

当前规划阶段仅做源码/文档核对，不表示产品测试、浏览器或真实后端验收已经通过。
