# 候选人引导真实后端持久化修复设计

**日期：** 2026-09-01

**状态：** 已完成方案讨论，待书面规格确认

**适用模式：** `VITE_DATA_SOURCE=backend`

## 目标

修复候选人引导在真实后端模式下无法完整落库的问题，使一次正常的可见 UI 流程能够持久化一条工作经历、一项技能、一张证书和一个 active intention；同时保证引导答案可在同一浏览器标签页刷新后恢复、个人信息页展示权威手机号，并避免开发标注工具遮挡业务按钮。

提交成功后，简历和 active intention 仍以 `/me/resume` 与 `/me/intentions` 的响应为准。本地状态只承担未提交编辑和受限的引导草稿恢复，不替代服务端数据。

## 已确认的产品与契约决策

1. 证书请求继续包含 `year` 字段，BFF 写入类型为 `number | null`。
2. 用户只填写证书名称时发送 `year: null`，不增加年份输入，不推断当前年份，也不发送 `0` 或 `NaN`。
3. BFF 正在调整并会接受 `null`；前端和严格 BFF fixture 可先按该契约实现，真实后端验收需等待对应 BFF 版本可用。
4. 刷新恢复只覆盖引导预填字段，不持久化简历正文。
5. Backend 模式暂时保留邮箱和微信行，但显示只读的“未接入”，不进行本地假保存；后续等正式接口接入。
6. 标注工具由显式构建变量控制，默认关闭，只有专用评审构建开启。

## 总体架构

修复沿用现有数据源、状态 reducer、页面和 BFF projection 边界，不引入通用表单框架或新的持久化子系统。

```text
页面未提交编辑
      │
      ├── 引导预填 allowlist ──> scoped sessionStorage
      │
      └── 保存简历
             │
             ├── 完整本地预检（零请求）
             │
             ├── 串行执行 mutation plan
             │
             └── GET /me/resume 权威回读

/me 身份 ──> environment + subject_id + candidate role
                         │
                         └── 控制草稿恢复、写入和清理
```

关键边界如下：

- 页面领域模型负责表达用户输入。
- 后端映射负责把页面模型验证并转换为 BFF 请求体。
- 简历数据源负责在首个请求前完成整个 mutation plan 的预检，并在执行后进行权威回读。
- 草稿 codec 只接受明确列入 allowlist 的引导字段。
- 会话生命周期负责在身份失效或变化时清理内存和当前账号草稿。

## 证书契约

页面领域模型继续使用现有的 `简历证书.年份: string`：

- `''` 表示用户没有填写年份。
- 数字字符串表示明确年份。
- 该表示保持现有 UI、Mock 数据和展示逻辑稳定。

BFF 请求类型改为：

```ts
interface BFF证书写入 {
  name: string;
  year: number | null;
}
```

映射规则固定为：

| 页面值 | BFF 请求值 | 结果 |
| --- | --- | --- |
| `''` | `null` | 合法 |
| `'2024'` | `2024` | 合法 |
| 非空非数字 | 无请求 | 客户端校验失败 |
| 非有限数或非整数 | 无请求 | 客户端校验失败 |

证书名称-only 是一个合法的完整条目。前端不得为了满足旧契约而恢复年份输入或填充伪造值。

## 简历保存：预检与执行

### 预检阶段

`保存简历` 在发出首个请求前完成所有同步请求体构造和字段验证，产生一个有序 mutation plan。预检包括个人资料、摘要、技能、工作经历、经历下项目、教育和证书。

新建经历的项目请求需要服务端生成的 experience ID。预检阶段仍会先构造并验证不含该 ID 的项目请求模板；执行阶段只把新返回的 ID 绑定到已经验证的模板，不能延迟字段验证。

现有引导流程允许暂存结构尚未完整的经历或教育。该行为保留：

- 缺少公司、行业或起始时间的暂存经历可以跳过。
- 缺少学校、专业或起始时间的暂存教育可以跳过。
- 已达到完整条目结构但字段非法时，整个保存失败且 mutation 请求数必须为零。
- 目录型写入缺少所选 `{ id, display_name }` 时属于客户端校验失败，不能通过文本推断 ID。

### 执行阶段

预检成功后按现有依赖顺序串行执行：

1. profile
2. summary
3. skills
4. experiences 及其 projects
5. educations
6. certificates

成功执行全部 mutation 后，最后一个请求必须是 `GET /api/v1/me/resume`。页面状态使用该响应水合，然后才允许提示成功和跳转。

如果 mutation 已开始后发生服务端错误，继续执行现有冲突恢复策略：重新 GET 权威简历并把可用快照带回上层。恢复 GET 不得把失败包装成成功；原始保存失败仍向页面报告。

## 错误语义和保存交互

增加独立的客户端校验错误类型，例如 `客户端校验错误`，包含稳定的错误码、字段和可显示原因。它不继承或伪装为 `BFF错误(status=0, code=network_error)`。

错误文案投影按以下优先级处理：

1. 客户端校验错误：显示具体字段原因。
2. BFF validation/field error：显示服务端字段原因。
3. 传输失败或真正的 `network_error`：显示网络错误文案。
4. 其他服务端错误：沿用现有状态码和错误码投影。

保存页面采用 single-flight 状态：

- 点击后立即进入保存中并禁用重复点击。
- 保存中显示明确状态。
- 失败后恢复按钮并显示真实错误。
- 只有 mutation 全部成功且权威 GET 已水合后才显示成功反馈并导航。

## 引导 reducer 合并语义

`启程引导` 不再整体替换 `引导预填`，而是在旧值上更新本次动作拥有的字段：城市、职位、筛选偏好、城市引用和职位引用。

已有薪资和到岗字段必须保留。引用字段在动作未提供时按现有启程语义写为空数组，防止旧目录选择意外绑定到新文本。

## Backend 引导草稿

### Allowlist

草稿只允许以下结构：

```ts
{
  城市们: string[];
  职位: string[];
  城市引用们?: { id: string; display_name: string }[];
  职位引用们?: { id: string; display_name: string }[];
  筛选偏好?: 求职初筛偏好;
  薪资?: {
    下限: number;
    上限: number;
    单位?: '月薪K' | '元/天';
  };
  到岗?: string;
}
```

禁止写入简历内容、认证 cookie、PDF 原始字节、PDF 解析文本、未脱敏联系方式、凭证对象、模型输出以及未知字段。

### 存储范围

使用专用 sessionStorage 键：

```text
账号存储键('候选引导草稿v1', {
  数据源: 'backend',
  环境,
  subject_id
})
```

草稿只在同一标签页会话内跨刷新恢复。Mock 的 localStorage 不参与该流程，相关测试必须验证其内容字节级不变。

### 严格解码

- 数组必须真的是目标类型数组。
- 目录引用必须同时包含非空 `id` 和 `display_name`。
- 薪资上下限必须为有限数字。
- 薪资单位只能为 `月薪K` 或 `元/天`。
- 可选字段可以缺失，但不能以错误类型出现。
- 任一已存在字段非法时拒绝整个快照并删除损坏记录，避免每次挂载重复失败。

### 恢复和写屏障

只有 `/me` 已提供当前 `subject_id`，且当前角色为 candidate 时才能恢复。

持久化层记录已经完成恢复的完整范围键。在该键与当前身份范围一致前禁止写入，从而避免首次渲染的空 `引导预填` 覆盖已有草稿。每次写入前重新比较范围；旧 effect 或迟到异步操作不能把账号 A 的数据写入账号 B。

### 清理生命周期

以下事件同时清除内存草稿和事件发生前的活动 sessionStorage 键：

- 主动 logout
- 401 导致的会话失效
- candidate 转为 recruiter
- `subject_id` 发生变化

清理必须在丢失旧 subject 引用前解析目标键。账号 A 的草稿既不能恢复到账号 B，也不能在身份切换后残留等待 A 再登录。

## 学校和专业目录选择

Backend 模式把“输入文本”和“选中目录引用”视为两个不同状态。

继续按钮条件为：

```ts
const 不可继续 = 词 === '' || (是后端 && 目录引用 === undefined);
```

行为约束：

- 输入非空文本但没有选中结果时按钮禁用。
- 选择结果后按钮启用。
- 选中后再次编辑文本，立即清除引用并禁用按钮。
- submit guard 保留相同校验，不能只依赖 disabled。
- 不自动选择第一项，不允许后端模式提交自由文本记录。
- 写入始终使用所选结果原始的 `{ id, display_name }`。

目录搜索明确展示请求中、空结果和错误三种状态。空结果文案为“没有匹配结果，试试缩短关键词”。搜索实现需要避免旧关键词的迟到响应覆盖当前结果。

## 权威联系方式

Backend 模式挂载个人信息页时调用现有 `加载P8凭证()`，复用设置页和账号安全页的凭证 projection。

手机号显示规则：

- 请求成功且存在唯一 `phone_otp`：逐字显示服务端 `display`。
- 请求成功但没有手机凭证：显示“未绑定”。
- 加载中或加载失败：显示 `—`。

手机号掩码不可编辑，也不能进入明文输入框。修改入口导航到账号安全页。

邮箱和微信行暂时保留，但 Backend 模式固定为只读“未接入”；它们不读取 Mock 联系方式、不 dispatch 本地保存，也不调用猜测的 API。Mock 模式保持现有行为。姓名等已经有正式简历写入接口的字段不受限制。

## 标注工具隔离

标注工具由以下显式构建变量控制：

```text
VITE_ANNOTATION_ENABLED=true
```

默认值为关闭。正式业务构建不设置该变量，因此入口层不渲染标注组件；专用评审构建显式开启。

开启时，入口层把设备框和标注工具放入独立评审布局：

- 宽视口使用并列布局，工具位于设备内容外侧。
- 窄视口使用两行布局，工具成为底部独立行，设备只占剩余可用高度。
- 不通过提高 z-index 让覆盖层压过业务页面。

如果设备框当前固定为 `100dvh`，实现可以把评审布局下的设备高度改为继承可用空间。除 `标注层.tsx` 和 `main.tsx` 外，这可能需要调整现有设备框样式文件；改动仅限于支持明确的高度所有权。

## E2E BFF Fixture

完整闭环使用测试级独立的可变 fixture，不改写或共享现有静态 fixture 状态。

fixture 初始条件：

- resume 各分区为空。
- intentions 为空。
- credentials 包含用于个人信息页断言的权威 masked `phone_otp.display`。

每个 mutation 必须：

1. 严格校验请求方法、路径和 body 结构。
2. 拒绝未知字段和不符合 nullable-year 契约的请求。
3. 记录 mutation。
4. 更新 fixture 的权威内存快照和 revision。
5. 让后续 GET 返回更新后的快照。

## 完整流程验收

E2E 通过可见 UI 完成以下流程，不直接创建 intention，也不通过修改 URL 绕过失败页面：

1. 从空状态选择城市和职位。
2. 填写 30–40K、个人资料和教育。
3. 添加一条工作经历、一项技能和一个名称-only证书。
4. 保存简历。
5. 完成偏好并创建首次意向。
6. 刷新页面并通过权威 GET 恢复。
7. 执行页面返回、前进，确认薪资仍为 30–40K。

最终 mutation 计数必须为：

| Mutation | 次数 | 关键断言 |
| --- | ---: | --- |
| experience POST | 1 | 权威 GET 返回 1 条经历 |
| skills PATCH | 1 | 权威 GET 返回 1 项技能 |
| certificate POST | 1 | body 包含 `year: null` |
| education POST | 1 | 权威 GET 返回 1 条教育 |
| intention POST | 1 | reload 后仅有 1 个 active intention |

最后一个简历请求必须是 `GET /api/v1/me/resume`。另外增加显式开启标注工具的窄视口测试，使用真实鼠标点击技能“添加”按钮并验证技能出现。

## 测试策略

各修改遵循 TDD：先添加失败回归并确认失败原因，再做最小实现，然后运行聚焦测试。

聚焦覆盖包括：

- 证书 `'' -> null`、数字年份和非法年份映射。
- 页面添加名称-only证书。
- 完整简历预检失败时零 mutation 请求。
- 完整保存的 mutation 路径和最终 GET。
- 客户端校验文案与网络错误文案区分。
- 保存 single-flight 和成功后导航。
- `启程引导` 保留薪资、到岗。
- 草稿恢复、账号隔离、严格解码和所有清理事件。
- Mock localStorage 字节级不变。
- 学校和专业按钮状态、编辑后引用失效、loading/empty/error。
- 权威手机号的成功、无凭证、loading 和 error 状态。
- Backend 邮箱/微信不存在假保存。
- 标注工具窄视口点击。
- 完整 Backend onboarding 闭环和精确 mutation 计数。

最终验证命令：

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm run test:e2e:data-source
```

所有命令必须退出 0。完整 E2E 还必须报告 mutation 计数及 reload 后的权威状态。

## 实施顺序与依赖

1. nullable certificate 请求契约。
2. 完整简历预检、客户端校验错误和保存状态。
3. reducer 合并语义。
4. scoped session draft 与会话清理。
5. 学校和专业引用有效性。
6. 权威手机号及 Backend 联系方式只读策略。
7. 标注工具构建开关和布局隔离。
8. 可变 BFF fixture 与完整闭环 E2E。

前两项有直接依赖；草稿、目录选择、联系方式和标注工具可以在契约确定后独立实现。完整 E2E 最后收口。

## 预期文件边界

- 证书与保存：`src/屏幕/工作经历.tsx`、对应测试、BFF 契约、后端映射、简历数据源、HTTP 客户端及其测试。
- 草稿：候选资料 reducer、资料缓存 codec、资料持久化、后端会话操作及状态测试。
- 目录选择：毕业院校、选专业及其测试。
- 联系方式：个人信息页及新测试，复用现有凭证状态和操作。
- 标注工具：标注层、入口、E2E；必要时仅补充设备框高度布局文件。
- 闭环证明：`e2e/数据源模式.spec.ts`。

## 非目标

- 不实现 PDF 到在线简历的自动填充。
- 不新增专业名称别名或前端目录 ID 推断。
- 不发明邮箱、微信披露或写入 API。
- 不持久化简历正文来掩盖服务端保存失败。
- 不通过直接创建 intention 绕过 onboarding 页面。
- 不在 Backend API 失败时回退到 Mock。
- 不重构为通用 mutation planner 或通用 draft store。

## 外部前提

BFF 必须按已确认契约接受 certificate `year: null`。在该版本可用前，前端单元测试和严格 fixture E2E 可以完成，但真实服务联调不能被报告为通过。
