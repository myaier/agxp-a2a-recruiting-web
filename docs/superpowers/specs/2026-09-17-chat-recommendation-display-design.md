# 聊天与推荐展示修复：纯前端设计

日期：2026-09-17。Revision：2，范围修订待审。用户明确本轮仅修改前端仓库，不修改后端代码、OpenAPI、数据库或部署；此前跨仓库 Spec/Plan/prompt 已撤销为执行依据。Revision 1 的 Claude review 不能视为本修订的审查结果。

## 1. 目标与边界

在现有后端 API 和权限语义内，修复聊天真实资料、头像、在线简历、推荐展示和企业屏蔽开关。仅编辑本前端仓库；Mock 与 Backend 统一布局但不制造后端尚未返回的事实。

所有请求使用现有数据源和状态操作。不增加 counterpart、match_analysis 等 wire 字段，不移除后端仍要求的 hidden 字段，不修改后端 schema。可增加仅前端使用的展示模型；不得把它当作新后端合同。

原始需求保留为目标，但以下能力只能部分交付：完整六维评分判定、解析为空的真实亮点生成、旧 hidden 数据导致的公司/标签遮蔽。必须明确呈现边界，不能通过前端补造数据宣称已修复。

## 2. 双端聊天列表与详情顶部

### 数据来源

- P7 现有会话仍是列表及准入事实源，保留分页/未读/排序/read-through，不把所有投递转换成会话。
- 招聘端通过会话 case_id 读取现有 P5 详情：姓名和头像取已授权 candidate_identity；副标题取同 Case 冻结 jobDetail 的用人企业名称与投递岗位。显示“投递企业 · 投递岗位”；代招不取猎头公司。缺企业只显示岗位。
- 求职端从同 Case jobDetail.publisher_profile 取招聘者姓名/头像/职务；公司复用现有详情链：当前岗位 publisher_organization_ref → 已有公开企业接口。显示“招聘者所属公司 · 招聘者职务”。用人企业和发布企业不可混用。
- 不新增 P7 counterpart。现有 `use真人会话资料` 已有大部分读取链，提取必要的纯映射供列表/详情复用；不新增通用身份服务或持久身份缓存。

### 补读边界

仅补读当前已加载会话页的 available 项；同角色/case 去重，最多 4 个 Case 补读并发。岗位/企业相同坐标复用本轮请求结果及已有状态操作，不按每次 render 发请求。新增分页只补新增项，显式重试重新读取失败项；离页/换账号/换角色使旧请求结果失效。

列表补充身份必须以本次成功的授权读取为依据，不能直接展示上次会话遗留缓存；P7 unavailable 或 P5 失权立即撤下身份。补读失败保持消息行可点击，显示“会话资料暂不可用”，不能拿 candidate alias 充当真名；不自动绕过权限。

列表和详情使用同一映射：第一行姓名/时间，第二行副标题，第三行消息摘要/未读。搜索已加载并映射后的姓名、副标题、摘要，不承诺全库搜索。加载/缺姓名与图片失败都有明确回退。Mock 同步企业/岗位语义，列表头像保持现有尺寸。

权衡：纯前端方案需要额外的现有 API 读取；后端集中投影可减少请求，但不是本轮必要条件，也不得作为执行前置。

## 3. 真人消息头像

- 招聘和求职两端，双方均使用 32×32px 圆形；移除我方原有 26px 和 2px 下移，同步气泡镜像留白。
- 我方：求职账号头像或招聘方档案 avatar_url，复用已有水合/读取及 revision 更新，直接进入会话也应可用。
- 对方：当前授权身份/发布人头像。头像独立于姓名是否为空，有图无名也显示图。
- 双方图片缺失或加载失败时显示各自真实姓名 trim 后首个 Unicode 字符；姓名缺失为“·”。不能从岗位、公司、提示文案或 alias 取首字。
- 换 URL 重新尝试加载；换角色/账号/会话不能串图。Mock 同规则，列表头像不改为 32px。

## 4. 招聘聊天在线简历

复用现有 Case candidate_resume 及独立 candidate_identity；“看简历原件”改为“看在线简历”。不依赖后端新增字段，也不以 PDF 坐标缺失判定结构化资料不可读。

按用户截图统一纸身：姓名、最近职位/年限、手机/邮箱、工作经历、教育经历、个人优势、底部“继续沟通”。工作日期右对齐，职位/描述在公司下方，经历顺序沿用源资料。缺公司不从描述反推。

手机/邮箱固定“—”，不拿登录手机号、PDF 内部解析或 Mock 联系方式填真实页面。null 区域显示暂未提供，[] 显示暂无；加载/错误/重试在消费页面管理。失权或换会话关闭旧层。保留其他页面的附件预览/下载，仅移除此入口的 PDF lease 请求。

从现有简历纸身提取两个消费者需要的纯展示部分，Mock 与 Backend 分别映射；不重构所有简历页面。

## 5. 推荐匹配分析：现有响应能支持的部分

### 本轮可做

将正向推荐依据移入唯一“匹配度分析”，移除重复的空分析区和独立“推荐依据”标题。总分继续使用后端 match_score，不重算。

按现有六维顺序显示：方向、技能、经验、地点、办公方式、薪资。消费 highlights、structured_requirements_confirmed、compensation_relationship，完整映射现有原因码：category_matched、skills_matched、experience_met、location_matched、workplace_mode_matched、compensation_overlap、compensation_near_miss。

- 明确正向原因可标勾并说明已匹配。
- skills_matched 仅说明有关键词命中，显示“有技能命中”，不能声称全部匹配，也不推断命中数量。
- compensation_overlap 表示匹配，near_miss 表示部分匹配；明确 unknown 显示“未核对”。
- 其他维度原因缺席显示“未提供判定”，附统一说明“当前接口仅提供部分匹配依据”；不画成“不匹配”，也不声称后端已核对或明确缺资料。
- 不展示逐维得分/满分，不用总分减法反推技能得分，不拿当前简历/岗位重算批次结果。
- Mock 使用相同六行布局和本轮有限信息展示模型，不继续暗示有可验证的 JD 逐项计分。原始评分算法不变，求职端原有匹配页面不改。

### 必须后端支持才可完整实现

精确区分各维度的全匹配/部分匹配/不匹配/未知，并显示可加总到总分的分项分值，需要批次生成时同源保存并返回六维解释。现有总分与正向原因无法恢复这些事实。原 Plan 的 match_analysis API/存储改造不在本轮实施范围。

## 6. 个人亮点与公司卡片

- 已有 personal_highlights 接线保留，有值展示；合法空改为“暂无可展示亮点”。不声称一定未生成/解析失败，不拿匹配原因冒充个人亮点。
- 公司非空时显示“公司 · 职位”；公司为空只显示职位；两项缺失显示已有空态。不借上一家公司冒充最近公司，不从自由文本挖取被过滤的公司。
- 正确样本 company=null 的直接原因已定位：源公司存在、current_employer=anonymous 已生效、经历 hidden=true；前端收到 null，不能凭展示修复恢复它。
- 另一账号精确 parse 的 suggestions=[] 已确认，但不能关联到正确推荐账号，也不能区分模型空/校验全丢/旧解析没有附属结果。若要修生成链，需对应主体与 file/version/parse 的服务端证据，属于后端后续工作。

## 7. 经历开关：仅接现有企业屏蔽 API

后端已有 organization-blocks API，本轮可以让“对这家公司隐藏我的信息”真正操作企业屏蔽，无需新增后端接口。

- 开关基于选定 organization_id 的有效屏蔽状态；隐私页与同公司其他经历保持一致。manual 一直有效，derived 来源按现有 employer_privacy_enabled 生效规则解释。
- 复用现有添加/解除操作、If-Match/幂等/风险确认；已有来源不覆盖。保持“编辑完成→上层保存”：仅暂存明确开关意图，保存前校验，再提交显式隐私变更与简历。失败保留待提交意图，标未保存，不把部分成功当整份成功；重试前权威重读。
- 更换公司/删除经历不隐式解除旧企业；取消未保存编辑不发屏蔽请求。同公司多个编辑意图按组织合并。
- **旧 hidden wire 合同保留**，该 UI 开关不再写入它。新手填/PDF 预填经历默认 hidden=false，避免继续把企业屏蔽误写成公司名遮蔽；既有经历原 hidden 值在无关保存时保留，不批量清空、不暗中放宽旧值。
- 现有测试数据可重建，以新建 hidden=false 的资料验收“屏蔽 A、对 B 按披露显示公司”。已有 hidden=true 的数据仍可能被后端遮蔽，这是已知未修范围；本轮不清库/迁移，也不承诺旧样本自动恢复。
- 企业资料访问是否拒绝继续由已有后端权威执行。前端不得通过“从页面隐藏”冒充权限修复；若现有后端某个旧推荐/Case/附件读取路径没有检查企业屏蔽，记录为后端缺陷，本轮不跨仓修补。

最小方案是把错误 UI 接线改到已有 API，同时停止为新经历制造 hidden=true。后端彻底删除 hidden 模型、改历史冻结资料/过滤规则仍属于后续工作，不能在前端假装完成。

## 8. 验收与明确不做

|范围|本轮验收|边界|
|---|---|---|
|聊天列表/页头|真实资料、两种企业语义、分页补读去重/并发、搜索、失权/迟到结果隔离|不新增 P7 字段；可合法缺资料|
|消息头像|32px、本人图、双方首字回退、换图重试、账号隔离|不改列表尺寸|
|在线简历|纸身、联系人占位、零 PDF 请求、关闭/重试/失权|不开放联系字段|
|匹配分析|六行、正向依据完整映射、缺判定不当不匹配、唯一总分|无完整分项判定/分值|
|亮点/公司|有值展示、合法空诚实展示|不恢复后端未返回的数据|
|企业开关|现有 API、同组织状态、失败待保存、新经历 hidden=false|不删除后端字段，不改旧值或权限逻辑|

只用前端 Vitest/Playwright 离线 fixture/Mock 视觉采集和 typecheck/build。真实后端或 STG 浏览器验收另按前端活动指南及实际环境授权执行，不能用 fixture PASS 证明后端权限安全。不运行后端测试、migration、服务启动或部署。

本轮不做：后端 counterpart 投影优化、六维快照/新 API、亮点生成/诊断代码、hidden 后端语义删除、旧数据迁移、联系方式披露、评分算法改变、后端权限修补。后端调研仅作为事实依据，不是后端执行任务。
