## 3. 方案选择与最小性

| 方案 | 收益 | 代价/缺口 | 结论 |
|---|---|---|---|
| 只加文档和标签 | 改动小，可搜索 | 16k 行 spec、跨入口重复和多目标长 Case 仍然存在 | 不足以满足本轮目标 |
| 复用 runner，按域拆分和裁剪，并从实际收集结果维护清单 | 提供独立选择、明确归属、可测量成本；保留既有基础设施 | 需要覆盖对账与共享 fixture 消费者验证 | 采用 |
| 新建统一测试平台/DSL/通用场景执行器 | 可以统一表面形式 | 增加第二套调度、注册和维护机制，没有当前必要性 | 不采用 |

只引入服务当前问题的组织方式：原生选择边界、局部 fixture 模块、一个入口文档、一份可再生成的 Case 清单。允许一个薄清单生成脚本读取原生 runner 的收集结果；不构造自己的执行引擎、插件注册中心、依赖调度器、跨运行缓存或独立结果数据库。

## 4. 分层与执行边界

| 层 | 负责证明 | 环境 | 不负责证明 |
|---|---|---|---|
| 单元/组件 | 计算/映射、状态转换、请求构造与解码、权限投影、组件单一交互、局部恢复 | Vitest；按测试实际需要使用 node/jsdom；受控时钟与本地替身 | Cookie/CORS、真实对象存储、服务端事务、部署正确性 |
| 前端集成/浏览器 | 页面与数据层协作、浏览器导航、真实 DOM/焦点/滚动、客户端错误恢复与隔离 | Playwright；本地 Vite；HTTP/WebSocket fixture 或产品 Mock | 真实 STG、真实模型或后端服务正确性 |
| L3 | 关键用户旅程跨真实服务可完成并持久化；真实身份与资源隔离 | 本地前端 backend+stg；后端既有 operator | 穷举所有故障组合、替代所有低层回归 |

- 视觉回归与可访问性/布局测试属于第二层的独立选集，不额外增加一个业务测试层。
- 第一、二层正常执行不依赖 Docker、本地完整后端栈、STG 可达性、OTP 或真实账号。浏览器业务 HTTP 与业务 WebSocket 不得因漏拦截逃逸到真实 STG；不误拦本地 Vite HMR。实现优先复用现有路由/事件桩，未知业务请求不得被通用 200 假成功隐藏。
- fixture 的 backend 模式项目在活动入口与文档中明确标为 fixture，不能把构建的 `VITE_BACKEND_ENV=stg` 当成真实服务证据。
- 第一层不得为分类把原本需要 jsdom 的测试强行迁到 node；纯进程内测试的环境优化须有依赖证据。
- 真实 L3 继续使用已有 operator、受限凭据输入、receipt 和清理合同，不复制后端环境工具。

## 5. Suite、Case、变体与选择

### 5.1 统一概念

- **Suite**：同一业务域或交互责任的一组测试，具有明确层级、目的、依赖与独立选择方式。
- **Case**：原生 runner 的一个可单独选择、独立准备、独立判定结果的测试。内部可有多个步骤，但只围绕一个可解释的风险/状态转换。
- **变体**：同 Case 的角色、视口或数据参数。清单同时列逻辑 Case 和执行变体，不将两种宽度冒称两个业务目标，也不跨模式错误去重。
- **步骤**：Case 内部动作，不把 `test.step` 当独立 Case，不将同一串行流程换标签后冒称完成拆分。

### 5.2 标识和原生选择

- Suite 采用可读、稳定的域名；Case 在单元/组件层用仓库相对文件路径加完整 `describe/it` 名称定位，在浏览器层用相对文件路径加完整测试标题定位。保留 runner project/参数作为变体坐标。
- 不为数千条现有单测批量插入无业务含义的顺序编号。文件/标题改名是可追踪的 Case 迁移，记录旧→新映射。
- L3 保留现有公开 Suite/Case ID 与 `manual/parsed` 变体，不在本轮把它们改成另一套命名。既有模型是一个 onboarding Suite、两个角色 Case、四个执行组合。
- 原生文件筛选与 `-t`/`--grep` 是执行真相。可以用少量 Suite 标签辅助跨文件选择；文档必须给出可复制命令，清单生成结果须可反查原测试。
- 单元/组件沿用源码邻近布局。对大文件按职责拆同目录测试文件，不为三层模型全量移动生产源码或所有测试。

### 5.3 Suite 范围

第一层按既有边界组织：数据契约/映射、状态操作、流程、页面、复用组件、运行配置/工具；每个模块/现有 `describe` 构成更细 Suite。重点拆分应用状态、发布岗位、MatchCase 详情、工作经历中的多个责任域。其他大文件先入清单和测量，再按独立风险/准备成本拆分，不按统一行数机械切块。

第二层使用如下业务归属，域内可有多个 spec；Plan 冻结实际文件映射，不增加层级管理平台：

| Suite 责任 | 现有覆盖 |
|---|---|
| 登录与数据源边界 | 区号、身份恢复、Mock 零业务请求、模式隔离 |
| 候选建档 | 社招/学生正常路径、首次意向、恢复、资料确认 |
| 招聘建档与 JD 导入 | 名片首写、首次发岗、JD 授权/建议/确认 |
| 简历与附件 | 在线资料、作品集、附件生命周期、解析授权与恢复 |
| 求职意向与目录 | 意向增改、私有筛选、城市/学校/专业/行业/职位引用 |
| 招聘组织与岗位 | 任职/组织、名片/公开企业、媒体权限、岗位编辑与发布 |
| 隐私与实名 | 披露、屏蔽/解除、竞态隔离、实名提交/取消 |
| Agent 规则 | 提案解释、确认、编辑、暂停/恢复、删除及错误恢复 |
| 推荐与委托 | 双端发现、刷新、收藏/淘汰、委托与作用域隔离 |
| 连续委托与 MatchCase | pre-Case、S0–S3、详情、终局、PDF 披露与会话移交 |
| 真人消息 | 收发、已读、事件重拉、重连、角色权限 |
| 账号与支持 | 会话、换绑、导出、注销、反馈、举报 |
| 展示与浏览器交互 | P1/展示接线、代理页、卡片/详情、选择器、抽屉、换壳 |
| 标注工具 | 标注构建与业务 UI 不互相遮挡 |
| 视觉采集 | 18 场景及已有 P1/展示接线采集责任，显式选择 |

拆分 `数据源模式.spec.ts` 的测试与 fixture/helper。按实际复用抽取最小模块，保持依赖单向与每 Case 独立状态；不复制整套巨型 fixture 到每个 spec，也不把全文件改名为 `shared.ts` 就视为模块化完成。可以保留一个薄路由装配入口，域模型/处理器/场景数据依责任归属分开，不建立通用模拟后端。

## 7. 长测试与成本治理

### 7.1 实施期先取有效样本

在实施期通过原生报告记录受影响测试的 Case 耗时、Suite 墙钟、准备成本、失败/超时情况；固定源码、浏览器/runtime、worker 数、模式与选集。优先读取可用且匹配版本的报告，缺失时只跑足以决定拆分的子集。拆前、拆后比对同一风险集合；不能把删除覆盖、提高并发或跳过失败计算为提速。

初始调查目标可用：单元/组件 Case 超过 1 秒、浏览器 Case 超过 10 秒、常用 Suite 超过约 60 秒时解释主要成本。它们是调查阈值，不是新增超时/失败门禁；真实改善幅度由实施数据决定，不承诺未经测量的百分比。

### 7.2 必须完成的拆分责任

- 候选/招聘正常建档各保留必要的少量前端接线冒烟；学生与社招的不同产品路径保留。其他编辑、目录、布局测试可用合法 fixture 准备进入目标状态，避免反复走完整建档。
- 拆开规则全链路中的不同主体/操作责任、隐私主链路中的披露/屏蔽/岗位条件、JD 导入与与其无关的完整岗位编辑。仅为某字段断言附带的无关导航不再重复运行。
- 附件上传→替换的版本归属、首次意向唯一性、未知结果同键恢复等跨步不变量，必须保留一个能证明其关联的 Case，不能拆成互不相关的成功快照。
- 第一层四个重点大文件按领域/状态分支组织可选择 Suite；每条测试独立构造输入和清理，不共享上条测试产生的状态。只覆盖一个完整竞态的长测试可以保留并说明理由。
- 对真正消耗时间的防抖/轮询单元测试，用受控时钟或显式 Promise 释放替代真实空等；验证计时行为本身时保留相应断言。浏览器使用可观察条件等待，不全局 time mocking、不用固定 sleep 掩盖竞态。
- 不把 `userEvent` 一概替换成低保真的事件；不删除焦点、真实滚动、取消零写入、权限、幂等、revision、权威回读等独有断言。
- 不提高全局/单 Case 超时、不增加重试、不强制单 worker来掩盖失败。现有超时应结合测量收敛，不能盲目降低导致不稳定。

如果某慢 Case 主要消耗来自当前产品必要等待或测试环境启动，且不能在不改产品/覆盖的条件下降低，明确记录原因和最小选择入口；不以重命名或物理分文件宣称它已提速。

## 9. 测试文档交付与清单真相

实施交付两份长期维护文档：

1. `docs/testing/README.md`：三层责任、Suite 目录、按影响选择测试、精确运行/列举命令、环境和产物位置、长测试规则、扩展 Case 的最小步骤、旧→新迁移表及 L3 未承接清单。
2. `docs/testing/cases.md`：单元/组件与浏览器的完整叶子 Case 清单、L3 当前可执行 Case/变体索引。按层和 Suite 分组，字段包含可执行标识、名称、相对源码链接、模式/参数、选择方式。无匹配的实际计时写未知，不用 timeout 当耗时。

第一、二层以 runner 实际收集结果为准，参数化测试展开为可核查的执行变体；薄生成脚本只列举，不执行测试、不启动服务、不访问网络、不在导入时写截图目录。清单输出稳定排序、无机器绝对路径/认证材料；未知文件或重复 Case 身份要显式报错，不能静默丢项。生成失败非零退出且不得把部分清单覆盖为成功结果。

L3 清单从现有活动指南获得，保留 Suite/Case/variant 的现有名称；执行结果按 run 保存在既有证据位置，不在静态清单给 Case 永久盖 PASS。可以在生成文档的独立手写区维护 L3 索引，避免为两套指南另建注册格式。

`README.md` 与 `CLAUDE.md` 指向新的测试总入口，保留直达真实 STG 指南；检查活动相对链接有效。若触及与 `AGENTS.md` 双写的工程原则则必须同步，但本任务没有修改原则的需求。
