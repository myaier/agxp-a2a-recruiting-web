## 1. 目标与已确认范围

候选人完成 onboarding 后，从“我的简历”编辑资料，只修改简历并回到简历；从“求职意向”编辑筛选要求，直接编辑首次引导拼接后保存的私有文本；城市选择的热门区、分省列表、搜索与已选项对同一城市显示一致名称。

用户已确认：历史结构化排除字段没有消费者，本次保留，不增加迁移、清理或生效排查。此项作为任务边界，不代表本轮重新审计了后端消费者。

首次 onboarding 的勾选方式保留。后续新增／编辑意向共用表单内的“哪些情况直接排除？”替换为文本框。本次不修改后端接口。

## 3. 方案取舍

采用现有共用资料页加显式编辑来源、替换意向表单局部控件、统一城市展示名的方案。它直接修正导航与展示边界，不新增一套页面或持久化模型。

不采用复制独立简历编辑器：会重复资料校验和保存链。也不采用仅由引导草稿是否为空推断来源：Mock／Backend、刷新和恢复存在不同状态，来源应可直接确定。城市不采用点击时逐个搜索或重写全部目录名字：已有 canonical ID 足以维持选择身份，差异在名称。

## 4. 简历编辑契约

### 4.1 入口与模式

从“我的简历”进入基本信息、工作经历及求职状态时，使用显式 URL 参数 `from=resume`。覆盖普通字段入口、工作／教育／技能／项目／证书入口、完整度补全入口和身份缺失后的补全入口。参数能保留到刷新，不由临时全局状态推导。

只有上述共用资料页识别该参数；无参数的首次 onboarding 路线保持原行为。若基本信息因身份为空必须继续到求职状态，须继续携带该参数。

### 4.2 保存、返回与数据

- 编辑模式：基本信息的主按钮显示“保存”；工作经历继续使用“保存”；求职状态补全的完成动作显示“保存”。各屏保存成功回到“我的简历”，不得进入意向题、披露说明或头像注册流程。
- 工作经历页内部的经历／教育编辑保存仍回到本页列表，整页保存才结束本次编辑。
- 基本信息身份为空时保留既有资料补全要求：先进入带编辑参数的求职状态，成功保存资料后回简历，不绕过必填要求，也不继续学历与偏好流程。
- 编辑模式不得创建或更新首次意向，不派发到岗引导预填，不写 onboarding 建档草稿、不确认 onboarding 预填分区、不触发 onboarding 建议恢复。必要时调整现有预填位置判定对 `from=resume` 的识别；不重构整个恢复机制。
- 继续使用现有简历保存操作和权威回显。保存失败保留输入并显示既有错误，不返回简历、不显示成功。
- 返回／取消沿用既有导航及页面草稿语义；本次不新增全局未保存拦截。通过明确成功落点结束编辑，不要求用户手动退出向导。
- 简历内显式“添加意向”的独立入口不携带简历编辑参数，不属于简历保存的后续步骤。

### 4.3 首次引导回归

学生、社招无参数入口继续原有资料、偏好、个人优势、披露与完成步骤，保留恢复和解析预填能力；不能通过“所有保存都回简历”修复日常编辑。

## 5. 意向私有筛选要求契约

在 `src/屏幕/添加意向.tsx` 的新增／编辑共用表单中删除排除卡片区域，原位置替换为与招聘侧视觉一致的多行输入：

- 标签：“给 AI 代理的筛选要求”；旁标：“选填”。
- 说明：“写下你的要求和偏好，AI 代理会据此筛选岗位。”
- 完整回显当前意向的 `private_preferences`，直接绑定 `意向草稿.私有偏好`，沿用现有草稿与保存链。
- 可编辑、增删任意行及清空全文。空值显式提交 `''`，不能转为 undefined 后回退原值。保留换行及原文，不拆成卡片，不二次加“不接受”前缀，不进行模型改写。
- 不照搬招聘侧 200 字输入限制，不截断已有文本；沿用意向接口的既有校验和错误提示，不新增未经后端契约支持的限制。
- 历史 exclusions 原值透传，新建保持现有 unspecified 默认值。私有文本修改不联动清除或生成结构化排除值。
- 不改变工资、办公方式、招聘类型、目录引用等其他意向字段。继续使用带 revision 的既有更新请求与保存后回显机制；失败不离页。

复用招聘侧的布局、文案结构和样式原则即可，不为了这一块引入通用表单框架。首次 onboarding 的排除卡及其固定拼接规则不受控件替换影响。

## 6. 城市名称一致性契约（外部分支承接，本任务不重复实施）

此项已由 `brown-lion` 分支 `audit-option-components-editors` 的 `docs/superpowers/specs/2026-09-15-editor-catalog-fullscreen-design.md` §5.6 及对应 Plan Task 6 承接；截至本轮核对尚未实现。本任务仅在其实现合入后验证相关消费者，不重复修改城市配置或兼容逻辑。该分支合同覆盖 22 个国内外热门名称、四处消费者与 Mock 有限别名兼容，范围大于下述原始需求；名称与 Mock 兼容以其最终批准合同为准。

原始需求范围覆盖候选 onboarding 多选工作城市、意向主工作城市单选、意向备选城市多选三个入口，生产代码承载页为 `选工作城市.tsx` 与 `选择城市.tsx`。

- Backend 模式以目录标准名显示同一 canonical ID；大陆热门项同步为对应标准名，例如“北京市／上海市／深圳市”，不只修复北京上海两个例子。
- 热门、目录分组、搜索结果、已选 chips，以及保存后再次打开，名称保持一致；已有短名草稿在当前展示中按相同 ID 对齐，不能刷新或重新选中后才修正。
- 标准名称应来自对应目录证据，不对全球城市统一追加或删除“市”。实施时核对大陆热门配置的目录名称；未取得可靠名称不得猜测海外名称。本次海外热门译名政策及港澳台分组不变。
- 名称是展示信息，ID 是选择与提交身份。同一 ID 从任意区域操作，都应同步选中／取消；同名不同 ID 不合并。
- 保留现有主城市禁选、单选／10 城市／9 备选上限、分页、搜索、重试和保存才落草稿的语义。
- 热门配置可以保存所需的标准名称，但不新增首载逐项搜索、不增加接口或缓存服务。已加载的目录与已有引用应遵循一致的名称选择规则，不能因区域渲染先后而相互覆盖出不同标签。
- Mock 使用本地城市字典的既有名称与字符串身份，不因 Backend 名称对齐引入“上海”和“上海市”两个可选项。共享配置的调整必须保留这一边界。

## 7. 技能与资格证书组件统一

用户追加：onboarding 和简历编辑中的专业技能、资格证书均采用当前专业技能的组件形式。两种旅程本来共用 `src/屏幕/工作经历.tsx`，差异在该页内技能是标签卡、证书是列表行；不另做两套实现。

- 将技能与证书统一为标签展示、输入框、添加按钮和逐项删除的同一组件。标签支持换行排列，长名称不撑破页面；技能与证书保留各自标题、输入提示和可访问删除名称。
- 共用组件仅承担展示与输入交互；技能仍为字符串列表，证书仍为包含编号、名称、年份的对象列表，不把证书降为字符串或重建已有 ID。
- 既有证书年份不丢失，有年份时仍可见；新证书仍按既有规则年份为空，不增加年份输入。
- 保留既有添加、空白校验及去重语义：技能沿用去重；不借样式统一删除历史同名证书或改变证书身份。证书按编号删除。
- 保留 Enter 添加与中文输入法组合输入保护，以及 onboarding 证书未提交输入的草稿恢复和成功添加后清理语义。页面整体保存归属不变。
- 共用组件的两个当前消费者就是技能与证书，不扩展为任意字段表单框架；“我的简历”摘要展示卡不在此组件替换范围。

## 8. 个人优势编辑入口

当前 `src/屏幕/我的简历.tsx` 的个人优势卡只有普通 div，没有点击事件；`src/屏幕/引导问答.tsx` 已有优势题编辑 UI，但其完成处理同时写个人优势和首次意向，不能直接照搬完成逻辑。

- “我的简历”的个人优势区改为可点击、可键盘操作的编辑入口；已有正文保留换行，空值显示明确的添加入口。
- 复用 onboarding 的个人优势编辑界面，从简历进入时直接显示个人优势，不先经过城市、薪资或排除题。使用显式编辑来源 `from=resume`，刷新仍保持个人优势编辑场景。
- 编辑初值来自当前已加载的简历个人优势；共享编辑正文与既有 500 字规则。不因日常编辑而使用演示文本或恢复 onboarding 解析建议覆盖现值。
- 编辑模式按钮为“保存”，只调用既有 `保存个人优势`；成功回到“我的简历”并显示保存后的值，失败保留输入及既有错误提示。返回而未保存不得提交个人优势。
- 不调用保存首次意向、不确认 onboarding 分区、不写引导草稿，也不进入披露、头像流程。
- 日常编辑不显示“已根据你上传的简历预先提取”或引导恢复动作等不成立的描述；onboarding 的实际预填、恢复与后续流程保持原有语义。
- 优先对既有向导添加窄范围个人优势编辑分支并复用优势题正文，不复制整套编辑器，不改变 onboarding 题序。具体分支入口与保存隔离的测试契约在 Plan 冻结。

## 9. 验收责任

实施 Plan 必须把下列反例落实到现有测试入口，先验证相关行为会失败，再实现修复：

1. 从简历所有共用页入口进入、刷新、保存，只回简历；学生／社招均覆盖。身份缺失补全后不落向导；保存拒绝留在编辑页；不发生首次意向写入和引导状态写入。
2. 无编辑参数的首次 onboarding 仍能进入偏好阶段并完成，恢复和预填判定不受影响。
3. 首次拼接的多行私有文本完整回显，编辑后保存并重开一致；可清空；超过 200 字的既有文本不丢失；其他意向字段和 exclusions 保留；首次 onboarding 卡片仍存在。
4. 北京市／上海市／深圳市同 ID 同时出现在热门、目录、已选时名字一致；从热门与目录互相取消；旧短名引用再次打开一致；主城市禁选与上限继续成立。两页面及单选／多选入口均覆盖。
5. 对更改的页面做浏览器布局检查，确认文本框可输入多行，标准城市名不会挤压按钮或底部 chips；真实后端意向保存／重新读取与简历保存回跳按 `docs/dogfood/真实后端行为验收.md` 选择相关路径，缺少环境时明确记录未完成，不用 Mock 证明真实持久化。

6. 技能与证书在 onboarding／日常编辑使用同一标签组件；添加、删除、中文输入法 Enter、证书编号／年份保留、未提交证书输入的刷新恢复均有针对性回归。用行为证明数据保留，不只断言相同 className。
7. 个人优势有值／空值均可进入独立编辑场景；刷新不回引导，保存成功回简历，失败留页，取消不写入，首次意向写入次数为零；正常 onboarding 仍保留其个人优势及首次意向完成链。

复用当前 Vitest／Playwright 和真实后端验收路由，不新增测试基础设施。具体最小命令、责任分工与执行模型在获批后的 Plan 冻结。本轮文档规划不运行重测试，也不声明产品验证通过。
