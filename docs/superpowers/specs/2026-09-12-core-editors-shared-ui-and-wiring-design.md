遵守 `CLAUDE.md`、`AGENTS.md`。与本任务有关的历史设计：

## 2. 已确认的产品决策

1. 本轮合并纯前端修复和展示统一；实习转正后端字段不纳入。
2. PM 已设计的 Mock Up 为样式基准，不能自行发明视觉、控件或重排无关页面。
3. 允许修改数据输入、事件回调及外层状态；进一步允许从现有 Mock 代码改造新的共用组件，而非只修改原组件。
4. 原 Mock 组件代码先保留用于对比；正式 Mock 和 Backend 都调用新的共用组件，不能仅改 Backend 而让 Mock 留在旧实现。
5. 其他感兴趣城市保留原城市按钮、标题、搜索框、已选区和整体样式；A–Z 改为真实行政区分组，移除右侧字母索引。
6. 学校、专业、职位类别、行业选择保留原 Mock 样式，允许接入已有候选行、多级展开和“加载更多”控件；Mock 提供模拟目录，Backend 提供真实目录。
7. 附件区保留原附件行样式，允许复用现有“＋”、滑动操作、确认层、状态文字，Mock 模拟添加、替换、删除和解析。
8. 岗位结构化确认采用当前 Backend 的复选框、说明和位置，纳入共用展示；Mock 也展示并模拟确认，不产生真实请求。
9. 新发现的展示能力缺口必须先交 PM 决定；不能把上述例外扩展为自主设计授权。

### 3.2 方案与取舍

采用“按具体区域改造既有展示 + 两模式外层提供数据/控制”的方案。新组件只解决本表列出的真实重复，优先沿用现有 CSS 模块与基础组件；已经共用的字段不再重复提取。组件数量、文件名与精确 props 由 Plan 冻结，不逐字段创建组件，不建立万能表单、万能目录树或新的设计系统。

仅共用 CSS 无法消除 JSX 分叉；直接以 Backend 页面作为整体设计会带入未经批准的布局变化；完整重写三个表单超出需要。局部合并可保留现有业务链并满足当前需求。

### 3.3 非目标与延期

- 不增加或修改 BFF/API/schema、数据库、权限、认证或部署配置。
- 不补岗位“实习转正机会”后端字段；保留既有本地附属行为，不宣称该字段已服务端持久化。待正式读写合同提供后另行接线。
- 不为意向增加年薪月数编辑入口；待 PM 明确要求采集该偏好再设计。
- 不恢复已删除的岗位关键词、四问硬性事实、加分项等输入入口，不改变不可变岗位字段。
- 不实现定位、浏览历史服务、全球城市拼音目录、第三方拼音依赖或全目录预加载。
- 不改个人优势编辑入口、简历诊断业务、简历条目排序、onboarding 题序或建档事务；不顺便修复其他审计发现。
- 不引入全局状态库、请求框架、公共配置开关、通用能力注册表或新测试平台。
- 不新增旧版/新版切换按钮、产品对比路由或长期维护的双版本运行分支。需要可交互的旧版演示时另行确认范围。

## 4. 原 Mock 对照代码与共用边界

### 4.1 对照代码

实施前保留本次被替换区域所在源文件及依赖样式的基线快照，存于 `docs/design-references/2026-09-12-core-editors/`，保留原相对目录层次并以 `.txt` 结尾，例如 `src/屏幕/选择城市.tsx.txt`。快照保留源内容，不重写原 Mock；内嵌于页面的组件可以保留完整所在文件，以免截取时遗漏样式/交互上下文。

Plan 列出精确快照清单与基线 Git blob；只保留本轮实际替换区域必要的源码/CSS，不复制仓库或 node_modules。基线截图使用既有视觉采集/浏览器工具在改动前获取，留在既有忽略的测试产物位置。代码快照用于查阅与差异对照，不进入 TypeScript 编译、生产包、运行路由或测试发现。

原 Mock 对照代码是冻结样本，不随新组件修复而改写；删除它需要用户后续明确同意。原 Backend 重复展示在消费者全部迁移后从运行代码中删除，不保留第二条隐式 fallback。

### 4.2 数据与控制

- 共用展示接收展示值、稳定键、选择/禁用/展开/忙状态及回调；不读取环境、BFF raw DTO、应用 Context、Mock fixture 或 localStorage，不调用 API、路由或业务派发。
- 真实请求、目录引用、分页游标、版本、会话代际、保存归属与错误处理仍由已有外层承担；展示不按显示名反查真实 ID。
- 允许局部纯映射与具体 props，不为一次性适配新建通用抽象层。已有基础组件（弹层框架、滑动行、确认层、滚轮等）直接复用，不修改它们的视觉实现。
- Mock 原有业务数据/草稿继续归现有 Mock 状态；新增模拟目录和附件控制仅用于驱动本轮共用展示，不伪造 Backend 数据、不启动真实请求、不写入后端环境存储。
- 同样展示输入与交互状态必须得到同样 DOM 结构和样式；数据量、权限、加载/忙状态造成的可见差异允许，但不能以数据源名称选择另一套 JSX。
- 不要求 Mock 模拟服务端幂等/CAS/解析器/网络栈；所需可见交互在外层模拟。错误状态通过现有测试注入验证，不增加产品调试面板。

## 5. 展示设计与现有组件支持

### 5.1 其他感兴趣城市

继续使用本页原标题、搜索框、城市按钮、最多9个计数、底部已选标签、保存与取消结构及 CSS。删除 A–Z 字母索引和按拼音字母组织的数据；分组标题使用目录 `admin1_name`，缺失时使用 `country_name`，顺序沿真实数据返回顺序。两者均缺时不编造行政区；该条目仍可在热门/搜索结果呈现，不新造“其他”分区。

热门区复用已存在的 Location 默认页口径，不宣称实时热度排名；Backend 不拿本地演示城市作可提交条目。当前/历史访问位置没有真实来源时，沿现有城市页“暂未获取定位”的不可选占位，不增加定位与历史查询；Mock 可以使用明确的模拟数据。

按已有默认页/搜索分页机制增量提供数据，采用已批准的现有“加载更多”控件，置于其对应列表尾部；不预加载完整目录，不把当前页当成全集。Backend 按 ID 去重，排除主城市，最多9个；搜索/翻页不丢已选项；取消不写草稿，保存才写本页负责的备选城市。Mock 使用相同展示与选择规则。

### 5.2 学校、专业、职位类别和行业

| 区域 | 原设计基准与允许的扩展 |
| --- | --- |
| 学校/专业 | 原教育编辑表单输入位置不变；使用当前已有候选列表/候选行样式，学校副行沿现有城市/国家展示；保留列表尾部“加载更多” |
| 岗位职业分类 | 保留原 Mock 分类弹层的标题、两栏、选中勾与尺寸；用真实或模拟数据替换写死的分类表，保留当前已实现的多级下钻与根/子分页 |
| 简历行业 | 保留原所属行业输入行及底部选择层；复用既有列表项、多级展开及分页，不为层级新造图标/面包屑/弹层 |
| 意向行业 | 保留原已选计数、推荐区、手风琴与标签样式；多级展开和分页沿当前已有实现的位置 |

层级条目按 `selectable` 决定能否写入选择；父项用于展开，不当成叶子提交；`has_children` 按现有契约读取，不用名称/parent_id 猜测。目录深度超出现有控件承载范围时必须记录具体输入和缺口交 PM，不截断目录、不无界扩成通用树。

选中身份按稳定 ID；同名条目不能相互覆盖，已选条目不因搜索/分页离开可见页而消失。Backend 保留精确学校/专业/行业引用、输入变更清旧引用、提交前引用检查及目录版本/迟到响应保护。Mock 沿用本地选择控制，可使用局部模拟键，不将模拟键传入真实请求。单选/多选上限、返回位置和保存时机沿现有业务归属。

加载、空结果和失败复用已有列表文字及轻提示；失败不能展示为成功、不能回退演示目录。此处允许把已有 Backend 候选与分页展示纳入 Mock 共用组件，不允许改动其他引导页布局。

### 5.3 简历附件区

共用原附件卡、PDF标记、文件名、说明、箭头；复用当前 Backend 的标题“＋”、`滑动行`、上传/解析授权及删除确认层。允许多行和已有空态，列表来源和上限由外层提供。

保留当前动作矩阵：未解析可解析、解析失败可重新解析；等待/处理中/成功状态不新增解析动作；替换/删除沿当前可用规则和提交锁。授权前不上传或发解析请求；失败不移除权威行，不用模拟进度冒充真实解析；动作绑定所点附件的真实 file ID。

Backend 保留上传验证、同意后请求、权威回读、轮询、会话隔离、文件预览与资源清理。Mock 外层提供模拟附件和相应状态/动作，文件名及状态变化驱动同一个组件；选择文件、确认和删除使用同一可见交互，但不调用后端、不宣称执行了真实解析。没有真实 PDF 内容时沿既有原型预览提示，不伪造文件或解析内容。

### 5.4 岗位结构化确认

将当前 Backend 复选框、说明及已有错误提示原样放在两模式共用的现有位置：公开岗位要求之后、给 AI 代理的筛选要求之前。不增加卡片、弹窗或新的解释文案。

Mock 模拟同样的确认状态与交互：新建未确认不得推进到成功；经验/学历/公开要求真实变化后撤销确认，修改私有筛选偏好不撤销确认。Backend 继续遵守当前 JobCreate/JobPatch 的确认要求与 sparse patch，不把点击同一值算变化；存量 legacy false 岗位修改无关字段仍按现有合同处理，不扩大服务端必填条件。校招/实习经验值按现有最终 wire 语义判断，不能因隐藏的残留选项误触发。

## 6. 两处前端接线修复

### 6.1 日常作品集链接

当前 `工作经历.tsx` 仅在建档旅程中携带链接，`招聘数据源/简历.ts` 又用建档跟踪参数限制链接写入，日常编辑因此只回读而不保存。

- 链接是否明确编辑与是否处于 onboarding 分离；日常编辑也记录本页本次修改，已保存值和未提交输入不得混为一谈。
- 未修改（包括只聚焦/失焦且规范化值未变化）省略 `作品集链接`；明确清空传 null；明确设置按已有规范化/校验发送字符串。
- 数据源不再把“有建档跟踪”作为链接可写条件；有意修改且最终值与权威值不同，即使其他资料未变也发 profile PATCH。
- PATCH 保留完整 profile 已有字段，使用现有 profile revision；不为单独写链接清空姓名、身份、生日等事实。身份为空不能伪造默认值或跳过后声称已保存，沿既有求职状态入口与提示处理。
- 检查所有 `保存简历` 调用方：未改链接的普通资料/个人优势保存不得因展开 GET 快照顺带携带旧 URL；明确编辑的链接不能被遗漏。
- 成功后通过权威 GET 回显；失败保留本次输入供显式重试，继续使用既有错误能力。保持原 401、409、结果未知处理，不新增自动重试或新的事务机制。
- 保持 onboarding 草稿、单槽回执、刷新恢复和预填确认规则；日常编辑不得为了写 URL 创建建档草稿。

### 6.2 意向跨类型薪资

当前 `后端映射.ts` 在区间薪资下无条件从原意向保留 `annual_salary_months`，切为实习/兼职后违反合同。

- 以本次最终 `recruitment_type` 与 `compensation.mode` 决定字段是否可携带。
- 目标为 social_full_time/campus 且 mode=range 时，可保留原始合法年薪月数；没有则省略，不默认12，不增加编辑入口。
- 目标为 internship/part_time，或 mode=negotiable 时，必须省略年薪月数；面议同时不携带 lower/upper。
- 保留现有跨计薪周期清上下限、同类型重复选择不清值的行为；毕业月、实习月数、每周天数沿既有类型转换规则，不扩大重写范围。
- 核验原14薪社招→兼职仍有区间、社招→实习后重新填区间、切换为面议、社招↔校招保留合法值、新建无年薪月数五类输入。

## 7. 验收与停止条件

### 7.1 必须满足

1. 本轮改造区域在 Mock/Backend 下实际调用同一新组件，不是只共用 CSS；对照快照不进入产品运行。
2. 原有 Mock 视觉基线保留，差异只来自第2、5节明确批准的城市分组/索引删除、候选/多级分页、附件操作与岗位确认。不同合法行数不要求像素高度相同。
3. 目录、附件、确认区覆盖正常、空、加载/忙、失败、选中与边界状态；无溢出、遮挡、焦点不可达或嵌套按钮。错误和占位不进入保存参数。
4. 作品集修改/清空刷新后仍为服务端值；未改 URL 的其他资料保存不覆盖 URL；日常与 onboarding 均不回归。
5. 意向切换不会发出目标类型禁止的薪资字段；保存/回读闭环正确。
6. Backend 的真实 ID、权限、CAS、幂等、目录版本、迟到响应、附件同意门和结果未知处理不因展示提取失效；Mock 不发真实请求。

### 7.2 验证分层

规划审查已执行8个相关测试文件、371项通过，并用定向调用复现两项问题。它们只证明旧基线及缺陷，不作为未来实现已通过的证据；本次写 Spec 不为文档重复运行产品测试。

实施阶段先在已有 Vitest/Testing Library 中补关键失败反例，覆盖页面提交参数、数据源请求及保留字段、映射边界和消费者。展示验证要覆盖共同输入的两模式结果，并检查真实页面入口均连接到共用组件；不靠测试复制 JSX 声称已共用。

沿用现有 Playwright/视觉采集工具做原 Mock 对照及改后双模式浏览器观察，精确场景和最小命令在 Plan 冻结。现有视觉配置默认启动 Mock，不能拿其结果冒称 Backend 通过；使用符合契约的网络桩可以证明前端边界，但必须标注为模拟。

真实持久化验收从 `docs/dogfood/真实后端行为验收.md` 进入，选择与 B02 候选编辑/附件、B04 岗位编辑相关的节点，并补本轮作品集及意向切换反例；不把局部节点通过宣称完整 Case 通过，不扩展 Hosted/无关业务。正式执行在实施 session 的具体 final gate 方案获批后进行；所需目标 URL、后端版本、专用账号及安全材料来源在该阶段核实，缺前置记录 BLOCKED，不绕过用户操作用 API 补写结果。

Plan 必须写出前端现有测试入口的最小覆盖，不直接套用后端仓库的 `tools/test affected`。同一有效候选不重复 broad gate；review 修复后只补失效覆盖，真实验收按既有环境归属和清理规则执行。

### 7.3 停止条件

实施中发现现有控件无法承载目录层级、加载恢复、附件状态或必要确认，且需要第5节之外的视觉变化时，先提供具体页面、状态、现有组件限制及最小选择供 PM 决策。可继续无依赖工作，不擅自新增按钮/卡片/导航，不删除真实能力以满足视觉一致。

发现后端版本不具备本文引用的能力时，报告实际合同差异，不在本轮补后端。批准范围、产品行为或持久化契约实质改变，先修订 Spec 再继续 Plan/实施。
