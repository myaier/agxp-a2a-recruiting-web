遵守 `CLAUDE.md`、`AGENTS.md`。调查基线为 `eeaead9abadfd1e87c4abda19fd3de5a6a66af63`。规划所在分支为 `e2e/triage`。实施从用户选择的当前工作区 `.` 开始，重新核对实际代码与该基线的差异；不自动同步目标分支，不把文档存在等同于相关实现已合入。合入目标在实施 final gate 具体化。

已有运行证据位于 `test-results/e2e-audit-20260915/`，属于被 Git 忽略的本地工件。迁移到其他机器时可重新生成，实施不能依赖这些文件必然存在；本 Spec 的事实表足以解释修复责任。

## 2. 依据与方案选择

对齐顺序：仓库规则 → 当前范围内已批准的产品／接口契约 → 实际已合入实现与相关行为测试 → 旧 E2E。发生冲突先核对具体版本和实现证据，不能因为旧测试失败就修改产品，也不能因为当前页面如此就默认接受其行为。

主要对账材料：

- `docs/superpowers/specs/2026-09-13-company-picker-and-verification-design.md`：公司选择、招聘自报企业、工作经历企业 ID、屏蔽边界。
- `docs/superpowers/specs/2026-09-14-stg-onboarding-contract-alignment-design.md`：企业命名、onboarding 与完成事实的后续契约。
- `docs/superpowers/specs/2026-09-14-recruiter-and-city-fixes-design.md`：招聘展示及城市行政分组；需核对实际已合入部分。
- `docs/superpowers/specs/2026-09-11-j-pilot-02-frontend-wiring-design.md` 与 `docs/journeys/J-PILOT-02/J-PILOT-02-产品旅程与状态规则.md`：当前候选建档流程及恢复责任。
- `docs/superpowers/specs/2026-09-14-agent-session-and-display-components-design.md`：双端固定代理入口与 Backend 能力边界。
- 规则库、产品反馈、直聊与时间展示的当前实现及相应组件测试；Plan 必须给出具体文件和迁移断言，不能只引用“最新 UI”。

用户补充授权：“做最小修复，不合适的测试可以考虑删除，有价值的测试也可以增加”。删除仅针对退役行为或已由现有测试覆盖的重复责任，记录证据和覆盖去向；当前独立风险没有其他覆盖时应保留或替换。新增用例必须指出一个现有覆盖无法证明的当前风险，不以数量或追求完备性为目标。

选择按受影响旅程迁移现有测试。只修首次报错虽更短，但会留下后续旧断言；全面重写测试框架则没有必要。现有 Playwright、fixture、trace 和采集协议已经能够完成任务，最小方案是在原处修复配置、数据与流程，不增加新框架、通用场景 DSL、契约平台或跨任务缓存。

## 3. 运行入口与采集契约

1. `npm run test:e2e` 继续承担默认 Mock 回归，只收集可在其 Mock 服务完成的用例；排除 Backend／annotation 专属用例及数据源专用文件，避免靠端口探测产生正常运行中的跳过。
2. `npm run test:e2e:data-source` 保留 Mock、Backend fixture、annotation 三项目边界，专属用例只在对应构建执行。修正标签／文件选择时列出迁移前后清单，任何从默认入口移出的测试必须在合法入口仍被覆盖。
3. 两个功能入口继续运行现有 P1／展示接线 Mock 采集场景。未设置 `P1_CAPTURE_DIR` 或 `WIRING_CAPTURE_DIR` 时，使用 Playwright 当前测试专属输出路径保存截图／场景 JSON；设置时继续遵守既有外部采集目录、scene ID 与相对 screenshot 路径协议。不得取消采集断言或用 skip 隐藏缺目录问题。
4. `ui:capture`／`ui:check` 的既有专用协议保持；文档将独立场景数校准为实际 18 个。新增能力不靠改写历史像素基线取得通过，本任务不安排无目的历史全量像素比较。
5. 测试服务显式锁定 Mock／Backend 数据源和后端环境，使用严格端口，避免复用不明配置服务；只管理本次启动的进程。默认命令不能受开发者 `.env.local` 意外污染。
6. 功能测试浏览器显式固定 `timezoneId: 'UTC'`，保留现有 UTC 时间断言；专用视觉采集已有的 `Asia/Shanghai` 保持。固定的是测试环境，不更改产品时间格式或用户时区行为。环境配置优先由 Playwright 提供，不要求用户手工设置 shell TZ。

### 4.1 招聘与组织 fixture

当前 `src/数据/招聘数据源/组织.ts` 要求招聘档案 `organization_ref` 必须存在，允许 null。36 条失败的 trace 均捕获缺该键的 200 响应。修改旧 fixture 类型、初始响应、写入回执及恢复路径，区分未选择 null 与显式组织 ID；不得随意给所有档案填同一个组织以绕过门控。

继续校准企业公开 profile、replacement 的当前必需字段与各场景使用的目录／onboarding 响应，保留 closed-object、revision、权限、身份与自报公司分离等约束。不放宽生产 decoder，不把自报企业 ID 自动当成可管理 affiliation。

复用已经正确的现有样本／helper，仅在真实重复处局部复用；不把 `数据源模式.spec.ts` 整体改造成新的模拟服务。成功用例的依赖响应必须符合实际 consumer 契约；明确测试错误响应的负例仍保留。

### 4.2 UI 与业务语义

- 公司／屏蔽：通过当前公司选择层的搜索、候选、确认执行。Mock 保留零 API，Backend 捕获真实目录 ID 与业务写入；不注入 DOM 或全局状态绕过本来要测的选择交互。
- 规则：按“哪些情况直接排除”“你教它的规则”等当前语义范围定位。已退出当前页面的意向规则不再硬断言可编辑；保留越权写入禁止等必要反例。正文与更多菜单用精确角色／名称和容器区分，避免模糊按钮匹配歧义。
- 企业名片／岗位：删除已被后续契约替代的“公司自由文本、禁止任何 organization_ref”断言，改为当前已批准的 ID 来源和权限边界；保留失败草稿、CAS、媒体协议与重入回读验证。
- 反馈／直聊：退役的按钮和路径不恢复为产品功能。旧用例改测替代行为，已有新测试确实覆盖相同业务风险时可合并，必须在 Plan 的覆盖对照中指出替代位置。
- 候选：不再假定点击“已毕业”自动选择社招；按当前契约显式选择求职类型，保留首次意向唯一性和刷新恢复。若核对发现实现违反批准契约，记录产品缺陷并暂停受影响用例的验收，继续其他独立工作。
- 城市：浙江、江苏使用不同且正确的行政编码，断言依据数据契约，不因名称不同而给相同编码构造不可能的分组样本。

### 4.3 偶发与异步边界

对公司名展示偶发失败检查 fixture 相位、页面导航、列表／详情与组织摘要回读的实际完成条件；通过目标页面／目标资源就绪判据等待。只有取得原因证据才修改，禁止固定 sleep、批量增加超时、强制单 worker 或全局 retries 掩盖失败。

恢复共享 fixture 后，在正常并发下重跑受影响消费者。Vite WebSocket EPIPE／ECONNRESET 单列诊断；如证实业务事件连接逃逸到真实后端，复用现有事件桩隔离该连接，不屏蔽错误日志或误拦 Vite HMR。没有证据的工具链警告不扩展为基础设施改造任务。

## 5. 范围与非目标

允许修改：`playwright.config.ts`、`playwright.数据源模式.config.ts`，上述失败对应的 `e2e/*.spec.ts`、`e2e/fixtures/*` 与必要的现有采集 helper，`README.md`；确需调整现有运行入口时可修改 `package.json`，但默认优先保留既有命令。Plan 必须逐 Task 列出精确文件，不将此目录范围直接当作任意改动授权。

不修改产品 UI、生产数据源／decoder／状态逻辑、后端 API、数据库或部署；不自动更新依赖，不大规模拆分超长 spec，不新建 page-object 框架。若测试修复不足以满足已批准产品契约，单列产品缺陷与证据，需额外批准后再扩大实施范围，不能谎称全部完成。

延期事项：大规模 fixture 去重、测试平台建设、长期性能优化、全面真实后端验收。只有本次局部修复后仍有重复契约漂移、测量证明运行成本成为实际瓶颈，或后续变更触及真实运行边界时才重启评估。

## 6. 验收标准

1. 无额外采集环境变量时，两个普通 npm E2E 入口均可完成，全部合法选中的用例通过，零新增无理由 skip／fixme／only；默认入口不再收集需 Backend 服务的用例。
2. 以既有 52 个 Mock 采集场景和 18 个独立视觉场景为覆盖基线，默认保留，显式目录采集仍可被现有比较器消费。用户补充允许删除不合适或重复测试、增加有价值测试；数量可以改变，但必须逐项说明退役依据或替代覆盖，不以减少当前有效覆盖达到绿色。
3. 111 条原始失败按共同原因迁移，覆盖对照记入单份 Plan：原位置、原风险、当前契约、修改后用例／替代位置、结果。解除阻断后的新增失败也纳入相同范围对账。
4. 请求形状、ID、revision、权限、幂等重试、权威回读、迟到响应隔离和 Mock 零 API 等原有仍有效的断言继续成立；已退役能力改测安全不可用／替代入口。
5. 普通并发下通过；时间用例不依赖宿主机 TZ。对原偶发用例做有界复测并记录次数及环境，单次通过不能宣称消除不稳定性。
6. 产品代码无改动；若发现阻塞完成的真实产品缺陷，明确记录未完成责任，不将放宽断言作为修复。

## 7. 验证与交付责任

开发阶段按入口选择、共享 fixture 消费者和业务旅程运行最小有效测试子集；已有调查证据用于复现和成本估计，不当作修改后 PASS。

共享配置影响测试选集，因此先用 Playwright `--list` 核验合法模式、数量和搬迁去向，再运行对应子集。fixture 变动通过真实浏览器执行 consumer，不能只检查 JSON 外形；用例原失败即已有失败证据，不另造一套镜像测试证明改测试本身。

最终责任为两个功能入口覆盖的合法选集、18 场景采集及修改代码适用的静态检查。两入口若重复覆盖可按明确选集组合验证，但必须保留两个普通命令可启动及路由正确的证据；不得在没有配置、fixture、运行时一致性证明时复用 PASS。具体去重与命令由获批后的 Plan 冻结，不机械前后各跑一轮全量。

本任务测试使用 intercepted Backend，不证明真实 BFF／STG 行为；不触及生产边界时真实后端 L3 为 none，不部署、不请求真实账号。若后续批准扩大产品范围，则重新计算边界与验收责任。

本次 planner 仅交付一个 Spec、一个经过异构文档审查的零上下文 Plan，以及一个含 Claude Code／Codex 两节的执行 prompt。实施由用户手动启动的新 session 完成，遵循 development-workflow 的实施 review 和 final gate；规划不自动实施或合入。
