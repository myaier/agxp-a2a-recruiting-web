## 5. 运行前置与业务边界

每轮先确认新 operator、前端/后端版本、preflight 能力 1、独占状态和日志/证据位置。后端 Python 依赖缺失时走其 `tools/dev-env.sh exec -- <原命令>`，不临时安装框架，不启动本地业务服务。

前端使用 `VITE_DATA_SOURCE=backend VITE_BACKEND_ENV=stg npm run dev -- --host localhost --port 5173 --strictPort`，浏览器固定访问 `http://localhost:5173`。确认代理上游为线上 STG，5173 被他人占用时不杀进程或随意换 Origin。

两个角色各有独立具名 agent-browser 会话。登录材料以受限进程与工具安全输入通道交接，不出 shell 明文 argv、聊天、日志、截图或录像；实际工具不支持时记录具体阻塞，不绕过。

准备流程复用 `validate → prepare --config → verify`。业务阶段全部通过真实 UI：上传合成 PDF、同意解析、等待真实解析成功、点名准确版本及当次披露、发起委托、处理本人待办和确认意向。环境操作是唯一准备/收尾例外，不直写业务 API、SQL 或模型结果。

本次 PDF 只为新匹配 Suite 的明确需求进行探索取证，不运行旧 B02 Suite，不宣称替换/解析全部分支已覆盖。若上传、解析或准确版本披露本身失败，保留真实失败并 cleanup，不用占位 PDF、预置解析结果或手填替代原件责任。

允许正常刷新推荐以找到本轮指定双方；只操作可证明属于本轮的岗位和候选。目标未出现则在预算内观察并调查，不随便委托其他 STG 用户，不注入推荐结果。不得使用收藏/不感兴趣/拒绝、订阅、Agent 规则、保存为规则、助手聊天、导出、反馈或举报；这些不属于当前最小业务路径及清理支持范围。

## 7. 探索、稳定性与失败语义

实施安排至少两轮双向探索，每轮两个 Case 各用新 run、顺序执行，完成上一 run 的 cleanup 后才开始下一个。第一轮发现入口差异、缺失事实与真实等待；第二轮验证收敛后的材料和流程能在新身份复现。每次配置修改都记录版本与原因，不删除先前失败。

稳定性完成标准：两个方向均须在相同最终 YAML/PDF 与流程版本下取得两个独立 run 的业务、清理和隔离通过；前期材料变更使旧证据不适用时，只补受影响方向。正式 final gate 再对最终选集执行，探索证据单列。总计最多三轮探索（六个 run）；仍不收敛则记录失败及原因，请用户决定后续调查，不无限运行直到碰巧通过。

每次运行前记录有界预算：普通 UI/持久化读回单节点 30 秒；PDF 解析或模型阶段单个异步节点 10 分钟；从发起至会话可达的业务观察总预算 40 分钟。预算是执行约束，不是产品 SLA，不延长服务端 deadline。后台工具采用短窗口跟踪同一进程；用户等待期间持续更新，不因一次工具超时重启 Case。若已有环境合同规定更短限制，采用更短值。

`PASS`、`FAIL`、`BLOCKED`、`NOT_RUN` 沿用现有 dogfood 语义。模型判不匹配或信息不足即本 Happy Case 未通过，记录具体事实；不能把“终态合理”计成 Happy PASS。等待耗尽记录最后状态，无法归因则标明原因未定；不把所有模型失败都归环境阻塞。工具 refs 过期可重新观察恢复，真实产品失败不能靠 API 补写、重复发起或放宽断言抹掉。

前端范围内、维持既有产品合同的必要修复可纳入实施 Task 并补相应本地回归；发现新的后端缺陷或需要改变产品行为时保留证据、先 cleanup，再向用户说明边界，不自行部署或扩大到跨仓库实现。

## 8. 清理、保留与跨轮隔离

无论成功、失败、超时或中断都对同一 run 履行 finally cleanup。持续记录 run/receipt/服务和浏览器归属，恢复时先读 status 和原回执，不换 ID 绕过未完成清理。

合法 retained 仅按新后端固定 kind/count/reason 接受；不要求删除全部 Case 历史、冻结主体锚点或空会话。当前 residual 必须为空且 retained 对账一致、旧身份不可用、占用释放。若仅 Hub 工作未终结，沿 operator 自身预算收敛；后续同 run 有界重试仍保留每次结果。未知/foreign/含消息等阻断不得擅自重分类，不 reset、不强制解锁、不手工 SQL。

清理结束后利用受限原 Cookie 做有界正常认证只读核验，确认 401；旧登录材料不可重建会话的核验按后端支持的受限通道执行，不公开材料。浏览器会话关闭前保留必要的受限核验材料，完成后按合同销毁。只停止本轮自建服务和会话。

相邻独立 run 的隔离检查复用当前后端 README：新 owner 列表与推荐、Case/进度/任务投影、通知及会话入口不出现旧结果；旧组织公开读不可见；新身份按对应角色合法读入口访问旧 Case、附件、评估/投影、会话 ID 被拒。由浏览器观察真实页面，必要时以同角色只读 API 补充。不存在某种旧资源时写不涉及，不制造资源凑覆盖。

迟到任务围栏的确定性证明引用后端已有 L2 责任，浏览器只能观察是否出现异常，不声称一次“没看到”证明全部并发安全。不删除历史残留 run，也不因 status 列出已退休历史而误报当前占用。

## 9. 本地基线修复与最终责任

首先保存当前分支的静态、单元、全部唯一功能浏览器与视觉结果；只跑同一原生命令一次，不把 alias 当第二份覆盖。功能浏览器沿用固定 workers=4、retries=0。历史四例先定向复现定位，再保持原风险断言修复：目录选择真实 ID、首次意向唯一、读取失败恢复、头像未知结果不伪成功等不能删减。

两类疑似竞态通过可控异步时序验证；成立时做最小产品修复和能击中原故障的回归，不成立时记录证据并修正已知事项，不添加猜测性防护。禁止固定 sleep、宽泛 route 兜底、自动重试、加超时或删除 Case 取得绿色。

最终本地责任为全量 `npm test`、`npm run test:e2e -- --workers=4 --retries=0`、typecheck、lint、build、清单 `--check`，以及既有视觉入口的 18 场景采集/比较与实际变更影响的展示检查。全量要求来自用户此次明确要求本地基线跑绿，不能用旧 Plan 的受影响子集替代。实际选集随 runner 收集，不以历史数量为硬编码断言。

视觉比较使用任务开始时冻结的前端基线和同一采集口径；不更新像素基线掩盖变化，也不以只采集成功冒称比较通过。必要产品修复引起可见变化时单列差异解释，涉及新视觉决策交用户确认。已有有效证据可按工作流条件复用，不在 review 前后机械全量重复。

本地 raw 证据放 `test-results/` 下本任务目录，必要时暂存在本次专有临时目录避免 Playwright 清空；真实浏览器证据放 `dogfood-output/<run-id>/`，均沿既有忽略规则。报告从执行开始持续写，业务、基础设施准入、cleanup/隔离分别给出 verdict。只在长期文档登记脱敏摘要，不新建报告平台。

## 10. 完成标准与非目标

交付完成需同时满足：本地基线所有责任真实通过；Suite 两条 Case 能独立选择；专用 YAML/PDF 版本受控且一致；探索达到 §7 的稳定性标准；正式选集双向验收到 A 终点；每个已创建 run 都已收尾且隔离证据成立；索引、指南和报告模板一致。只完成设计、环境准入或其中一个方向不称整体完成。

本次不做旧 STG Suite 回归、真人消息收发、随机负向模型场景、岗位/候选池规模测试、模型质量评分、全库类型化、通用自动点击框架、后端开发/部署、数据库清空或发布流程改造。只有新 Case 的实际失败证明现有能力不足时，才提出对应扩展，不在 Plan 自行加入。

当前仅完成规则/源码/历史证据调查与环境只读检查。本次基线测试、配置/PDF 创建、探索和正式匹配均尚未执行。Spec 获批后由 planning owner 编写 Plan 并组织文档 review；实施会话承担修复、探索、代码 review 与最终验收。
