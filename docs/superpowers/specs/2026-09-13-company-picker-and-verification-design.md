# 七类公司选择入口统一与企业认证接线

日期：2026-09-13。版本：v1.0。状态：用户于 2026-09-13 批准 v1.0 并要求零上下文 Plan、Claude review 与执行提示词；进入规划，尚未实施。批准内容快照：revision `4b4edad965ef89e6a59a9927cacab3a94cdbdf37`，blob `1aeb99dc03fb2ff343a3fd10cb67a7771aace7d1`。

## 1. 目标与依据

让用户在七类页面中通过同一个底部抽屉搜索、添加并选择企业，业务保存使用后端企业目录 ID；招聘者可以随后申请成为所选企业的管理员。

前端基线：`5fca5f7a30376c962bd89f3e2afa5e46cab47421`。后端调查基线：`agxp-monorepo@e2c40ef2ec6cdc8ca5228add4a83d5dde0deb684`（`release/0.2.5`）。工作区为 `.`，本任务只修改前端仓库。后端 checkout 由执行环境定位，不绑定规划机器路径。

遵守 `AGENTS.md`、`CLAUDE.md`。后端合同来源为 `apps/recruitment-bff/openapi/mobile-v1.yaml`，已核对公共路由、内部 mobile API 及 organization/job/resume 领域实现。源码存在不代表运行环境已部署，本轮未做运行环境验收。

用户已确认七类入口、底部搜索抽屉、复用现有组件，以及邀请加入和公司档案编辑使用预先确定的企业。历史契约中企业仅可从已认证关系推导、经历只写公司文本、管理员申请提交 display_name 的限制，在本范围内由当前后端合同替代。

采用具体的公司选择层，加现有页面各自的数据与保存控制。七处存在真实重复，因此共享搜索、添加、选择交互；不建立万能表单或目录框架。优于新增全屏路由（需要额外返回与草稿交接），也优于在七个表单内分别铺开搜索结果（重复状态处理、挤动原布局）。

## 3. 组件与交互

### 3.1 复用边界

- 直接复用 `src/组件/弹层框架.tsx` 的底部定位、关闭与键盘操作。
- 沿用 `src/组件/简历行业选择正文.tsx` 的抓手、标题、滚动列表、选中勾版式及现有样式。
- 从 `src/组件/教育目录候选列表.tsx` 提取实际共用的候选行和分页展示，保留教育消费者的原行为；公司副文和认证文字由公司外层提供，不让教育组件承担企业逻辑。
- 复用 `src/屏幕/组织查询钩子.ts` 的防抖、分页、去重和请求代际机制；移出屏蔽来源前置条件，来源归屏蔽页面所有。
- 共用展示只接收展示值、选中／忙／错误状态与回调；真实请求、账户隔离、幂等及业务保存仍在现有外层。
- Mock 和 Backend 使用同一套公司选择展示。Mock 使用本地模拟目录与操作，不向后端发请求；不模拟审核后台，不把本地 ID 送入真实接口。

现有弹层 effect 依赖关闭回调，公司选择层保持其回调稳定，验证连续输入和中文输入法不被焦点恢复打断；只有实际验证证明现有骨架不能满足本交互时才最小修复，并覆盖已有消费者。

### 3.2 搜索与选择

表单公司行显示当前企业常用名，未选时提示选择。打开抽屉展示标题、搜索框、结果与底部添加入口。输入非空后按现有 250ms 防抖搜索，空输入提示输入公司名称，不虚构热门企业或拉取全目录。

结果主行显示常用名，正式名存在时显示副文，明确展示已认证／未认证；不把企业已认证解释为用户已认证。选中以 ID 判断，不按名称反查。点击已有企业即关闭并回填父页面待保存值；取消或遮罩关闭不改变原值。

分页增量加载，保留当前选中；词变化清理旧查询结果与游标，迟到请求不能覆盖新词或新账户。首次搜索失败显示重试，不能假称“没有企业”；分页失败保留已加载结果并可重试。

### 3.3 添加

抽屉提供“添加新企业”，在同一抽屉内切到名称输入，预填搜索词；用户可返回搜索。名称遵守后端去首尾空白后的 1–80 Unicode 字符及控制字符限制。

“添加并选择”才调用创建接口。创建成功或同名复用后，使用响应企业回填并关闭。显示“添加企业不会自动获得管理员权限”；不增加第二层确认框。创建在途禁用重复提交，同一尝试的重试沿用现有 HTTP 幂等纪律；失败保留名称和错误。用户离开后迟到结果不能改写别的页面或账户。

添加是已明确触发的独立目录写入：即使用户随后取消父表单，目录条目仍存在；不自动删除共享条目，也不自动选择到其他业务资源。

## 4. 各入口的数据归属

### 4.1 招聘名片与认证

招聘名片保存 `organization_ref`，属于自报公司选择，与当前可管理 affiliation 分离。选择未认证公司不要求管理员权限；已有成员关系列表继续诚实展示，不能因为新选择产生或提升成员身份。

实名认证页默认展示招聘档案已保存的自报企业；在该页更换是待申请企业的本地选择，进入管理员申请携带这一 ID，不隐式修改招聘档案。管理员申请直接进入时默认使用档案企业，没有则要求选择。路由携带的 ID 必须经过真实读取验证，不信任携带的认证状态或名称。直接访问、刷新均有可用的选择入口。

申请页保留正式名、登记标识、说明、域名与证据；不再把常用名作为认证请求的可写字段。域名允许空数组，遵循后端而非旧前端强制至少一个的校验。企业切换时清理上一企业的申请表单与证据；取消选择不清理原表单。

已提交申请绑定的企业不可更换；查询、取消针对原 request_id。新的待申请选择不得改写已有申请。提交返回 pending 或 approved 均按服务端展示，approved 后刷新关系和对应企业事实；不能凭提交成功直接标为管理员，也不能固定承诺人工审核时长。

邀请加入仍由口令固定企业。公司档案编辑仍按明确选定的可管理关系进入，不能用新的自报企业 ID 覆盖管理目标。这两页不新增选择器，只核验本次状态拆分没有影响其权限边界。

### 4.2 岗位

新直招岗位默认使用档案已保存的企业，表单允许更换；一个选择同时产生相同的发布方与用人企业 ID。代理岗位使用两个明确选择，发布方可预填档案企业，用人企业需明确选定；不把客户公司当成申请人任职企业。

保留既有发布模式来源，不为本任务新增招聘身份体系或无关模式切换。编辑从岗位本身的两个 ID 恢复，不能拿当前名片覆盖既有岗位；保存时提交实际选择。岗位企业更换不回写招聘名片、经历或其他岗位。

未认证企业允许选择和保存；不以企业认证或管理员身份阻止本次目录及岗位 CRUD。保持岗位所有权、结构化确认、revision 和其他真实发布条件。

### 4.3 工作经历与解析预填

每条经历保留真实 `organization_id`，名称用于展示服务端快照。解析或旧草稿的公司文本只预填搜索词，不自动匹配首结果、不静默创建。缺少 ID 的条目保留可见内容并提示选择，在会提交该条目的保存路径上阻止无效请求；不得跳过条目导致整份简历保存时丢经历。

日常编辑与 onboarding 保存链均携带 ID；其他技能、教育、项目等分区保持原归属。既有已关联经历无需重复选择。

### 4.4 屏蔽

屏蔽名单保留当前雇主／关联公司／手动添加三种来源。选中或创建企业后仅回填，点击“屏蔽”才写隐私；引导问答的“再加一家”则在选择完成后执行该明确的添加屏蔽动作，成功后才展示 chip。

一键屏蔽只对简历中真实关联的企业 ID 去重执行，沿用来源规则和逐次最新隐私 revision。存在未关联公司文本时先提示补齐工作经历选择，不静默忽略或按名称屏蔽。部分成功按返回权威状态显示，失败可重试，开关不能假称全部成功。关闭／解除沿用原有当前雇主与关联公司风险确认，不能由一键开关绕过。

## 5. 后端合同与错误

以下公共路径统一以 `/api/v1` 为前缀：

| 操作 | 合同 |
| --- | --- |
| 搜索 | `GET /organizations?q=…&limit=…&cursor=…`，候选／招聘角色均可用 |
| 创建 | `POST /organizations`，body 仅 `display_name`，带 Idempotency-Key |
| 搜索项 | `organization_id, display_name, legal_name: string|null, verification_status: unverified|verified` |
| 创建响应 | `{organization, created}`；201 新建，200 复用／重放 |
| 招聘档案 | `GET/PATCH /recruiter/profile`；PATCH 使用 If-Match 和 organization_ref |
| 岗位 | 原创建／更新接口携带 publisher_organization_ref、hiring_organization_ref；名称快照由后端生成 |
| 简历经历 | 原简历保存接口的 experiences 项写 organization_id，不再写 company 文本 |
| 认证申请 | `POST /recruiter/organization-admin-requests`；multipart metadata 为 organization_id、legal_name、registry_key、explanation、domains，另附 1–5 个证据文件 |
| 状态 | 原申请列表／取消、recruiter/affiliations 与企业读取接口 |

认证证据每份最多 10 MiB，支持 PNG/JPEG/PDF。写操作保留现有 Origin、会话、幂等与版本控制，不重复建立 HTTP 层。

同步实际消费者的严格 DTO 校验，接受未认证企业 legal_name=null 和认证状态新字段。创建同名复用不覆盖企业资料。名称停用冲突、字段无效、选择失效分别显示可操作错误；409 版本冲突重读权威值且不静默覆盖用户选择，401 走既有会话清理。错误不回退 Mock，不造成功或管理员身份。

## 6. 非目标与延后

不实现审核后台、自动合并企业、工商查询、企业删除、全目录预加载、历史推荐、邀请目标改选或公司档案编辑内切换企业；不改后端自动批准配置。只有实际新增需求或后端契约缺口才重新评估。

不全面重构推荐／初筛认证门槛、企业管理架构或所有展示页面；只校准七类入口及它们直接读写的企业事实。若发现范围外阻断完整推荐链路，应明确报告，不暗中扩张本次任务。

不新增持久化兼容双轨或数据库迁移；已有前端草稿按原机制适配 ID，不能清空用户内容来规避。除共享组件实际受影响者外，不重排其他页面。

## 7. 验收与验证责任

1. 七类入口都可打开同一选择层；注册／日常编辑、Mock／Backend 的对应交互复用同一展示。
2. 搜索、分页、中文连续输入、选中、取消、创建及同名复用可操作；错误有重试且不产生虚假选择。
3. 网络请求中使用真实 ID；重载后档案、经历、岗位从服务端恢复，不依赖本地公司声明。
4. 两个代理岗位企业不混淆；编辑不受后来名片选择影响；直招两个 ID 相同。
5. 认证申请准确绑定目标企业；企业已认证不等于用户管理员，邀请／管理目标不会被自报选择覆盖。
6. 屏蔽必须以真实 ID、正确来源和最新 revision 执行，部分失败与解除风险诚实呈现。
7. 验证过时请求、重复点击、创建重试、取消父表单、切换企业后旧证据、账户切换、未认证企业及缺 ID 草稿等失败反例。

实施阶段优先使用现有 Vitest 的组件／状态／HTTP 合同定向测试，补充能证明上述真实风险的用例；对提取的候选列表覆盖教育旧消费者。运行 typecheck、lint 与 build；具体文件和最小命令由 Plan 冻结，不新增测试平台。

浏览器验收覆盖七类入口及小屏软键盘／抽屉滚动、返回和焦点。真实后端验收沿 `docs/dogfood/真实后端行为验收.md`，注册路径参考现有 onboarding 验收指南，选取相关 CRUD 与账号隔离责任；不自动执行全量 Hosted 或 STG。正式执行所需目标 URL、部署版本、账号来源、环境归属与清理在实施 session 的 final gate 具体化；缺前置记未验证，不能以源码检查替代行为证据。
