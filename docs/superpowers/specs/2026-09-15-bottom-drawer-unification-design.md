## 1. 目标与依据

统一 onboarding、简历编辑、求职意向编辑、岗位发布及编辑中薪资、日期、年份和实习数值字段的底部选择组件，修复抽屉打开时背景先上移、再回到原位的问题。

调查基线：`eeaead9abadfd1e87c4abda19fd3de5a6a66af63`。遵守 `CLAUDE.md`、`AGENTS.md`，按 development-workflow 交付一份 Spec、一份获批后编写的 Plan，以及文档 review 后生成的一份双宿主执行提示词。本规划 session 不实施产品。

用户已确认：

1. 全屏目录选择由另一个 session 负责，本任务只负责底部抽屉。
2. 相同字段在所有现存编辑入口使用同一个组件，覆盖 Mock 和 Backend；只共用 CSS 或滚轮 hook 不算完成。
3. onboarding 的薪资、出生年月、就读时间也改为点击字段打开底部抽屉。
4. 实习月数、每周到岗天数一起统一为抽屉，保留各业务入口允许的取值范围。
5. 薪资统一组件和交互，但保留各入口的面议、动态上限、档位和校验规则。
6. 本轮先完成规划，实施由用户后续手动启动新 session。

相关历史合同：`docs/superpowers/specs/2026-09-14-picker-interaction-consistency-design.md`。本文仅覆盖其中以下冲突要求：日薪/时薪保持原控件、就读年份常驻页面且用户滚动即时写草稿、出生年月不调整。对应新行为分别为共用薪资抽屉、年份区间抽屉确认后写草稿、出生年月抽屉。该文档其他业务与数据合同继续适用；不恢复已删除入口，也不扩大其历史任务范围。

## 2. 问题与调查证据

### 2.1 重复实现

- `src/屏幕/引导问答.tsx` 自行渲染薪资双轮；意向和岗位月薪使用 `src/组件/薪资区间层.tsx`；岗位日薪/时薪分别打开下限、上限数字抽屉。
- `src/屏幕/学生分流.tsx` 与 `src/屏幕/添加意向.tsx` 各自组合弹层框架和内嵌双滚轮选择预计毕业年月。
- `src/屏幕/基本信息.tsx`、`src/屏幕/就读时间段.tsx` 将双滚轮常驻页面；简历教育、工作及实习经历使用 `src/组件/年月滚轮层.tsx`。
- 学生分流和意向表单用标签选择实习月数、每周天数；岗位表单已经使用 `src/组件/数字滚轮层.tsx`。

### 2.2 背景跳动根因

`src/组件/弹层框架.tsx` 挂载后立即 `.focus()` 首个内部控件；抽屉 CSS 同时从 `translateY(100%)` 向零位移执行约 240ms 入场动画。控件尚在屏外时，浏览器为显示焦点而滚动外层页面。`overflow: hidden` 没有阻止这种聚焦触发的程序滚动。动画推进使可滚动溢出缩小，外层滚动值回到零，造成背景先上移后复位。

在“添加求职期望 → 薪资要求”的 Chrome 浏览器实验中：

| 布局 | 原始代码 | 临时对照：弹层内部聚焦禁止带动滚动 |
| --- | --- | --- |
| 390 × 844 | 页面外壳 scrollTop 从 0 到 236，再到 0 | 始终为 0，标题位置不变 |
| 1280 × 900 桌面手机外框 | 页面外壳 scrollTop 最大 270，随后回到 0 | 始终为 0，标题位置不变 |

对照仍将焦点移入“取消”按钮，保留原动画。临时回归用例在原始代码上失败、局部修复后通过；误启动的实施已停止，产品修改与新增测试均已撤回。上述记录只作为根因调查证据，不能作为未来实施提交的验收结果。真机软键盘和 iOS Safari 尚未验证。

## 3. 范围与最终组件归属

“所有页面”指下表现存字段的全部消费者，包括同一页面承担的 onboarding、日常新增和编辑，以及 Mock / Backend；不指把应用内所有弹窗改造成字段选择器。

| 字段 | 页面 / 流程入口 | 目标共用组件与变化 |
| --- | --- | --- |
| 薪资区间 | 引导问答；添加/编辑求职意向；招聘 onboarding、应用内发布/编辑岗位 | 全部使用 `薪资区间层`；引导内嵌双轮改抽屉；岗位日薪/时薪改一次打开上下限双轮；已有月薪入口接续使用 |
| 出生年月 | 基本信息（候选 onboarding、日常基本资料编辑） | 点击字段打开 `年月滚轮层` |
| 预计毕业年月 | 学生分流/完善资料；添加/编辑校园招聘意向 | 两处删除页面自组抽屉，使用 `年月滚轮层` |
| 入学/毕业年月 | 在线简历教育经历编辑；“我的简历”跳入同一编辑入口 | 继续使用 `年月滚轮层`，作为共享消费者验证 |
| 入职/离职年月 | 在线简历工作/实习经历编辑 | 继续使用 `年月滚轮层`，保留至今/未结束的外层业务表达 |
| 就读年份区间 | onboarding 就读时间段 | 点击字段打开薄的年份区间抽屉，内部复用 `内嵌双滚轮` 与 `弹层框架`；保留入学年、毕业年两列 |
| 开始工作年份 | 基本信息 | 继续使用 `数字滚轮层` |
| 年薪月数 | 发布/编辑岗位的既有入口 | 继续使用 `数字滚轮层`；不为意向新增年薪月数采集 |
| 实习月数、每周到岗天数 | 学生分流；添加/编辑实习意向；发布/编辑实习岗位 | 全部使用 `数字滚轮层`；求职侧标签改选择行；岗位保留数值入口 |

年份区间与单个年月属于不同精度、不同值结构，不把二者强塞进一个“日期万能组件”。就读年份区间是现有的两个相关字段，新增薄抽屉只负责临时状态与确认；不复制一套滚轮实现。

公司选择的形式不调整。共享 `弹层框架` 的修复自然影响公司、行业等其他现存弹层，必须检查相关消费者，但不修改这些选择器的内容、业务或全屏归属。

## 4. 方案与工程取舍

采用“扩展既有具体组件 + 页面传入业务规则”的最小方案。

- 只统一弹层外观，保留各页自写的正文与状态处理，无法满足同字段同组件要求。
- 重写全站通用 picker、全局弹层管理器或 schema 驱动表单，会扩大接口和维护成本，当前没有必要。
- 既有薪资、年月、数字组件已覆盖大部分需求。新增能力只包括现有消费者确实需要的离散数字档位、薪资业务策略，以及承载既有年份区间的薄抽屉。准确 props 和文件名在获批后的 Plan 冻结。

共用展示与控件不读取数据源模式、不调用后端、不访问业务 Context。页面或现有适配层拥有输入值、规则、草稿与保存动作；通过显式参数表达业务差异，不以“Mock/Backend”选择两套 JSX。不按 URL 在组件内部识别业务规则。

允许删除替换后无消费者的页面滚轮 JSX、样式和临时状态。不顺便重排其他字段、重写页面状态架构或清理无关代码。保留现有底部抽屉视觉与滑入动效，高度按内容和可用空间决定，不固定为屏幕的 50%。

## 5. 所有本轮字段抽屉的交互合同

### 5.1 进入、选择与退出

1. 页面显示字段名称、当前值或未填写占位；点击才打开抽屉。未填写字段不能在父表单中显示成已确认的默认值。
2. 顶栏为“取消 / 字段标题 / 确定”；确认文案统一为“确定”。沿用现有尺寸、圆角、遮罩与滚轮选中态；不新造样式主题。
3. 打开时从父值创建本次临时状态；滚动、键盘、点击档位只改临时值。初始化和滚轮程序定位均不算用户确认。
4. “确定”按该业务的既有规则处理并一次回填本字段的完整值；区间上下限或年份对不得分两次持久化成半个状态。业务状态更新后关闭；本地抽屉不直接发保存请求。
5. “取消”、遮罩、Escape 均丢弃本次临时编辑，父值、确认标志、持久化草稿和其他字段保持不变。重新打开从父值初始化，不恢复已取消值。
6. 父页“保存/下一步”的职责和既有网络失败恢复保持；抽屉确定不等于整张表单提交。原字段确认会触发现有业务保存的入口继续由页面处理，控件不接管网络事务。
7. 不新增路由或 history 项；浏览器后退沿页面既有路由离开行为，不新增跨路由草稿存储。因页面卸载而消失的未确认抽屉不回填。
8. 只读、不可编辑、业务条件不满足的入口继续遵守原限制；不因共用组件而开放编辑能力。

### 5.2 焦点、布局与动画

- 在共享弹层首开聚焦时禁止浏览器自动滚动外层；优先使用已验证的 `focus({ preventScroll: true })`，保留焦点进入及原动画。
- 关闭恢复焦点也不得移动背景；原触发元素仍连接且可聚焦时恢复，否则不强行滚到失效节点。
- Tab / Shift+Tab、Escape、滚轮方向键与首尾键保持可用。不能为了背景稳定把长列表内目标焦点藏在可视区域外；如需滚动，只作用于该弹层的内部容器。
- 不延时若干毫秒再聚焦、不先滚动背景再复位、不删除动画掩盖问题，不新增全局 body 锁滚系统。
- 入场、交互和关闭保持父表单滚动位置；滚轮滚动不带动外层背景。层内滚轮或内容区在短屏仍可操作，取消与确定可达。
- 岗位月薪“输入金额”模式保留；键盘弹起时输入和确认可达，不能因自动聚焦导致背景跳动。真机键盘表现需单独验收。

## 6. 业务规则保留合同

### 6.1 薪资

同一个 `薪资区间层` 承载不同业务规则与同一套实际双轮 UI；不能把原引导整套独立 JSX 包进去就宣称共用完成。

| 业务入口 | 必须保留的规则 |
| --- | --- |
| 引导问答月薪/实习日薪 | 现有默认/预填；0 表示面议，选面议回填 0/0 并隐藏上限轮；现有变步长档表、下限变化的上限联动、`算上限档表` 的动态带宽和近段加密；最大下限仍有可选上限 |
| 求职意向月薪/日薪/已有时薪周期 | 原默认、可选档位、单位与现有有效小数/大额值往返；确定时上限取 max 的现有规则，不改成岗位的报错策略 |
| 岗位月薪 | 原 0–100 K 常用档和当前有效整数补档；“输入金额”覆盖原 0–9999 整数域；现有超范围合法整数不截断；倒置在确定时报错且不关层，不静默交换或提高上限 |
| 岗位日薪/时薪 | 日薪 50–800、时薪 20–200，均步长 10；缺值临时落点分别沿用 200/40；保持原范围夹紧和最近档吸附规则，不新增精确输入或扩展取值范围；原字段值在取消时不受吸附影响 |

岗位日薪/时薪原来分别编辑上下限，现在两处金额入口打开同一个区间抽屉，确定时回填两值。其倒置校验继续由既有表单提交规则负责，允许保存中间编辑态到表单；不把月薪的抽屉内拦截新增到日薪/时薪。该差异以业务策略显式表达。

各策略的边界与代表样例在 Plan 对照上述基线源码及已有测试冻结，不借统一 UI 修改算法。`月薪K`、`元/天`、`元/时` 与 wire 金额倍率不变；面议、年度发薪月数、切换求职/招聘类型后的字段清理与序列化不变。保留合法已有数据的现有处理，不为 UI 改造新增后端协议。

### 6.2 年月与年份

- **出生年月**：范围保持 1970–2010 年、1–12 月。已有完整生日或可用完整预填可回显；Backend 未确认时父字段显示未填写，抽屉内部可沿用 1998/6 临时落点。只有确定才将完整年月标记为用户确认；打开、滚动后取消不会写入生日。保留 Mock 显式演示值、预填 eligibility、保存成功后确认分区等合同。
- **预计毕业年月**：学生分流与校园招聘意向复用同一年月组件，保持当前年起共 8 年、1–12 月和原缺值临时落点“次年 6 月”；意向已有年份补入可选范围的能力保留。父表单原“必填、不早于本月”校验继续生效，不改成打开抽屉自动补默认。组件上下界由调用方提供，不能误用简历的“最晚本月”默认限制。
- **简历年月**：教育、工作、实习的起止约束和既有默认、至今表达保持，由原页面继续传入；本轮不调整未来毕业时间等既有业务边界。
- **就读年份区间**：保留两列 2000–2030、各自可空“请选择”、解析预填过滤与 Mock 数据层 2021/2025 演示值。可确认单侧值或清空，父页继续显示未填项，下一步仍检查完整性与起止合法性；抽屉本身不提前替代此校验。确定时一次回填并写现有建档草稿，取消不写。非空年份仍按入学 9 月、毕业 6 月拼成原数据格式；不因改抽屉新增月份采集。明确覆盖旧“每次滚动即时写草稿”行为；确定后的返回/刷新恢复继续使用原草稿能力。
- **开始工作年份**：沿用 `数字滚轮层`，范围 1990 至当前年，原确认回填和保存归属不变。

### 6.3 实习数字和年薪月数

| 字段 | 求职 onboarding / 意向 | 岗位 |
| --- | --- | --- |
| 实习月数 | 离散档 `[1, 3, 6]`，父字段保留“至少 N 个月”语义 | 连续 1–24 个月 |
| 每周到岗天数 | 离散档 `[2, 3, 4, 5]` | 连续 1–7 天 |
| 年薪月数 | 不新增入口 | 12–36 薪 |

`数字滚轮层` 增加离散档表能力是为了现有求职侧范围，不能用最小/最大自动生成求职侧未开放的 2/4/5 个月或 1/6/7 天。原连续范围消费者保持原行为。

求职侧缺值仍未填写，打开时可暂落第一个可选档，确定才回填；取消后必填检查不能被绕过。已有岗位默认保留。组件不得为所有调用者新增默认持久化，也不得按数据源模式改变档位。

## 7. 状态、接口与并行边界

- 页面持有业务真值；抽屉仅持有生命周期内临时值。关闭后丢弃，重新打开读取最新父值。页内其他字段、步骤、上传/解析状态和滚动位置保留。
- 现有解析建议与建档草稿的资格判断、已确认标志、保存失败时序保持；迟到预填不得覆盖用户正在编辑的临时选择。
- 不改 BFF/API/schema、数据库、权限或发布配置；Mock 不发送真实写入，Backend 失败不回退 Mock。
- 本轮主要触点为 `弹层框架`、`薪资区间层`、`年月滚轮层`、`数字滚轮层`、必要的双轮展示能力和年份区间薄组件，以及第 3 节列出的页面接线。
- 全屏任务可能同时涉及 `发布岗位.tsx`、`工作经历.tsx`、`添加意向.tsx`、`引导问答.tsx` 等文件。本任务不拥有整份文件，只改本文列出的数值/日期区域及必要 import、状态、样式和测试。实施前按 development-workflow 核对改动预告与最新基线；不覆盖另一任务的目录选择代码，也不代其完成全屏改造。

## 8. 验证与完成标准

复用现有 Vitest、Playwright、类型检查与 lint。Plan 冻结定向测试文件与命令；本规划阶段不为填表重跑测试。最终验收必须同时检查代码中的组件调用和实际交互，不能靠组件名文本搜索或旧测试全绿代替。

| 边界 | 必须证明的结果 |
| --- | --- |
| 覆盖完整 | 第 3 节每个入口映射到目标组件；同入口 Mock/Backend 共用 JSX；所有被替换的页面独立滚轮不再参与产品渲染 |
| 事务 | 打开/调整/取消零回填；确定完整回填一次；重复打开读取父值；上下限/年份对不产生半更新；其他字段与滚动位置不丢 |
| 薪资 | 面议 0/0、动态上限、上下限最高档、日/时薪步长与吸附、意向小数/大额、岗位精确输入/倒置、单位倍率与切类型序列化均保持既有合同 |
| 年月 | 出生缺值/已有值/建议值/取消/确认；预计毕业跨年与过去月份校验；简历起止边界、年变更后的月份约束与至今不回归 |
| 就读年份 | 空值、单侧值、显式演示值、有效/越界建议、清空、倒置；取消不写草稿，确定一次写双值；下一步保存失败不确认分区、不跳转 |

## 9. 非目标与延期

- 城市、学校、专业、职位类别、行业的全屏改造由另一 session 负责；公司选择保留当前形式。

- 不为求职意向增加年薪月数入口，不恢复已删除的最早实习日期等字段。
- 不新增全局弹层系统、状态库、路由、草稿服务、配置开关、虚拟列表或通用表单引擎。只有现有实现无法解决的真实布局/性能证据出现时才另行设计。
