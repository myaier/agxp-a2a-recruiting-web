## 2. 入口、正常路径与结束边界

[I] 新候选选择求职身份后进入 `/student`；现有登录恢复可能直接进 `/app`，并未判定建档是否完成。[C] 同标签页有本轮草稿时恢复中断步骤；退出重登／换设备的未完成者可从头重走。[E] 完成识别与既有资源复用的最小实现仍需核实，不建立跨设备步骤系统。不能据“有候选角色／有头像／列表有一条意向”独自判定完成。

[I/E] 按现状及最小改动方向保留学生／社招题序，不新增页面或向导框架：

- 学生：完善资料 → 基本信息 → 学历、学校、专业、就读时间 → 经历 → 求职状态 → 偏好问答 → 披露说明 → 头像 → 首页。

**已确认的完成边界 [C，D01]**：PDF可选，允许全程手填；头像可选；资料与首次意向保存成功后即可进入首页，暂无推荐或推荐加载失败不影响建档完成。学生和社招均允许“暂无工作／实习经历”并继续；用户填写经历时，才校验该条目的必要字段，不要求为完成建档编造经历。教育经历至少填写一条，必填学校、学历、专业、入学时间和毕业时间；仍在读填写预计毕业时间，不要求已经毕业。Summary可编辑、可手填或使用解析建议，也可留空，不阻塞完成。排除卡片可全部不选，自定义私有诉求可留空；表示没有额外提出排除要求，不代表接受所有工作条件，不阻塞建档。

**其余字段与完成实施约束 [I/E]**：已确认的可选／必填规则优先；其余页面沿现有校验，不顺手加要求。例如姓名非空、求职身份／机会类型／办公方式／城市职位目录引用及类型相关字段沿现有入口；生日未确认则不虚构写入，技能／证书不新增最低条数。以当前主体已保存资源核实完成，关键写入结果未知不报成功，已保存部分不假装回滚。不新增整体事务、匹配成功门槛或说明确认的服务端签署流程。具体完成识别方法由实施核实，不默认增加完成API。

## 3. 数据与状态分开表达

本旅程没有双方 Agent 对话；Agent／模型的用户可观察工作主要是PDF识别及形成待核对建议。[I/E] 沿用页面加载、结果与错误呈现，不新增虚构聊天、工具调用流水或内部推理状态。

| 状态层 | 事实／页面状态 | 用户应理解的意思与边界 |
|---|---|---|
| UI | 正在上传、正在保存、返回中、弹窗打开 | 仅描述前端动作，不能据计时器证明业务成功 |
| 文件 | 上传未确认／已确认的文件版本 | 收到成功并能核实来源才有确定文件；与解析完成分离 |
| 解析[I] | not_started | 未开始解析；不意味着文件不存在 |
| 解析[I] | pending | 服务端正在等待处理；可能含内部自动重试等待 |
| 解析[I] | processing | 正在处理PDF，不承诺真实百分比或完成时刻 |
| 解析[I] | succeeded | 对准确版本解析成功；不是建议读取成功，更不是资料已保存 |
| 解析[I] | failed | 本轮解析失败；不等于用户资料无效或无法手填 |
| 建议UI[P:D09] | 正在读取／可供核对／暂时不可用／本轮不再使用 | 区分模型已完成与浏览器取得建议，勿把GET失败说成模型失败 |
| 资料[P:D02/D03] | 未保存草稿／已确认保存／部分保存／结果待核对 | 按分区／资源保留事实；“下一步”不天然等于全部内容已保存 |
| 旅程[P:D01] | 建档中／符合完成条件 | 产品判定，尚未决定是否新增持久字段；不能先造一个后端总状态机 |

[I] 后端内部有attempt、lease及重试预算，它们不是用户状态。[E] 沿用真实状态和现有入口，不能把内部120秒或3次尝试变成端到端SLA；本草稿不提出完成时间保证。

[P:D03/D09] 解析和保存失败提供事实性提示，样例“识别暂未完成，可继续等待或手动填写”“部分资料已保存，剩余内容未保存”“正在核对是否保存成功”。样例不是定稿文案，也不代表已实施。

## 4. 解析建议、资料确认与私有诉求

### 4.1 PDF到本人资料

[I→P:D09] 建议始终绑定准确文件、版本和解析结果；换文件／版本、换主体／角色后，旧建议不能进入新表单。只在本轮明确激活预填后读取，已有附件不自动等于本轮选择。[C] onboarding只处理一份PDF；中断重来时显示已上传的这份，用户可继续使用或主动替换。无需多附件选择器；注册后最多3份的管理属于其他旅程。复用已有附件作为本轮预填来源需要前端接线，不新增跨次进度恢复或临时文件转正机制。

[I→P:D03/D09] PDF解析不自动改写在线简历。建议用于空白字段；已有服务端值和本次手填优先。列表不按下标猜测合并，解析无法确定的目录值不伪造ID。缺失或有歧义的结果可让用户补齐后确认；具体页面必填见D01。

[C] 至少一条教育经历，填写学校、学历、专业、入学时间及毕业时间；仍在读填写预计毕业时间。[I] 学历、学校、专业、时间分屏期间可能暂不构成合法教育条目。当前部分“下一步”只保留本地不完整条目，刷新可丢。[P:D02/D03] 页面必须区分草稿与已保存；不能为让每页请求成功而捏造学校、专业或日期。

[C] 本轮明确区分两项：“个人优势／自我介绍”Summary可以编辑、手填，也可采用解析建议；允许留空，不阻塞建档。Highlights优势标签只能来自简历解析，用户不可编辑，以简历依据为产品意图；不能承诺模型输出天然公平或无误。[I] 后端独立标签资源目前允许修改文字，这不自动授权前端开放编辑。[C] Highlights仅招聘者可见，onboarding与候选人简历页均不展示；不可编辑语义已确认，不再与Summary混用。招聘者在何场景可见仍受既有披露／角色权限约束，此项不授权提前披露。[I] 补充核查确认当前招聘展示必须有候选PUT确认，自动解析不会自动发布。[C，B02-H01] 取消候选确认前置，解析生成的Highlights无需候选人确认，直接按既有隐私权限供招聘者查看；不可编辑，不从Summary生成。不得暗调本人确认或将自动产物标为本人已确认。此为目标行为，当前后端仍待修改。

### 4.2 私有诉求

以下是已确认上游语义[C]：

- 排除卡片允许全部不选、自定义诉求允许留空，不阻塞建档；其含义是没有额外提出排除要求，不是同意所有工作条件。
- 新onboarding的排除卡和自定义诉求进入 `private_preferences`；四个历史排除字段填 `unspecified`，不据此清除历史意向的旧规则。
- 保存文字保持用户真实意思；硬性诉求与一般偏好不能互相替换。已有否定不再次加“不”，不把缺少说明视为对方已满足。
- 私有文本供己方Agent后续受控使用，不作为公开简历或公开给招聘方的原文。
- 文本形成与保存属于02；是否适合以及后续条件确认属于01及后续旅程，不由02的卡片产生匹配通过／不通过结果。

[C] 保留现有卡片与自定义输入：内置卡片按明确含义拼成文字，例如“大小周”生成“不接受大小周”；自定义内容保留原文，不让模型改写，也不统一添加“不接受”。沿用现有下一步动作保存，不新增确认页；撤回此前增加只读预览的建议，不作为本轮必需改动。

[C] “纯外包 / 乙方”卡固定生成“不接受纯外包/乙方”，不拆分、不额外解释或追加确认。空选择的含义已确认[C]。自定义与卡片有矛盾时不得擅自改写或选择一方，是否需要额外提示尚未决定，不新增自动裁定机制。

[C] 同页“屏蔽公司”纳入02首版真实接线，不暂缓。它是独立隐私动作，不混入私有诉求文字。[I] 当前仅本地状态，不代表公司已经屏蔽；选择公司名不能替代真实组织身份，写进私有文本也不能实现双向隐私屏蔽。[C] 用户从真实公司结果中选择后屏蔽，同名时不自动猜测组织；找不到对应组织时明确提示，不显示屏蔽成功。[E] 复用现有隐私接口核对结果；现有默认显示只能作为待选提示，必须经用户选择真实组织才写入，不能自动屏蔽所有简历公司。写入失败保持未成功并允许重试，不假报成功、不额外阻塞用户放弃该可选选择。

## 6. 保存失败、未知结果与刷新恢复

### 6.1 写入事实

[I] 简历各分区、summary、意向和头像分别保存，可能部分成功。意向创建有幂等键、替换有版本控制；前端当前没有完整保留本轮首次意向身份，不能仅靠“列表非空就跳过”处理返回修改。

[P:D03] 推荐行为：

1. 保存失败保留可继续处理的当前输入；已核实成功的分区保持成功，不能显示整条回滚。
2. 网络中断、超时或“结果未知”不是确定失败。先读取已知对象或核对原命令；有完整原键和原请求时才按原合同重放，不能把修改后的内容塞入同一键。
3. 列表为空不证明未受理，列表有一条也不证明就是本次成功。用户不能在不知情时因重试生成第二条“首次意向”。
4. [C] onboarding完成后的修改走既有意向编辑页，属于旅程外；保存流程按现状、最小改动推进。当前summary、首次意向、头像分阶段保存，不是整体事务；保留该边界，不新增整体提交／回滚或保存后锁定步骤机制。此前“返回修改更新同一意向”是未批准建议，不作为新增流程要求。[P:D03] 接线时核实既有返回／重入路径，若存在静默丢修改或重复创建，按具体缺陷最小修复，不借机重设计onboarding。
5. [E] 对账仍无法确定时保持待核对，不显示已完成，允许稍后重新核实。首版不新增人工协助入口、处理SLA或排障平台，也不自动继承01的人工支持承诺；若既有接口确实不能支持安全恢复，交接时指出具体缺口。

这些是目标草案。是否需要增加命令恢复坐标等由合同阶段决定，不在产品文档承诺某种浏览器存储或新增查询API。
