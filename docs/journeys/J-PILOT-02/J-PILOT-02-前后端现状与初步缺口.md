# J-PILOT-02：求职者 onboarding 前后端现状与初步缺口

> 后续校准：当前产品规则见[旅程v1.0](J-PILOT-02-产品旅程与状态规则.md)，新增作品集／Highlights范围见[合同校准](J-PILOT-02-Highlights与作品集合同校准.md)。本报告保留初轮研究时态，旧待决策与交集结论不能覆盖后续确认的范围。

2026-09-10。阶段：现状研究，非产品定稿、非实施交付。范围：求职者学生／社招建档、真实 PDF 解析与建议确认、私有诉求、首次意向、披露和头像、完成后进入首页，以及异常和中断恢复。用户认可范围见[范围与依赖澄清](J-PILOT-02-范围与依赖澄清.md)。

## 结论

本旅程已有大部分资源 API、真实前端接线、解析 worker 和分区预填能力，可以独立于 J-PILOT-01 推进产品合同。主要缺口是私有诉求仍走旧映射、同页屏蔽公司未真实落盘、首次意向未知结果与返回修改、建档进度恢复和注册完成语义。不能把已接线理解为完整 onboarding 已验收通过。

PDF 解析的真实 provider 可靠性另有未关闭缺陷。它不阻止研究、合同设计和 fixture 覆盖，但会影响真实 PDF 成功路径的验收结论。手填分支可独立验证，不能代替解析分支验收。

## 同名能力边界

onboarding“个人优势”当前是 `PATCH /api/v1/me/resume/summary` 的自由文本保存，允许手填，解析建议只是可选初值。后端另有 `personal-highlights` 来源绑定标签资源，不能因为名字相近就加入本旅程，或据其成功PDF前置误判手填缺接口。本轮API范围已排除该独立标签能力。

## 02 与 01 如何并行

API候选范围共43个公开operation，递归涉及132个BFF Schema；按路径及方法映射到37个内部资源operation，其余为身份入口。核对两份Spec的候选对象与01差异，operation和Schema改动交集均为空。具体集合及结果见[机器核查结果](api-overlap.json)。

02生成简历、附件版本和意向私有诉求，01消费这些已有资源。语义依赖以已合入release的合同为准，01可使用按该合同准备的数据独立验收。02不修改01的S0终局、Negotiation待办、PDF披露和Case状态。

前端仍共用意向映射、附件操作、HTTP与会话水合等代码。后续实施应先列最终改动对象，避免两分支同时调整共享基础能力；当前无证据要求拆分整份OpenAPI或新增并行管理机制。
