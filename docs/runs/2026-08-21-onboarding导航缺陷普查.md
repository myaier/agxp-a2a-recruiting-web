# Onboarding 导航缺陷普查（静态 + 浏览器复现）

- 日期：2026-08-21
- 范围：`Onboarding流程` 登记的三条路径（学生求职 / 社招求职 / 招聘方）全部屏幕
- 方法：先读流程合同与全局状态建图，再逐屏静态审查；关键结论用 `http://127.0.0.1:8083` 实机复现
- 结论：**主 agent 的根因假设成立，且实际后果比假设更严重** —— 不只是"取到 undefined 渲染不出内容"，白屏之后再点一次「下一步」会直接冲出整条注册流
- 计数：A 类 4 条、B 类 7 条、C 类 2 条、D 类 3 条、E 类 4 条（共 20 条，其中 8 条已在浏览器实测复现）

---

## 0. 先回答"根因假设真不真"

假设原文：`题序` 是动态过滤数组，答完薪资后「期望薪资」被移出、数组变短，而 `第几题` 是独立 useState 不跟着收缩，越界后 `当前题 === undefined`。

**真。但触发条件比假设窄，后果比假设宽。**

- 窄在哪：`题目顺序` 是 `[期望职位, 工作城市, 期望薪资, 硬性排除, 个人优势]`，`硬性排除` 与 `个人优势` 永不被过滤，所以「期望薪资」永远不是数组末项。**只移除薪资一题不会越界**（后面的元素左移，索引正好落到下一题 —— 这也是 `引导问答.tsx:85` 那句注释「当前索引自然落到下一题」在描述的巧合）。
- 宽在哪：真正越界的是**一次 dispatch 同时满足了两个过滤条件**。`存薪资预填` 在 `引导预填` 原本为 `null` 时，会把它从 null 变成非 null —— 于是 `期望职位`、`工作城市` 两题**同时**被踢掉，数组从 5 项塌到 2 项，`第几题` 还停在 2 → 越界白屏。
- 用户口中的「退出去了」实际有**两条**独立机制都能产生，见 A-2 与 E-1，两条都已实测复现。

## A 类 —— 索引游标配动态数组

### A-1 `第几题` 越过收缩后的 `题序` 末尾 → 整块白屏【已复现】

| 项 | 内容 |
|---|---|
| 文件行号 | `src/屏幕/引导问答.tsx:47`（`第几题` useState）、`:53-57`（`题序` filter）、`:58`（`当前题 = 题序[第几题]`） |
| 连带 | `src/状态/应用状态.tsx:1149-1156`（`存薪资预填` 的 `?? { 城市们: ['上海'], 职位: [] }` 兜底把 `引导预填` 从 null 变非 null） |

**触发步骤（浏览器实测）**

1. `localStorage` 里没有 `AGXP求职筛选v1`（即 `引导预填 === null`），且 `基本信息.身份 === '在校'`
2. 打开 `#/wizard` → `题序` = 全 5 题，首屏是「期望职位是」
3. 点两次底部主按钮（「保存（已选 3）」→「保存（已选 1）」）→ 到第 3 题「期望现金月薪是？」，此时 `第几题 = 2`
4. 点「下一步」

**为什么现在的写法会出问题**

`下一题()`（`:82-86`）派发 `存薪资预填`。reducer 用 `?? { 城市们: ['上海'], 职位: [] }` 兜底，`引导预填` 由 `null` 变成对象。下一次 render 时 filter 的**两个**条件同时生效：

- `全局.引导预填 && (题 === '期望职位' || 题 === '工作城市')` → 踢掉 2 题
- `薪资已答 && 题 === '期望薪资'` → 再踢 1 题

`题序` 从 `[期望职位, 工作城市, 期望薪资, 硬性排除, 个人优势]`（5）塌到 `[硬性排除, 个人优势]`（2），`第几题` 仍是 2 → `题序[2] === undefined` → `:116-139` 五个 `当前题 === 'X' ? … : null` 全部落空。

**实测结果**：页面正文只剩 `‹ / 下一步 / ✎`，问题区整块空白。

**为什么身份是关键**：`:84` 只有非在校才 `跳转(路径.基本信息)`。在校 → 不跳转，白屏当场可见；在职/离职 → 被跳转掩盖，但状态错误一样发生（并直接引出 B-1）。

### A-4 `题序` 每次 render 裸算，与 `第几题` 之间没有任何钳制（结构性）

| 项 | 内容 |
|---|---|
| 文件行号 | `src/屏幕/引导问答.tsx:53`（无 `useMemo`）、`:47`（独立 useState） |

`题序` 的三个依赖 —— `全局.引导预填`、`筛选偏好.求职类型`（经 `判断求职薪资单位`）、`已存薪资单位` —— 任何一个在本次挂载期内变化，长度都会变。而 `第几题` 是完全独立的 useState，**没有任何 clamp、没有 effect 同步、没有边界兜底**。

现在能跑，靠的是"期望薪资恰好不在数组末尾"这个巧合。这是本轮缺陷的**类根因**：修法不该是给薪资打补丁，而是让游标与数组绑定（例如改用"当前题名"而非下标，或在取值处 clamp 并对 undefined 兜底）。

## B 类 —— 返回后状态不一致

### B-1 答完薪资 → 返回 → 薪资题永久消失【已复现 · 就是用户报的现象】

| 项 | 内容 |
|---|---|
| 文件行号 | `src/屏幕/引导问答.tsx:47-58`、`:82-86` |

**触发步骤（浏览器实测全程）**

1. `#/student` → 点「已毕业」→ 点「社招全职」→ 进「期望的职位是」选一个（如 Golang）保存 → 点「下一步」
2. `#/wizard` 显示「期望现金月薪是？」← **这就是用户说的「能看到薪资的选择」**
3. 点「下一步」→ 派发 `存薪资预填` + `跳转(路径.基本信息)`，到 `#/basic`

**为什么**：路由切换让 `引导问答` 卸载重挂，`第几题` 归 0；但 `薪资已答` 已经在全局里翻成 true，`题序` 变成 `[硬性排除, 个人优势]`，`题序[0]` 就是硬性排除。用户以为"回上一页"能改薪资，实际薪资题已被永久移出题序 —— 唯一的回头路是退到 `#/student` 重按下一步（`启程引导` 会整体重建 `引导预填`，把薪资清掉），但用户没有理由知道这一点。

## C 类 —— useEffect 在重挂载时误重置

**先说结论：这一类在 onboarding 各屏里没有找到"无条件 effect 重置数据"的实例。**全仓 `useEffect` 在 onboarding 屏只出现两处（`引导问答.tsx:518/526` 在 `薪资轮` 内部，只管滚动定位；`企业实名认证.tsx:39` 是计时器清理，写法正确）。但缺口以另一种形态存在：

### C-1 整条 onboarding 没有任何一屏做 POP/PUSH 分流（结构性缺口）

| 项 | 内容 |
|---|---|
| 证据 | 全仓 `useNavigationType` 只有 `src/屏幕/添加意向.tsx:87` 一处 |

`引导问答`、`学生分流`、`招聘名片` 都存在"跳次级页再回来"的路径，但都没有 `添加意向.tsx:109-114` 那道闸：

```ts
const 草稿不是本条 = 挂载时草稿编号 !== (路由编号 ?? null);
if (导航类型 !== 'POP' || 草稿不是本条) { 派发({ 型: '开意向草稿', … }); }
```

这几屏"侥幸"没踩到 C 类，是因为它们干脆没写 effect —— 代价是改成了 B-4 / B-5 那种"本地态直接丢"。**同一个病的两种表现**：真相放在了组件而不是全局。修 B-4 / B-5 时应参照 `添加意向` 的两条做法（真相入全局 + 按导航类型分流），而不是各自打补丁。

## 0. 类根因的修法（A 类总纲）

不给薪资打补丁，改的是「游标和数组不是同一个真相来源」这件事本身，落在三处：

1. **题序在挂载时算一次就冻结**（`引导问答.tsx:53-59`）。过滤条件读的 `引导预填` / `薪资已答` 恰恰会被「答题」这个动作本身改写，每次 render 重算 = 用户答一题、题目集合当场变一次。冻结之后「这一段问哪几题」在进屏那一刻定死，答题只推游标、不动集合。
2. **游标存题名，不存下标**（`引导问答.tsx:62-63`）。下标只有配上「题序永不变」才成立；存题名则游标本身就是一道题，`当前题 === undefined` 这个状态在类型上根本不存在，白屏无从发生。选它而不是「越界就 clamp 回去」，是因为 clamp 只是把坏状态改成另一个坏状态（用户仍会莫名其妙跳题），而换游标类型是把坏状态从可表示集合里删掉。
3. **题序按构造非空**（`onboarding配置.向导题序`）：`硬性排除` 与 `个人优势` 两题恒在末尾，任何入参组合下长度 ≥ 2。所以不需要「空数组」的运行时兜底 —— 用构造保证比用 if 兜底更可靠，也不违反「不许吞错」。新增用例穷举 8 种入参组合断言非空。

配套的第二个结构改动是**把「向导是合同里的第几站」写进地址**：`#/wizard?stage=salary`（薪资段）/ `#/wizard`（偏好段）。原来屏幕靠「薪资答没答」反推自己是第几次进来，而答薪资这个动作会让推断当场翻面 —— B-1 和 E-1 都是这一个反推塌掉的两种表现。段由合同给定、不随答题变化，`Onboarding流程.社招求职` 里两次进向导现在登记成两个不同地址。
