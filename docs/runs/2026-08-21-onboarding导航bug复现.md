## 一、根因判定

**主 agent 的根因假设成立，且已拿到直接证据。**

`引导问答.tsx` 第 47 / 53–58 行：

```ts
const [第几题, 设第几题] = useState(0);          // 独立索引游标
const 题序: readonly 题名[] = 题目顺序.filter(...);// 每次 render 动态重算、长度会变
const 当前题: 题名 = 题序[第几题];                // 越界时静默变成 undefined
```

`题序` 的长度由 `全局.引导预填` 和 `薪资已答` 决定，而这两个值会在**组件挂载期间**被 `派发` 改变；
`第几题` 是独立 `useState`，不会跟着数组收缩/增长做修正。于是出现三种越界形态：

| 形态 | 触发 | 现象 |
|---|---|---|
| **数组收缩，索引越界** | 答完薪资 → `存薪资预填` 让 `引导预填` 由 null 变非 null，一次性过滤掉「期望职位/工作城市/期望薪资」三题，`题序` 5→2，而 `第几题` 还停在 2 | `当前题 === undefined` → 题干整块不渲染，屏幕只剩返回箭头 + 一个「下一步」按钮 |
| **数组收缩，索引未越界** | 同上但 `第几题 === 0` | 不白屏，但「上一题」的语义被偷换：用户按返回想回薪资题，实际直接退出整个向导 |
| **数组增长，索引前移** | 在「个人优势」题输入作品集链接 → `存求职筛选偏好` 把 `求职类型` 写成默认值 `['实习生']` → 薪资单位由 `月薪K` 翻成 `元/天` → `薪资已答` 变 false → `题序` 2→3 | 用户正在打字，页面当场跳回上一题「硬性排除」，输入框失焦、内容丢失 |

TypeScript 之所以完全没告警：`tsconfig.app.json` 没开 `strict`，也没开 `noUncheckedIndexedAccess`，
所以 `题序[第几题]` 的静态类型是 `题名` 而非 `题名 | undefined`——`const 当前题: 题名` 这个标注是个谎言。
运行时也没有任何 console 报错（见 §四），属于**纯静默失败**。

### 复现 B — 用户原话那条：「返回上一页 → 再点下一页 → 退出去了」

这条在**正常流程**（不需要清缓存）就能稳定复现，走的是「数组收缩、索引未越界」形态。

#### B-1 社招（已毕业）路径

1. `#/identity` → 点「我要找工作」→ `#/intro`
2. 点「开始设置求职偏好」→ `#/student`「完善资料」
3. 保持「已毕业」+「社招全职」，点「选择期望职位」→ 选一个（如 Golang）→「保存」
4. 点「下一步」 → `#/wizard`，**第一题就是「期望现金月薪是？」**（`第几题=0`，`题序=[期望薪资, 硬性排除, 个人优势]`，长度 3）
   —— 对应用户说的「正常流程走的时候能看到薪资的选择」
5. 点「下一步」 → `#/basic`「创建在线简历」，`引导预填.薪资` 落库为 `{下限:50, 上限:60, 单位:"月薪K"}`
6. 在「创建在线简历」点左上返回 → 回到 `#/wizard`
   **★ 异常 1：屏幕不是薪资题，而是「哪些情况直接排除？」**
   探针：`第几题=0`，`题序=[硬性排除, 个人优势]`（长度由 3 掉到 2），`当前题=硬性排除`
   —— 薪资题被静默移出题序，用户再也没法用向导内的返回回到它
7. 在「哪些情况直接排除？」再点返回 → `第几题===0` → 走 `返回()` = `navigate(-1)`
   **★ 异常 2：直接弹出整个向导，落到 `#/student`「完善资料」**
   —— 这就是用户说的「就退出去了」
8. 在「完善资料」点「下一步」 → 又回到 `#/wizard` 的薪资题
   （因为 `启程引导` 整体重建 `引导预填`，把刚存的薪资清零了 —— 第 5 步答的薪资白答）

#### B-2 在校（学生）路径 —— 「答完薪资后按返回就退出」更直接

### 复现 C — 打字打一半被弹回上一题（`题序` 变长）

**前置条件**：`引导预填` 存在但**没有 `筛选偏好` 字段**（`存薪资预填` / `存引导预填` 的兜底对象 `{城市们:['上海'],职位:[]}` 不带 `筛选偏好`；旧版 localStorage 缓存同理），且 `身份 === '在校'`。

1. 按复现 A 走到空白屏，点返回落到「个人优势」题（`第几题=1`，`题序=[硬性排除,个人优势]`）
2. 点「粘贴你的作品集、GitHub 或项目链接」进入编辑态
3. 在输入框里输入任意一个字符

**结果：页面当场跳回上一题「哪些情况直接排除？」**，输入框消失、刚输入的内容不再可见。

原始探针（E1）：

```json
{ "步":"E1 输入作品集链接后",
  "标题(屏正文)":"‹ | 哪些情况直接排除？ | 大小周 ✓ | 纯外包 / 乙方 ✓ | …",
  "第几题":1,
  "题序":["期望薪资","硬性排除","个人优势"], "题序长度":3,
  "当前题":"硬性排除",
  "筛选偏好":{"作品集链接":"github.com/lidali","办公方式":["现场","混合","全远程"],
             "实习月数":3,"每周到岗天数":4,"求职类型":["实习生"]},
  "薪资预填":{"上限":60,"下限":50,"单位":"月薪K"} }
```

链路：`存作品集链接` → `派发 存求职筛选偏好`，而 `筛选偏好` 取的是
`全局.引导预填?.筛选偏好 ?? 默认求职初筛偏好(身份 === '在校')`。
`引导预填.筛选偏好` 缺失时兜底成 `{求职类型:['实习生'], …}`（`onboarding配置.ts:148-152`），
`判断求职薪资单位` 于是把单位从 `月薪K` 翻成 `元/天`（`onboarding配置.ts:194-196`），
`已存薪资单位('月薪K') !== 当前薪资单位('元/天')` → `薪资已答` 由 true 翻 false →
「期望薪资」被重新插回题序 index 0，所有后续题整体后移一位，`第几题=1` 于是从「个人优势」指到了「硬性排除」。

## 三、我另外发现的触发路径

按任务要求试了几条相邻路径，结论如下。

### 1. 浏览器后退键（不是页面上的返回栏）—— 会整段跳出向导

向导内的换题只改 `第几题`，**从不 push history**；整个 `/wizard` 只占一个 history entry。

1. 在向导第 2 题「个人优势」（`第几题=1`）按浏览器后退
2. → 直接落到 `#/onboard/status`，**一次退掉向导全部题目**
3. 再按浏览器前进 → 回到 `#/wizard`，但 `第几题` 重新挂载为 0，落到「硬性排除」而不是离开时的「个人优势」

实测：

```
H2 下一步→个人优势   hash=#/wizard        第几题=1  当前题=个人优势
H3 浏览器后退键      hash=#/onboard/status 第几题=无向导
H4 浏览器前进键      hash=#/wizard        第几题=0  当前题=硬性排除
```

### 2. 硬刷新停在向导中间某一题 —— 位置和已填答案全丢

1. 走到「个人优势」（`第几题=1`），先在上一题「硬性排除」里勾上「全现场办公」
2. 刷新页面（`location.reload()`）
3. 回到 `第几题=0`「哪些情况直接排除？」，且**「全现场办公」的勾没了**

实测刷新前 `{hash:"#/wizard", 第几题:1}`，刷新后屏幕文本：

```
‹ | 哪些情况直接排除？ | 大小周 ✓ | 纯外包 / 乙方 ✓ | 全现场办公 | 频繁出差 | …
```

原因：`已选职位 / 已选城市 / 排除项 / 自我介绍` 全是 `useState`（源码第 9 行注释「答案只存在内存里」），
刷新即清零；`第几题` 也是 `useState`，刷新回 0。刷新后落在哪一题只取决于 `引导预填` 的持久化残留。

### 3. 薪资 → 基本信息 → 工作经历 → 回向导 → 反复前进后退

社招路径（复现 B-1 第 6 步）已经覆盖：回到向导必然重新挂载、`第几题=0`，
而 `题序` 因为 `薪资已答` 变 true 收缩到 2，所以**回来后永远落在「硬性排除」**，薪资题不可达。
再按一次返回就整段退出向导（B-1 第 7 步）。
从 `#/student` 重新「下一步」会触发 `启程引导` 整体重建 `引导预填`（`应用状态.tsx:1115-1120`），
把已答的薪资清空 —— 用户来回一趟，薪资白答，且不会有任何提示。

### 4. 学生分流那条路

已在复现 B-2 完整走通。补充两点：
- 「在校 + 实习生」在「完善资料」页会额外要求「最早可开始实习日期」，未填时「下一步」保持禁用（这是正确行为，不是 bug）
- 「在校 + 实习生」下 `判断求职薪资单位` 返回 `元/天`，薪资题标题变「期望日薪」，此时单位自洽，复现 C 那条翻转不会触发

### 5. 同类模式的反向扫描（源码层，已排除）

对「索引游标遍历派生数组」这一类做了全仓扫描，`useState(0)` 只有三处：

- `src/屏幕/引导问答.tsx:47` `第几题` —— **有缺陷**（`题序` 是 `filter` 出来的派生数组）
- `src/屏幕/发布岗位.tsx:129` `第几步` —— 安全，`步骤顺序` 是长度恒为 3 的 `const` 静态数组
- `src/屏幕/求职意向管理.tsx:27` `求职状态下标` —— 安全，`求职状态档位` 是静态数组且用 `% 长度` 取模

所以这一类缺陷目前只有 `引导问答.tsx` 一处，但它有三种发作形态（见 §一表格），修的时候三种都要覆盖。

## 四、控制台 / 报错情况

全程 `read_console_messages` 只有 Vite HMR 连接日志和 React DevTools 提示，**没有任何 error / warning / Uncaught**：

```
[debug] [vite] connecting...
[debug] [vite] connected.
[info] Download the React DevTools for a better development experience: …
```

同时页面内挂了 `window.onerror` / `unhandledrejection` / `console.error` 三重钩子，全程 `错误: []`。

**结论：这是纯静默失败**，不会抛错、不会触发任何 error boundary，只会渲染出一个空壳。
配合 `tsconfig.app.json` 未开 `strict` / `noUncheckedIndexedAccess`，`npm run typecheck` 也不会报。
