## ① 断头路：进得去出不来 / 做完一件事没有下一步

### 1-1【严重】三块屏零入口，只能手敲 URL

对 `路径表.ts` 里每个键做全仓引用统计（排除 `路径表.ts` 与 `应用.tsx` 自身），下面三个的引用数是 0：

- **`未通过说明` `/rejected`** —— 路由注册在 `src/应用.tsx:138`，屏在 `src/屏幕/未通过说明.tsx`。全仓没有任何 `跳转(路径.未通过说明)`。
- **`候选未通过` `/hr/rejected`** —— 注册在 `src/应用.tsx:166`，屏在 `src/屏幕/候选未通过.tsx`。同样零引用。
- **`企业往来记录` `/hr/thread/:id`** —— 注册在 `src/应用.tsx:167`。求职端的对应屏 `往来记录` 至少还有一个入口（`src/屏幕/归档谈判.tsx:40`），企业端一个都没有。

**缺了会怎样**：前两屏正是「硬性核对逐条摊开 + 代理小结 + 一条可执行的放宽建议」这一整套解释（`未通过说明.tsx:81-132`、`候选未通过.tsx:82-133`），是这个产品「代理不是黑箱」的核心论证。现在它写完了、跑得起来、没人看得到。

**建议**：做。求职端从「历史接洽」的「对方未通过」那类卡（`归档谈判.tsx:15-19` 已经有 `对方未通过` 这个结果类型）点进 `未通过说明`；企业端从「已筛掉的候选」行或「初筛记录」里结果为「挡掉」的行点进 `候选未通过`。两条路都是现成的列表，加一个 `跳转` 即可，不新增屏、不新增文案。

### 1-2【严重】通知设置整组消失，8 个开关没有入口

`src/屏幕/设置.tsx:1-5` 的文件头注释写「分五组：账号 / 隐私与可见性 / 通知 / 通用 / 关于」，实际渲染只有三组 —— `设置.tsx:109-110` 是两行空行，通知组和通用组不在了。企业端同样，`src/屏幕/企业设置.tsx:83-84` 也是空行。

`src/状态/应用状态.tsx:549-556` 定义了 6 个求职端开关，屏上只渲染 `对现雇主隐身` 一个（`设置.tsx:85`）；`应用状态.tsx:583-589` 定义了 5 个企业端开关，只渲染 `允许代理自动发起接触` 一个（`企业设置.tsx:67`）。以下 8 个开关在全 App 无任何入口：

`需要你时推送提醒`、`有新机会时推送提醒`、`每日简报推送`、`允许平台用我的数据改进匹配`、`需要拍板时推送提醒`、`有新候选时推送提醒`、`每日人才简报推送`、`允许岗位数据改进匹配`。

### 1-3【严重】「收藏候选」是只写不读的状态

## ② 空态缺失：列表为空时用户看到什么

现状是「一半屏做了空态、一半没做，而且做了的那一半用了三套不同版式」。

### 2-1【严重】企业通知中心没有空态

`通知中心.tsx:84-90` 有完整空态（🔔 + 标题 + 说明）。`企业通知中心.tsx:47-79` 是同一份代码抄过去的，唯独把空态整块漏了 —— 全部已读且列表为空时是一片纯白。

**建议**：做。整段拷过去即可。

### 2-2【严重】消息 Tab 只有「搜不到」空态，没有「一条都没有」空态

`消息列表.tsx:90-95` 与 `企业消息.tsx:97-102` 的空态文案都是「没有匹配的会话。换个关键词，或者切到「全部」看看。」

这句话对「搜索无结果」是对的，对「新用户一条会话都没有」是错的 —— 用户没输任何关键词，系统却让他「换个关键词」。而消息 Tab 是三个主 Tab 之一，新用户点进去的第一印象就是这句话。

**建议**：做。按 `搜索词.trim() === '' && 当前页签 === '全部'` 分出第二种空态。这属于修正错误文案，不是新增解释性小文案。

### 2-3【中】规则类的屏删空后是两张空白卡

`规则库.tsx:62-106`：两个分组标题（「全 局 规 则 · 所 有 谈 判 生 效」「意 向 级 · 仅「AI 产 品 经 理」」）+ 两张卡，卡里 `.map()` 出 0 行时卡体是空的。而规则在这一屏是可删的（`规则库.tsx:187-189`），删空是能到达的状态。企业端 `企业代理设置.tsx:66-76` 同样。

`看市场.tsx:257-305` 的筛选层和 `候选筛选抽屉.tsx:75-125` 也一样 —— 全删完只剩一个「＋ 添加规则」。

**建议**：做，但用结构表达而不是加文案：0 条时不渲染分组卡与分组标题，只留「＋ 手动添加规则」那条虚线按钮。用户看到的是一个明确的空表单，不需要一句话解释。

### 2-4【中】岗位管理 / 求职意向管理删空后没有落点

- `岗位管理.tsx:95-135`：`在招组` 与 `归档组` 都为空时，两个 `? :` 都返回 null，整屏只剩底部那条「＋ 发布新岗位」。这不是不可达状态 —— 删除动作就在同屏（`岗位管理.tsx:68`）。

## ③ 状态不可见：代理干的活用户看不见

这一节最要紧 —— 产品卖点就是「代理替我干活」，代理干完看不见等于卖点没落地。

### 3-1【严重】首页顶部的意向栏和求职意向表是两份数据

`顶部意向栏.tsx:15` 引入的是 `模拟数据.ts:26` 的静态常量：

```ts
export const 意向切换 = ['后端工程师', 'AI 产品经理'];
```

`顶部意向栏.tsx:61-72` 直接 `意向切换.map()` 渲染切换胶囊。而用户真正在管理的是 `状态.求职意向表`（`应用状态.tsx:79`），增删改分别走 `新增意向` / `删意向` / `改意向`（`添加意向.tsx:140-141, 147`）。两者毫无关联。

**缺了会怎样（用户在哪一步卡住）**：
1. 用户走完「我的 › 求职意向 › 添加求职意向」，认真填了 7 行（城市 / 职位 / 感兴趣城市 / 薪资 / 行业 / 底线），点保存 → 回到首页，顶部还是那两个胶囊，新意向不存在，也没有任何一个岗位归属于它。整条「一份简历挂多个意向、各自独立谈」的主线在 UI 上不成立。
2. 删掉一条意向 → 顶栏仍然显示它，且 `在谈首页.tsx:31` 仍会按这个字符串过滤出在谈单。
3. 同一个概念两个名字：顶栏叫「后端工程师」，意向管理里叫「[上海] 后端工程师」（`模拟数据.ts:1357`）。用户看不出这是同一件东西。

**建议**：做，这是本轮最该修的一条。顶栏改读 `状态.求职意向表`，显示用标题里 `[城市]` 之后的那一段（`应用状态.tsx:495` 的正则已经能拆），在谈 / 市场列表的 `意向` 字段按同一口径匹配。

### 3-2【严重】委托给代理去谈的岗位，永远留在「看市场」里

`看市场.tsx:74-83` 的过滤条件是「本意向 + 非不感兴趣 + 非屏蔽公司」，**没有排除 `状态.已委托`**。委托之后（`应用状态.tsx:746-772` 的 `委托入谈`）这个岗同时出现在「在谈」和「看市场」两个子视图里，市场卡上的按钮变成不可点的「AI代理已接手」（`看市场.tsx:381-385`），然后就一直挂在那儿。

对照企业端：`候选推荐.tsx:57-59` 明确把已接触过的人移出推荐流，只让当次会话里刚点的那张留着显示反馈，下次进来就消失。两端逻辑正好相反。

**缺了会怎样**：用户委托了 8 个岗，市场流里就永久堵着 8 张「已接手」的死卡，越用越脏；而且他会怀疑「我到底委托没委托」—— 因为这个岗还在「待选」的那个列表里。

**建议**：做。照抄企业端的做法（本次会话留、下次进来移出），两端就一致了。

### 3-3【中】岗位管理列表上的「在谈 N 人」是假数字

`岗位管理.tsx:224` 显示 `岗.在谈数` —— 这是种子数据里的静态字段（`企业端模拟数据.ts:31, 64, 87, 104`），发布新岗时写死成 2（`应用状态.tsx:898`），此后终止候选、接触新候选都不会改它。

而同一屏的停止招聘确认框用的是实时计算的 `数在谈()`（`岗位管理.tsx:42-43`，被 `:151` 使用）。所以会出现：行上写「在谈 4 人」，点停止招聘弹出「这个岗位还有 2 位在谈候选」。

**建议**：做。行上也改用 `数在谈(岗.编号)`，删掉 `在谈数` 字段。
