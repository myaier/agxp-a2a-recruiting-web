## 0. 判断口径

BOSS 有而我们没有的东西，分四类处理：

| 类 | 含义 | 处理 |
|---|---|---|
| A 该补 | 与双盲无冲突，且用户会自然去找 | 列出并给做法 |
| B 不补 | 与双盲 / 代理谈判机制冲突，或在我们这里已有更强的等价物 | 写清冲突点在哪 |
| C 断链 | 功能已经写完了，但没接上入口 / 没带参数 | 优先级高于任何新功能 |
| D 待确认 | 读代码判断不了，需要产品拍板 | 单列，不混进结论 |

**C 类是本次最大的发现**：求职端有 3 处「屏做好了但没人能走到 / 走到的是同一份假数据」，其中职位详情的共享常量会让任何一次多点两个岗的演示当场穿帮。

---

## 1. 结论：最该补的 3 条

1. **职位详情按岗位取数**（C 类断链）——`职位详情.tsx:67` 把 `市场职位详情` 这个**单例常量**当所有岗位的详情用，7 个岗点进去 JD、发布人、公司卡全是 MiniMax。
2. **一个「先留着」的出口**（A 类）——现在对一个岗只有两个动作：委托代理（`委托入谈`，且退出后进归档不可恢复，`归档谈判.tsx:31`）或不感兴趣（负反馈）。没有「我还没想好」的落点，用户不敢点也不敢关。
3. **「谁接触过我」提到「我的」宫格 + 对外画像预览入口**（A 类）——双盲产品里用户最大的两个焦虑是「有没有人看我」和「他们看得到我多少」。前者埋在 `设置.tsx:100` 三级菜单里，后者求职端**根本没有**（只有企业端视角的 `/hr/resume/:id`）。

## 2. 首页 / 推荐流

### 现状

- 职位 Tab 是双子视图：`在谈` / `看市场`，共用顶部意向栏（`主壳.tsx:17`、`顶部意向栏.tsx:92-116`）。
- 市场卡内容（`看市场.tsx:334-392`）：公司字标 + 公司名 + 公司简介（行业·轮次·规模）+ 适配环 + 薪资 + 职位名 + 标签行（城市·区 / N 薪 / 办公方式 / 到岗）+ 发布人（区分企业直招 / 猎头）+「让AI代理去谈」。
- 操作：整卡进职位详情；「让AI代理去谈」当场变成在谈单。**没有**收藏、没有左滑、卡上没有「不感兴趣」。
- 筛选：`看市场.tsx:204-313` 已彻底改成规则清单（写一句话 → 落规则库），**不做任何本地档位过滤**（`看市场.tsx:17-20` 注释明写）。
- 下拉刷新有（`组件/下拉刷新.tsx`）。数据 7 条（`模拟数据.ts` 市场列表 M-01…M-07）。

### 2.1 卡上没有发布时间 —— 建议补

- **现状**：`市场职位.发布于` 字段已存在（`数据/类型.ts:75`），mock 也有值（`模拟数据.ts` M-01 `发布于: '4 小时前'`），但只在职位详情渲染成 chip（`职位详情.tsx:106`），市场卡不显示。
- **缺了会怎样**：用户在列表里判断「值不值得让代理去谈」时，拿不到新鲜度这一维。一个挂了 3 个月的岗和 4 小时前发的岗，在卡上长得一模一样。
- **建议**：补。字段已在，只是把它摆到标签行末。这不是加文案，是把已有数据显示出来。

### 2.2 列表完全无序 —— 建议补默认序，不补排序器

- **现状**：`显示列表` = `本意向市场.filter(命中搜索)`（`看市场.tsx:86-89`），没有任何 sort。当前顺序就是 mock 数组顺序。对比：在谈列表是排过的（`在谈首页.tsx:40`，需要你置顶）。
- **缺了会怎样**：适配环（93 / 88 / 86…）在卡上很显眼，但列表不按它排，用户会觉得这个分数是装饰。
- **建议**：默认按适配分降序，**不给用户排序器**。BOSS 的「最新 / 薪资从高到低」是给用户当过滤工具用的；在我们这儿排序权在代理，给一个「按薪资排」等于把代理降级成列表控件。

### 2.3 卡上没有「不感兴趣」快捷动作 —— 建议补左滑

- **现状**：「不感兴趣」只能进职位详情后从浮动条 🚫（`职位详情.tsx:227-237`）或 ⋯ 抽屉（`职位详情.tsx:257-269`）触发。企业端的候选卡**已经有左滑「不合适」**（`候选推荐.tsx:8` 注释）。
- **缺了会怎样**：刷市场时每剔掉一个岗要「进详情 → 点 🚫 → 返回」三步。
- **建议**：补左滑，与企业端同构。注意 `看市场.tsx:12` 那条「底行不放收藏/屏蔽小图标」是反对在底行堆图标，不是反对左滑手势，两者不冲突。

### 2.4 没有「先留着」的出口 —— 建议补（Top 3）

- **现状**：对一个市场岗只有三种可能：委托代理（`派发({型:'委托入谈'})`，`看市场.tsx:160`）、不感兴趣（进负反馈池，`应用状态` 的 `不感兴趣岗位`）、或什么都不做。而委托是**单向不可逆**的：退出谈判后进归档，`归档谈判.tsx:31` 明写「已结束的单不会再恢复成在谈 —— 阶段只往前走」。
- **缺了会怎样**：用户看到一个有点意思但拿不准的岗，点下去代价高（代理立刻去接触对方、产生接触记录、消耗匿名额度），不点就找不回来（没有浏览历史、没有收藏、列表按意向过滤）。结果是**犹豫的岗全部流失**。这是我判断求职端最实的一个缺口。
- **建议**：补一个只影响自己列表、不触发任何代理动作、不产生任何对外痕迹的「先留着」。它与双盲**零冲突**——对方完全不知情。放在「我的」宫格里做落点。
- **不要**叫「收藏」并配一枚星，因为企业端的 `收藏候选`（`应用状态.tsx:154`）是攒人才池的语义，两端不对称，同名会混。命名交产品定。

### 2.5 分页 / 加载更多 —— 待确认

7 条 mock 一屏放得下，看不出原型是否需要无限滚动。真实数据量级需产品给。

## 4. 职位详情

### 现状

内容顺序（`职位详情.tsx:91-222`）：职位名 + 薪资 → 标签行 + 发布于 chip → 发布人卡（实名 + 「直接聊」按钮）→ 匹配度分析（适配环 + 5 维核对 + 硬性要求 ✓✗ + 技能 chips）→ JD（职位详情 + 职位要求）→ 公司卡 → 底部浮动条（🚫 不感兴趣 + 让AI代理去谈）。右上 ⋯ → 不感兴趣 / 举报（`举报层.tsx`，4 个原因 + 同时屏蔽，屏蔽双向）。

**这一屏在「匹配度可解释」上明显强于 BOSS**：BOSS 只给一个「匹配度高」标，我们逐维摊开了拿什么比出来的。

### 4.1 所有岗位共用同一份详情数据 —— 必须修（Top 1，C 类断链）

- **现状**：`职位详情.tsx:67` `const 详 = 市场职位详情;` —— `市场职位详情` 是 `模拟数据.ts:1224` 的**单例常量**。页面里 `详.标签`（第 100 行）、`详.发布人`（第 112-118 行）、`详.职位详情` / `详.职位要求`（第 187、193 行）、`详.公司`（第 204-217 行）全部读它。只有职位名、薪资、适配分、技能要求走 `岗`（按路由参数取到的那条）。
- **缺了会怎样**：点开小红书的「AI 产品经理（搜索推荐）」，看到的 JD 是 MiniMax 的 Agent 岗，发布人是「陆知遥 · MiniMax」，公司卡写 MiniMax，再点公司卡进的是 MiniMax 的公司主页。**任何一次点开第二个岗的演示都会当场穿帮。**
- **同类**：`在谈详情.tsx:449` `const 详 = 在谈职位详情;` 也是单例（小红书 J-02 的），所有在谈单的「职位详情」Tab 都显示它。
- **建议**：把 JD / 发布人 / 公司 挪进 `市场职位` 与 `在谈单` 类型里按条存。这是原型可信度的地基，优先级高于本文档任何一条新功能。

### 4.2 没有办公地址 —— 建议补

- **现状**：职位详情整屏没有地址，最细只到标签行的「上海 · 徐汇」。地址在 `企业详情.tsx:236` 有，但那是公司档案里的总部地址，不是这个岗位的办公地。
- **缺了会怎样**：地址是求职者仅次于薪资的决策项。现在用户要判断通勤，得先点公司卡进企业详情、还不保证是同一个办公点。
- **建议**：补一行办公地（文本即可）。**与双盲零冲突**——招聘方本来就从第一轮起实名。地图可先沿用企业详情已有的降级做法（`企业详情.tsx:231` 的「导航 ›」给一句原型说明），真机走 `原生桥/能力接口.ts`。

### 4.3 「不感兴趣」两个入口、反馈不一致 —— 建议收敛

- **现状**：浮动条 🚫（`职位详情.tsx:227-237`）派发后**静默返回**；⋯ 抽屉第一项（`职位详情.tsx:257-269`）派发后给 `轻提示('已不再推荐，代理会记住这类岗位')` 再返回。同一个动作，两个入口，两种反馈。
- **缺了会怎样**：不是缺，是重复。用户从不同入口做同一件事得到不同结果，会怀疑这两个是不是不一样的东西。
- **建议**：留一个。留哪个由设计定；留下来的那个不要新写提示语。

### 4.4 相似职位 —— 不补，改成「这家还在招 N 个」

- **现状**：全仓 `grep 相似` = 0。
- **判断**：BOSS 的「相似职位」是「这个不合适、再刷几个」的兜底，在我们这儿那是代理的活，用户从详情退出来就是回代理筛好的市场流。**但**「这家公司还在招什么」是真需求，而且已经做好了——`企业详情.tsx:369-395` 的岗位层。
- **建议**：在职位详情的公司卡上带一行在招数（`档.在招岗位数` 已有），点进去就是那个层。不做「相似职位」推荐位。

### 4.5 福利 chip 行 —— 不补

BOSS 在 JD 上方堆「五险一金 / 餐补 / 年度旅游」。我们的立场是福利 = 待核条款（`企业详情.tsx:212-223`，分「代理已核对」和「公司自述，尚未核对」两组）。在职位详情重新摆一排未经核实的宣传 chip，会把我们刚建立的「已核 / 自述」区分打掉。**不补。** 若要在职位详情露出，只露「共 N 条条款 · M 条已核」这个数。

### 4.6 举报 —— 已覆盖，做得好

`举报层.tsx` 三处共用（职位详情 / 直聊 / 真人会话），4 个原因 + 「同时屏蔽」联动真实拉黑（`举报层.tsx:39`），且屏蔽在看市场里真的生效（`看市场.tsx:70-83`）。BOSS 的举报没有联动屏蔽这一层。

## 5. 沟通 / 消息

### 现状

`消息列表.tsx`：大标题 + 放大镜 → 三页签（全部 / 仅会话 / 通知）→ 搜索条 → 会话行（头像 + 标题 + 副标题 + 时间 + 摘要 + 未读数胶囊 / 红点）。会话行不放任何操作按钮，点整行进对应会话页。

三类会话：AI代理动态 → `问AI代理`；直聊 → `直聊会话`；真人 → `真人会话`（`消息列表.tsx:44-48`）。

### 5.1 会话没有身份 —— 必须修（C 类断链）

- **现状**：`路径表.ts` 里 `直聊会话: '/chat/direct'`、`真人会话: '/chat/human'`，**都没有参数**。`取跳转路径` 按会话**类型**映射到固定路由（`消息列表.tsx:44-48`）。职位详情的「直接聊」也是 `跳转(路径.直聊会话)`（`职位详情.tsx:123`），落到写死的「陆知遥 · MiniMax」（`直聊会话.tsx:43-45`）。
- **缺了会怎样**：从任何一个岗点「直接聊」，进的都是同一个人的同一段对话。有两个直聊会话时，点哪个都一样。
- **建议**：两条路由加 `:id`。与 4.1 是同一个病根。

### 5.2 未读永远清不掉 —— 建议修

- **现状**：`消息列表` 直接读模块级常量 `模拟数据.ts:395` 的 `消息列表`（`消息列表.tsx:17、35`），未读数 `4` 和红点写死在数据里，**没有任何 dispatch 能改它**。对比：通知中心是真的会清的（`通知中心.tsx:30` 派发 `读通知`，`我的.tsx:52` 的铃铛红点跟着真实未读数走）。
- **缺了会怎样**：点进会话再出来，红点还在。用户会当作没读过，反复点。
- **建议**：把消息未读移进全局状态，点行即清。通知中心那套现成的可以照搬。

### 5.3 底部导航没有未读角标 —— 建议补

- **现状**：`玻璃导航栏.tsx` 全文 37 行，只有图标 + 文字 + 选中态，无角标。
- **缺了会怎样**：不在消息 Tab 上时，用户完全不知道有新消息。「代理替你谈完了一轮等你拍板」这种事，靠用户自己想起来去点消息 Tab。
- **建议**：补。纯结构，无文案。

### 5.4 置顶 / 免打扰 / 删除会话 —— 不补（本轮）

- **现状**：`grep 置顶` 在求职端只命中「需要你的卡置顶」这类排序注释，没有会话置顶。全仓无长按菜单。
- **判断**：BOSS 需要这些是因为求职者同时被几十个 HR 轰炸。我们的会话数结构性地少（AI 代理 1 条 + 直聊若干 + 意向确认后的真人若干），排序已经由「需要你」这条线接管。**先不补**，等真实会话量出来再看。

### 5.5 快捷回复 / 常用语 —— 不补，冲突

- **现状**：`grep 快捷回复` = 0。直聊有功能键行（换微信 / 换电话 / 发简历，`直聊会话.tsx:78`），真人会话已自动互换联系方式并钉在流顶（`真人会话.tsx:61-65`）。
- **判断**：**冲突点**——BOSS 的快捷回复是给求职者低成本批量应付海量 HR 用的。我们的产品前提是「批量应付这件事由代理做完了」，真人对话只在意向确认之后发生，每一条都是高价值的。给这里配一排「您好，我很感兴趣」的模板，等于承认代理没干成活。**明确不补。**

### 5.6 「立即沟通」/ 一键投简历 —— 已有等价物，且是有意的双盲 opt-out

- **现状**：BOSS 的「立即沟通」我们有对应物 = 职位详情发布人卡上的「直接聊」（`职位详情.tsx:121-126`）。落地页第一屏就是旁听条「你选择了自己聊，AI代理在旁听：只提醒、不插话」（`直聊会话.tsx:58-66`），消息流第一条系统条是「你们已互相看到身份 · 匿名保护结束」（`模拟数据.ts:1280`）。
- **判断**：这是**用结构而不是文案**表达了「点下去就实名」——旁听条和系统条是状态显示，不是提醒语。已覆盖，不需要再加任何东西。
- BOSS 的「一键投递简历（露真名）」则明确**不补**：递交简历在我们这里是四阶段的第二阶段，由代理隐去联系方式后发出（`我的简历.tsx:300`），跳过前面的匿名初筛直接实名投递，会把整个阶段机作废。

## 6. 我的

### 现状

`我的.tsx`：工具行（切身份 / 通知 / 设置）+ 头像行 → 我的简历 + 四统计（在谈 / 初筛中 / 待你拍 / 已归档）+ 代理状态卡 → 规则库 + 宫格：
- 常用功能：我的简历、求职意向、AI代理规则库、屏蔽名单（`我的.tsx:80-85`）
- 其他功能：披露偏好、历史接洽、帮助与客服（`我的.tsx:86-90`）

**隐私这块比 BOSS 强**：对现雇主隐身（关闭前有二次确认，`设置.tsx:150-173`）、逐项披露偏好（薪资数字与并行接触数**锁死在数据层**，`披露偏好.tsx:1-15`）、双向屏蔽、谁接触过我。

### 6.1 「谁接触过我」埋在三级 —— 建议提上来（Top 3）

- **现状**：`接触记录.tsx`（/visitors）唯一入口是 `设置.tsx:100-106`「设置 › 隐私与可见性 › 谁接触过我」。「我的」宫格里没有（`我的.tsx:80-90`）。
- **缺了会怎样**：BOSS 的「看过我」是「我的」一级入口，也是求职者最高频点的东西之一。我们这一屏做得比 BOSS 克制也更有立场（只列企业 + 动作 + 时间，不出现 HR 姓名 / 停留时长，`接触记录.tsx:1-6`），是双盲机制的透明面——**这正是要给用户看的东西**，埋在设置里等于没做。
- **建议**：提进「常用功能」宫格。

### 6.2 求职端没有「对方看到的我」预览 —— 建议补（Top 3）

- **现状**：`我的简历.tsx` 是本人视角（真名直接显示，第 8 行注释）。对方视角的组件存在（`组件/简历预览层.tsx`，永远只有代号），企业端也有完整的匿名在线简历页（`/hr/resume/:id`）。**求职端没有任何入口能看到「企业现在看到的我长什么样」。**
- **缺了会怎样**：这是双盲产品用户第一位的焦虑——「我到底暴露了多少」。披露偏好页给了规则（`披露偏好.tsx`），但规则不等于结果，用户看不到成品。
- **建议**：在「我的简历」顶部加一个预览入口，复用 `组件/简历预览层.tsx`。**这不是抄 BOSS**（BOSS 没有这个功能），是我们的机制必须自带的东西。

### 6.3 附件简历不能管理，且文件名是写死的 —— 建议修 + 补

- **现状**：`我的简历.tsx:289-307` 的 PDF 行，文件名硬编码 `'沈亦舟_简历_2026.pdf'`（第 299 行），而全局状态里有真实的 `简历文件名`（`应用状态.tsx:161`，注册时上传写入，`学生分流.tsx:78`、`工作经历.tsx:105`）。点一下只 toggle 一句「原型演示：真机上在这里打开系统 PDF 预览」。
- **缺了会怎样**：① 用户在注册时传了 `张三的简历.pdf`，进「我的简历」看到的是别人的文件名；② 传完之后**再也不能换 / 不能删 / 不能预览**——只有注册流那一次机会。
- **建议**：三件事。① 读全局 `简历文件名`（这是 bug）；② 复用 `工作经历.tsx:105` 已有的 file input 支持替换；③ 点开走已有的 `组件/简历预览层.tsx` 原件层（`在谈详情.tsx:327` 已经这么用了），不要 toggle 提示条。

### 6.4 「求职状态」三处各说各话 —— 建议收敛

- **现状**：至少三份真相：
  - `求职意向管理.tsx:27、81`：本地 `useState` 在三档里轮转，**不落全局**，返回再进就回到第一档；
  - `模拟数据.ts:1343` `我的信息.状态`：「我的」头像行显示它（`我的.tsx:137`）；
  - `基本信息.身份`（在校 / 在职 / 离职）：`我的简历.tsx:24-28` 用它算简历上的状态说法；
  - 另有注册流的 `求职状态` 屏（`/onboard/status`）写 `引导预填.到岗`。
- **缺了会怎样**：用户在意向管理里改成「离职 · 尽快到岗」，回到「我的」头像行还写着老状态，简历上又是第三种说法。
- **建议**：收敛到一处并落全局。这条**不是 BOSS 对照出来的缺口，是我们自己的数据一致性问题**，但它长在 BOSS 有的那个功能位上（求职意向管理），所以放这里。

### 6.5 设置页缺两组，且注释承诺了它们 —— 建议对齐

- **现状**：`设置.tsx:3-4` 注释写「分五组：账号 / 隐私与可见性 / 通知 / 通用 / 关于」，代码里只有账号、隐私与可见性、关于三组，第 108-110 行是两行空白。
- **缺了会怎样**：没有任何通知开关。代理是 7×24 在后台谈的（`代理详情.tsx`），用户唯一能做的是退出登录（`设置.tsx:139`）。
- **建议**：补通知组的最小集（至少一个总开关 + 一个「只在需要我拍板时提醒」），或者把注释里的承诺删掉。**不要**补一堆细分开关——代理的存在意义就是少打扰。

### 6.6 「我看过的」浏览历史 —— 不补

- **现状**：`grep 浏览` 在求职端只命中「浏览器」相关，`选择城市.tsx:22` 注释明说没有浏览历史。
- **判断**：BOSS 的「我看过的」价值在「从几百个里回头找那一个」。我们的列表是代理筛过的、量级小，且真正的需求（「拿不准，先留着」）应该用 2.4 那条解决，不该用一份被动记录的浏览日志去凑。**不补。**

## 7. 投递管理

我们没有「投递」这个动作。等价物 = 委托代理 → 在谈单 → 四阶段（匿名初筛 → 递交简历 → 需要协调 → 意向确认）→ 归档（历史接洽）。

**这块整体比 BOSS 强**：BOSS 的「已投递 / 已查看 / 邀面试 / 不合适」是四个死状态标；我们的四阶段每一阶段都有代理小结、核对清单、双方对话流（`组件/阶段对话流`）、可就地介入（`在谈详情.tsx:295-306`）。「已查看」的等价物是 `接触记录.tsx` 的三档动作（查看画像 / 发起接触 / 递交简历后查看），比 BOSS 细。

### 7.1 没有跨意向的总览，且两个数字对不上 —— 建议补（强候选）

- **现状**：
  - 「我的」四统计读**全量** `状态.在谈列表.length`（`我的.tsx:57-68`）；
  - 「在谈」列表按**当前意向**过滤 `单.意向 === 状态.当前意向`（`在谈首页.tsx:31`）；
  - 顶部意向栏是左右平铺切换（`顶部意向栏.tsx:60-72`），**没有「全部」这一档**。
- **缺了会怎样**：用户在「我的」看到「在谈 5」，切回职位 Tab 只看到 3 张卡，剩下 2 个在另一个意向下。他不知道少的 2 个去哪了，也没有任何视图能一次看全。**这就是「投递后想看进度」最直接的失败点。**
- **建议**：二选一——① 意向栏加「全部」档；② 统计跟着当前意向走。前者更符合「一份简历挂多个意向、各自独立谈」的设计（`我的简历.tsx:309-314`），但需要产品拍板。

### 7.2 「未通过说明」整屏没有入口 —— 必须修（C 类断链）

- **现状**：`屏幕/未通过说明.tsx`（148 行，硬性核对 4/5 逐条 ✓✗ + 代理小结 + 「要不要松一档」量化建议 + 维持红线 / 改成可谈两个动作）已经写完并挂在 `/rejected`（`应用.tsx:138`）。全仓 `grep` 结果：**除了路由注册，没有任何一处跳转到它**。归档列表里「对方未通过」的条目点进去是 `往来记录`（`归档谈判.tsx:40`），也就是一条纯对话流。
- **缺了会怎样**：用户被刷掉之后最想知道的「我为什么没过、卡在哪一条」，有一张专门做好的页在那儿，但没人能走到。这是 BOSS「不合适」状态在我们这儿的强化版，白做了。
- **建议**：归档列表里 `结果 === '对方未通过'` 的条目跳 `/rejected`（并按 6.x 的做法带上编号，现在它读的也是单例 `模拟数据.ts:1318`）。

### 7.3 面试日程 / 面试邀约 —— 待确认产品边界，本轮不补

- **现状**：求职端 `grep 面试` 零命中（企业端有 `发布岗位` 的面试轮次字段）。产品的四阶段止于意向确认，之后 `跳转(路径.真人会话)`（`在谈详情.tsx:238`），面试安排全在聊天正文里（`模拟数据.ts` 真人会话摘要「面试官是邵铭 + 架构评审组，流程约 90 分钟」）。企业端注释明写「面试邀约先不做」（`企业真人会话.tsx:22`）。
- **判断**：这是四阶段之后的整片空白。**需要产品先回答一个问题：意向确认之后，我们还管不管？** 如果管，第一步是真人会话里的结构化「面试邀约卡」（时间 / 地点 / 轮次 / 接受或改期），不是一个独立的日程页。如果不管，就明确写进产品边界，不要留着当缺口。
- **本轮建议**：不补，列为 D 类待确认。

## 9. 明确「不补」清单（含理由）

| BOSS 有的 | 不补的理由 |
|---|---|
| 一键投递简历（露真名） | 跳过匿名初筛直接实名，四阶段作废 |
| 快捷回复 / 常用语 | 它是用来批量应付海量 HR 的；批量应付在我们这儿是代理干的活 |
| 列表排序器（薪资 / 最新） | 排序权在代理；给排序器 = 把代理降级成列表控件。只补默认序 |
| 相似职位推荐位 | 真需求是「这家还在招什么」，已在企业详情里做完，接上入口即可 |
| 职位详情的福利 chip 行 | 会打掉我们「已核对 / 公司自述」的区分。只露「N 条条款 · M 条已核」 |
| 公司主页的员工文字点评 | 要配审核 + 申诉整套；我们的命题是代理核过什么，不是众包口碑 |
| 「我看过的」浏览历史 | 用被动日志凑「拿不准先留着」的需求，不如直接做那个功能 |
| 会话置顶 / 免打扰 | 会话量结构性地少，排序已由「需要你」接管。等真实量级 |
| 竞争者人数 / 你超过 X% | 可反推他人，与双盲直接冲突（`企业详情.tsx:7-9` 已经写死了这条立场） |
