## 一、她改了什么（按主题）

### ① 流程与配置：新建 `src/流程/onboarding配置.ts`

这是她这轮的地基文件，定义了 5 类东西：

1. **类型**：`Onboarding角色`（学生求职 / 社招求职 / 招聘方）、`求职类型`（社招全职 / 校园招聘 / 实习生 / 兼职）、`办公偏好`（现场 / 混合 / 全远程）、`求职薪资单位`（月薪K / 元/天）、`求职初筛偏好` 接口（求职类型、办公方式、毕业时间、实习月数、每周到岗天数、实习开始日期、作品集链接）。
2. **`Onboarding流程`**：三个角色各自的页面路径数组，自称是「首次注册的唯一流程合同，页面跳转与自动化测试共用」。
3. **`初筛字段矩阵`**：通用 / 社招 / 学生 / 实习 四组字段名常量。
4. **`身份首次入口(身份)`**：企业 → `路径.企业实名认证`，求职者 → `路径.引导说明`。
5. **三个纯函数**：`求职初筛缺失项()` 校验必填、`迁移主要求职类型()` 处理旧缓存里同时存了「校招 + 实习」导致月薪/日薪口径打架的情况、`判断求职薪资单位()` 决定滚轮走月薪还是日薪。

**重要事实**：`Onboarding流程` 和 `初筛字段矩阵` 这两个导出，**除测试文件外全仓库无人引用**（grep 全库确认）。实际页面跳转仍是各屏各自硬编码 `跳转(路径.X)`。真正被业务代码用到的只有 `身份首次入口`（选身份.tsx:101）、`默认求职初筛偏好` / `求职初筛缺失项`（学生分流.tsx）、`判断求职薪资单位`（引导问答.tsx:42）、`迁移主要求职类型`（应用状态.tsx:315）。所以文件头注释里那句「页面跳转与自动化测试共用」目前不成立——它是一份**文档 + 测试断言**，不是运行时合同。

## 四、她带来的净收益（客观）

1. **从零建起测试基建**。此前仓库没有任何 `*.test.*` / `*.spec.*`。现在有 vitest（jsdom + testing-library，20 用例实测全绿）+ Playwright（iPhone 13 mobile-chromium，3 条真实浏览器 e2e），并接上 `npm run test` / `test:e2e`。e2e 那条「发布实习岗全流程」是真正端到端的，不是 mock 出来的假 e2e。

2. **reducer 纯化**。把 9 处散在 `归约()` 里的 `localStorage` 写入搬到 Provider 的 8 个 `useEffect`，reducer 恢复成纯函数。这在 React StrictMode / 未来并发渲染下是实打实的正确性修复，不是洁癖——单测 `应用状态.test.ts` 里那条「更新认证状态时不直接写 localStorage」正好锁住它。

3. **弹层可访问性一次性收口**。`弹层框架` 一个组件解决了 15+ 处手写遮罩的键盘不可达、无 dialog 语义、无焦点管理、Escape 不响应，并有 3 条单测护着。配上 oxlint 的 4 条 jsx-a11y error 规则，后续新写的 click-div 会被 lint 直接拦下。

4. **路由级 lazy 分包**。登录首屏从「一次性打包全部约 60 屏、807.84KB / gzip 238.47KB」降到约 397KB / gzip 131KB，构建不再报 500KB 大包警告。手机端首屏这是很实的收益。

5. **两个真 bug 修复**：
   - `候选推荐.tsx` 的 `useMemo` 漏 `状态.推荐列表` 依赖（推荐池变化后列表不刷新）；
   - `发布岗位` 新建路径硬编码 `${下限}-${上限}K`，实习/兼职岗薪资单位会被写错——她改成一次派发完整岗位对象，顺带消掉了「先建半成品再补字段、编号可能对不上」这个隐患。

6. **「结构化初筛 vs 加分排序」这个思路本身是对的**。必备技能池 / 加分项池分离、`初筛字段矩阵`、发布前的「AI 初筛条件确认」摘要、`薪资初筛()` 只回结论不回数字、以及审计文档里「未采集到答案返回『待核对』而不是『不符合』」「改必须项只对新筛选生效、不静默改写历史结论」这两条后端约束——都是我们之前没写下来的、值得吸收的东西。分歧在于「自由文本要不要保留淘汰权」，不在「要不要有结构化字段」。

7. **薪资单位漂移保护**。`迁移主要求职类型()` + 启动时校验缓存单位、不匹配就丢弃薪资——这是我们之前没考虑过的老缓存脏数据场景（同时存了校招月薪和实习日薪）。

8. **两份文档本身有价值**。评审文档对 mockup 阶段的定性（「直接用模拟数据不算缺陷」）是克制且准确的；P0 薪资口径冲突确实是我们代码里 README/类型注释与 UI 行为不一致的地方，她提出来了。审计文档的 LinkedIn / Indeed 对标是可复用的产品参照。
