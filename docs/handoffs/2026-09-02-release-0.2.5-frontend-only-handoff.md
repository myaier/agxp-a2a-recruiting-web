`src/屏幕/添加意向.tsx` 当前同时存在：

```ts
const 可保存 = 草稿.工作城市 !== '' && 草稿.期望职位 !== '' && 草稿.办公方式.length > 0;

const 提交 = async () => {
  if (!可保存) return;

```

- 城市和职位已填、办公方式为空时，用户点击保存必须看到“请选择办公方式”；
- 将焦点或视口引导到办公方式组，提供可访问的 invalid/description 关联；
- 选择任一办公方式后清除该错误；
- 其它必填项继续执行现有校验，不因本修复被绕过；

- 不自动补 onsite/hybrid/remote，不修改 BFF contract。

实现可以让保存按钮在存在表单错误时仍可点击并集中校验，也可以使用等价的 inline error 方案；完成态不能保留“按钮不可用但没有原因”。

## 6. 交付 C：候选岗位深链恢复与安全返回

> **状态：已完成，原问题已失效。** 判定时间：`2026-09-05 05:37 +08:00`。依据：当前前端 `main@fc006281` 的 `src/屏幕/职位详情.tsx` 已按路由岗位 ID 复用当前意向推荐快照，缺失时走现有 CandidateJob 权威读取；未命中时保留安全只读/不可用语义，不回退 Mock 或其它岗位。对应深链、刷新、跨 scope 与安全返回测试已存在。保留下文作为冻结合同与回归验收记录，不再重复领取实现。

### 6.1 当前问题

Backend 职位详情只从当前意向的内存推荐快照寻找 `recommendation_id`。刷新或直接打开职位 URL 时，页面退回裸 CandidateJob，职位仍可读，但反馈和委托被禁用；返回按钮在没有站内 history 时可能离开应用。

后端 release 已提供按 `intention_id` 读取 candidate recommendation list，推荐卡带完整 CandidateJob、推荐坐标和 latest delegation summary，因此不需要新增接口。

### 6.2 实现要求

访问候选职位详情时：

1. 当前意向和对应推荐快照已在内存时直接复用，不增加请求；
2. 快照缺失时，先完成现有 candidate intentions 水合，再按**当前意向**调用已有 recommendation list；
3. 只在返回卡的 `job.job_id` 等于路由 job ID 时恢复 `recommendation_id`、`intention_id` 和 delegation；
4. 不扫描其它意向、不借用另一 scope 的 recommendation ID；
5. 裸 CandidateJob 可读但当前意向没有推荐时，继续显示只读详情，并明确说明当前不能做推荐反馈或委托；
6. 404、401、scope/role/subject/route 切换及迟到 response 继续走现有 generation fence；
7. 有有效站内来源时正常返回；无有效 history 时 replace 到候选市场稳定路由，不进入 `about:blank`，不回 Mock 页面。

### 6.3 测试

- 刷新/深链可以恢复同一意向推荐坐标与 delegation；
- 当前意向无对应推荐时保持只读且零 mutation；
- 多意向存在同一 job 时绝不跨 scope 借坐标；
- 旧账号、旧角色、旧路由的迟到 response 被丢弃；
- 有 history 正常返回，无 history 回市场稳定路由。

### 8.1 只使用 release 已有状态


### 8.2 文案、恢复和导航

| 状态 | Backend 页面文案 | 行为 |
| --- | --- | --- |
| `accepted` | 已提交给 AI，等待处理 | 保持轮询，不声称已接手/已联系 |
| `evaluating` | AI 正在评估 | 保持轮询，禁止重复提交 |
| `case_started` | 已创建真实在谈 | `case_id` 非空时显示“查看进展” |
| `needs_user` | 需要你处理 | 只展示当前后端已允许的入口，不猜动作 |
| `refused` | 本次未能继续 | 按现有 refusal code 显示安全原因 |
| `failed` | 本次处理未完成 | 显示通用安全失败，不生成本地 Case |

要求：

1. 删除 Backend 分支中的“AI代理已接手”“已开始沟通”等过早成功文案；Mock 分支原型可以保留；
2. candidate/recruiter 卡片与详情使用同一状态文案表；
3. `case_started` 只使用后端 `case_id` 导航对应角色 MatchCase detail，不从 job/recommendation/alias 推导；
4. 刷新推荐 scope 后从推荐卡 delegation summary 或现有 delegation list/get 恢复状态；不得只依赖 React 内存；
5. terminal 状态清除进行中 UI，保留通用可读结果；是否允许重新发起仍遵循当前页面业务条件和完整 PDF/披露流程；
6. 轮询失败上界、single-flight、session/scope generation fence 继续复用现有 operation/hook；
7. 后端返回未知状态/错误词时 strict decoder fail closed，不为未来合同写宽松兼容。

未来 `delegation_agent_unavailable`、`delegation_evaluation_failed` 等精确原因留在 Hosted Agent 前端 Handoff，等待后端实现后再接。

### 8.3 Case 可发现性

- `case_started` CTA 与“在谈”列表必须导航同一个 server `case_id`；
- candidate/recruiter 列表和详情都从现有 MatchCase API 权威读取；
- 页面刷新、App reload 和角色切换后不生成本地“在谈”填空；

本轮不新增 Agent chat、日报或漏斗 API。未来只有在后端提供批准后的真实合同后才能恢复 Backend 输入框。

### 10.3 测试

## 12. 实施拆分与并行边界

建议 Coding Agent 写成一份 Spec，并按冲突面拆为三个可独立验证的 Plan：

1. **表单与详情 truthfulness**：交付 A、D；
2. **Discovery/Case 状态与导航**：交付 B、C、E、F；
3. **Backend/Mock Agent 页面隔离**：交付 G。

三个 Plan 不依赖后端修改，可以使用隔离 worktree 并行；但 Plan 2 会集中修改 P4/P5 状态与路由，内部不要再按页面拆成多个并行 writer。最终由一个集成 owner 合并，统一运行前端测试和 backend-mode 浏览器走查。

如果 Coding Agent 判断修改文件高度重叠，也可以合并为一个 Plan；不要为了并行制造共享 selector、通用错误框架或额外状态层。

## 13. 验证要求

### 13.1 定向测试

每项修改先运行对应 Vitest。测试必须同时覆盖 Backend truthfulness 和 Mock 不回归，且断言零错误 mutation、零跨 scope 污染、零 Mock fallback。

### 13.2 前端验证门

实现收敛后至少运行仓库当前有效的：

```text
npm run test -- <target test files>
npm run typecheck
npm run lint
npm run build
```

若仓库提供正式 affected/changed-files gate，以仓库规则指定入口作为唯一 plan-scope broad gate。

### 13.3 Backend-mode agent-browser 走查

使用 `VITE_DATA_SOURCE=backend`，连接未修改的 `release/0.2.5@45f7323e` 环境，验证：

1. 新建和编辑求职意向时，办公方式为空有可见反馈；
2. 未验证组织的岗位进入候选推荐页，页面在发请求前给出准确前置说明；
3. 候选推荐职位刷新/深链后恢复当前意向坐标，或安全降级为只读；
4. 职位详情显示城市、办公方式、办公地点和年薪月数，结构化/自由文本说明不混淆；
5. 委托只显示 accepted/evaluating 真实中间态；若后端 task 因当前已知问题失败，UI 显示当前合同允许的通用失败，不声称成功；
6. 任何已有 `case_started` fixture/记录都使用真实 `case_id` 进入 MatchCase；
7. P5 `screening_resume` 与 parse/人工决定阶段文案明确；
8. 候选和招聘“问 AI 代理”页面只显示 Backend truthful 说明，无假统计或假回复；
9. Mock 模式抽样确认原型仍可使用。

本批次不要求真实 Agent task completion；那属于后端身份/Runtime 修复后的集成 Handoff。浏览器验收不能因当前 Agent 后端失败而改写数据库或回退 Mock。
