## onboarding求职端


### P0

**基本信息采集屏（姓名/开始工作年份/在校或在职身份）**

- BOSS：注册后必填基本信息页：头像、姓名、性别、出生年月、开始工作年份、在校或在职身份
- 我们：注册流四屏为 引导说明.tsx→工作经历.tsx→引导问答.tsx→披露说明.tsx，全程无任何基本信息表单；我的简历.tsx 第 33-38 行的基本信息（姓名/工作年限/最高学历/当前状态）初值直接取 模拟数据.ts 的 我的信息.姓名 与写死的「9 年」，onboarding 从未采集；而 模拟数据.ts 未通过说明.核对项 显示匿名初筛要用「年限 9 年 ≥ 要求 5 年」做硬性核对，年限数据无采集来源
- 补法：在引导说明与工作经历之间加一屏极简「基本信息」：真名（灰字注「仅意向确认后披露」，服从双盲）、开始工作年份（滚轮选择，自动折算年限供匿名初筛核对）、在校/在职身份；头像/性别/出生年月不收或深度弱化——匿名期用代号+首字，符合双盲与做减法的设计文化


### P1

**专业技能标签**

- BOSS：在线简历有独立「专业技能」标签分节，选标签构成简历画像
- 我们：全仓 grep 无「技能标签」；引导问答.tsx 优势题只有 500 字自由文本 + GitHub 链接；模拟数据.ts 未通过说明.核对项 里匿名初筛要核对「技术域——基础架构，与你的后端经验对口」，目前只能靠期望职位方向间接推断，无结构化技能数据
- 补法：在优势题下加「专业技能」标签选择（从上传简历解析预选、可增删，词表复用行业字典的方向层）；标签进匿名画像参与技术域核对——技能标签不暴露身份，匿名初筛阶段可安全披露，正是双盲下最该结构化的字段

**项目经历分节**

- BOSS：在线简历有独立「项目经历」分节（项目名/角色/时间/描述）
- 我们：全仓 grep 无「项目经历」；工作经历.tsx 编辑页只有单个「工作内容」textarea；我的简历.tsx 分节仅有 基本信息/工作经历/个人优势/附件简历 四块
- 补法：不做独立大分节（服从极简），在工作经历编辑页内加「关键项目」子条目（项目名+角色+一句话结果）；代理在「递交简历」阶段自动脱敏（隐去可识别雇主的字眼）后放入匿名材料，匿名初筛阶段不披露


### P2

**教育经历多段支持**

- BOSS：教育经历可添加多段（本科+硕士等）
- 我们：工作经历.tsx 第 93 行 教育 是单个 教育段 useState，列表视图只渲染一张教育卡且无「添加教育经历」按钮，初始值写死上海交通大学硕士一段
- 补法：把 教育 改为列表 + 复用现有「＋ 添加」行与教育编辑页，匿名画像仍只披露最高学历一档（学历层级不指向身份）

**在校/应届求职状态档**

- BOSS：求职状态含「离校-随时到岗」（应届/在校生）档
- 我们：引导问答.tsx 第 594-599 行 到岗选项 四项全部为「离职/在职」前缀，无在校或应届档；而同文件薪资档注释（第 375-378 行）明确写「应届与实习集中在 1-10K，每 1K 一档才够用」，说明产品预期覆盖应届但状态题走不通
- 补法：到岗题增加「在校 · 离校随时到岗」一档（或由基本信息屏的在校身份自动带出），复用现有「优先推荐」徽标逻辑，不另起分支流程

**资格证书分节**

- BOSS：在线简历有「资格证书」分节
- 我们：全仓 grep 无「证书」；我的简历.tsx 与 工作经历.tsx 均无该分节或字段
- 补法：我的简历加选填「资格证书」分节（证书名+取得年份），证书不指向个人身份、匿名初筛阶段可披露，作为硬性条件核对的加分素材；onboarding 不强制收，保持流程轻

**多求职意向的建档引导与行业字段口径统一**

- BOSS：求职期望可添加多个意向，每个意向 = 职位类型+城市+薪资范围+行业偏好
- 我们：引导问答.tsx 一轮只产出一份职位/城市/薪资答案，最后一题直接跳披露说明，无「可再加一个意向」提示；添加意向.tsx 已有完整表单（含独立「期望行业」字段）但只能事后从求职意向管理进入；且引导问答把行业做成期望职位题内的「xx（行业）」附带标签，与 添加意向 的期望行业字段口径不一致
- 补法：披露说明完成进主壳后，顶部意向栏以一行轻提示引导「＋ 添加第二个意向」复用现有添加意向表单（onboarding 本身保持单意向、不加屏）；同时把引导问答的行业标签与 添加意向.期望行业 统一成同一字段

## 求职端主流程


### P0

**职位关键词搜索**

- BOSS：顶部搜索框，按职位名/公司/技能关键词直接搜职位。
- 我们：顶部意向栏.tsx 的放大镜（aria-label「搜索职位」）点击只派发「切子视图→看市场」，看市场.tsx 列表仅按当前意向过滤；全站没有任何职位搜索输入框（消息列表.tsx 的搜索只搜会话）。放大镜承诺了搜索但没兑现，属误导性死入口。
- 补法：点放大镜在看市场顶部展开一条搜索行，对职位名/公司行/标签做本地包含匹配即可；搜索空态引导「让AI代理帮你搜」跳问AI代理（问AI代理.tsx 的回复规则表已有搜岗话术）。保持极简：一个输入框，不做历史词/热搜。

**职位筛选器**

- BOSS：薪资/经验/学历/公司规模/融资阶段/距离多维筛选器。
- 我们：顶部意向栏.tsx「筛选 ▾」按钮点击只弹 轻提示('筛选功能待接后端条件项')，是死按钮；数据/类型.ts 的 市场职位 也没有经验/学历等可筛字段。
- 补法：底部抽屉给少量软性维度：办公方式（远程/混合/现场）、城市、企业直招/猎头、适配分下限。薪资维度只做「薪资带与我有交集」单开关（代理已知带宽交集判断），绝不出数字区间滑杆，守住双向不披露口径。


### P1

**收藏职位**

- BOSS：收藏职位列表，跨会话保存待看岗位。
- 我们：职位详情.tsx 的 ☆ 收藏是本地 useState（注释自认「只是这一屏的视觉开关，不进全局 store」），离开页面即丢；应用状态.tsx 无收藏字段，全站无收藏列表入口；看市场.tsx 卡片按设计刻意不放收藏图标。
- 补法：收藏写入全局状态持久化，定位为「先收着、还没让代理去谈」的待办池：在看市场筛选抽屉加「只看收藏」，与「AI代理已接手」状态互斥展示；不在卡片上加图标，维持做减法的卡面。

**面试管理（邀约/日程/结果）**

- BOSS：面试邀约、日程提醒、面试结果一体化管理。
- 我们：真人会话.tsx 功能键行只有换电话/换微信/发简历，无任何面试邀约/时间/结果元素；消息列表.tsx 与通知中心.tsx 也没有日程聚合。意向确认转真人后，约面试只能靠纯文字自由聊。
- 补法：按本产品口径长在意向确认后的真人聊天里：功能键行加「约面试」，发出结构化面试卡（时间/方式/地点）落进消息流，双方点确认后在真人会话顶部职位卡下挂一行日程提醒，AI代理只提醒不介入（复用直聊会话.tsx 的「代理提醒」灰条）。

**「不感兴趣」未接入状态与代理学习**

- BOSS：点「不感兴趣」后该职位从推荐流剔除并影响后续推荐。
- 我们：职位详情.tsx 抽屉里「不感兴趣，别再推给我」点击只是关抽屉+返回（onClick 仅 设抽屉展开(false)+返回()），不写任何全局状态，岗位仍留在看市场流里，代理也学不到任何东西。
- 补法：派发「不感兴趣」动作把该岗从市场流过滤掉，并复用拿不准弹层（A24）追问一句「要不要记成规则」——把单次否决沉淀为代理的长期过滤规则，直接接上规则库.tsx 已有的叮嘱→规则机制，这是比 BOSS 更符合本产品的改法。


### P2

**举报入口**

- BOSS：职位与招聘者均有举报入口（假岗/骚扰等），平台治理标配。
- 我们：职位详情.tsx「⋯」抽屉只有「不感兴趣」和「取消」；直聊会话.tsx/真人会话.tsx 右上「⋯」是纯展示 span 点不动；全站求职端无举报路径。
- 补法：在职位详情抽屉和两个会话页「⋯」菜单补「举报」项，选分类原因提交，提交后可顺手一键加入屏蔽名单（复用已有双向屏蔽机制），不另起新页面。

**对接人响应时效（HR活跃度的代理化改造）**

- BOSS：职位详情展示 HR 活跃度（如「刚刚活跃」），帮用户判断值不值得开聊。
- 我们：职位详情.tsx 发布人卡只有姓名/公司/职务/静态备注；唯一的时效信息是往来记录.tsx 里写死的系统条「等待对方代理响应 · 一般 24 小时内」。
- 补法：招聘方从第一轮起实名，展示合规：在发布人卡加一行「对方代理通常 N 小时内回」——用对方代理的历史响应数据替代真人在线状态，帮用户在「直接聊」和「让代理去谈」之间做选择，不违反任何双盲约束。

## 企业端建档与岗位


### P0

**岗位编辑（发布后可改）**

- BOSS：职位发布后可随时编辑职位内容并重新上线
- 我们：发布岗位.tsx 只有新建路径（派发'发布岗位'）；岗位管理.tsx 左滑仅 停止招聘/删除/重新开放，点在招岗行是「切当前岗位」，全库无任何编辑入口
- 补法：岗位管理左滑加「编辑」进入发布岗位三步表单的编辑态（预填现值）；保存改动硬性条件时由代理对在谈单做一次增量核对，阶段既不回退也不跳跃，只更新核对清单。

**硬性条件可配置（初筛合同写死）**

- BOSS：发职位时技能标签/要求可自由配置
- 我们：发布岗位.tsx 第 28 行 硬性条件选项 硬编码为 ['Go 主栈','5 年以上','常驻上海','可混合办公']，发风控算法等任何其他岗位都无法表达自己的初筛条件——而硬性条件是匿名初筛（四阶段第一段）的执行合同
- 补法：支持原地添加自定义条件片（复用企业代理设置.tsx 的折叠输入行交互），并让代理从「职位要求」文本建议生成候选片供勾选。


### P1

**企业主体认证材料**

- BOSS：企业认证需营业执照/在职证明
- 我们：企业实名认证.tsx 仅 1.2 秒模拟人脸识别，要点宣称核验「任职公司」但无任何营业执照/在职证明的材料环节；候选端企业详情.tsx 展示「工商信息·已核验」却无企业端来源
- 补法：认证分两层：个人（人脸+在职证明）与企业主体（首位认证人提交执照，后续同事复用），沿用现有「要点行」版式逐项打勾完成，保持一屏极简——这是实名承诺的信任地基。

**公司档案维护入口**

- BOSS：企业可维护公司主页（简介/福利/地址/资质合规展示）
- 我们：企业详情.tsx 是候选端视角（读 数据/公司档案 展示公司自述/作息与条款/办公地/工商信息），企业端 onboarding 与「我的」均没有维护这些内容的任何界面
- 补法：企业端加「公司档案」编辑页，字段与候选端企业详情一一对应（自述三段/作息/条款清单/办公地）；条款默认标「自述」，被对方代理核对后升「已核」，呼应现有的核对文化。

**重新寻访（刷新/重发的双盲版）**

- BOSS：刷新/重发提升职位曝光排序
