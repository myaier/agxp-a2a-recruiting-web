# 本周初筛记录规格（标注 2026-08-21 17:39）

用户原话（在企业端主页标注「AI代理动态 / 你的招聘AI代理 / 本周替你初筛 …」这一行）：
「我们模拟两个已经完成筛选的对话，我看看是什么样子的」

## 现状与缺口

日报卡上写着「触达 23 → 硬性匹配 12」、「昨夜新触达 8 人，替你挡掉 3 个硬性不符的」，
但这些数字**点不动**，代理到底怎么筛的、挡掉的是谁、按哪条硬性条件挡的，全都看不到。
这与项目里已有的产品原则冲突 —— 见 src/屏幕/已筛候选.tsx 的注释：
「负反馈必须可回看、可撤销，否则它就是一个静默的黑洞」。
代理替你挡掉的人，同样不能是黑洞。

## 入口

企业端 消息 Tab →「AI代理动态」→ 企业问AI代理 → 日报卡内的人才漏斗
→ 「硬性匹配」那一行整行可点 → `/hr/screening-log`。
漏斗其余四行保持不可点（本轮只做这一档）。

## 屏：本周初筛记录（`/hr/screening-log`）

- 返回栏 ‹ + 标题「本周初筛记录」
- 列表按岗位分组（P-01 / P-02），每组一个小节头（岗位名）
- 每条 = 双盲头像（头像字 + 灰绿底）+ 代号 + 画像 + 右侧结果标
  - 结果标两种：「通过」（深绿）/「挡掉」（灰）
  - 第二行小字：硬性 N/5 + 完成时间
- 点条目 → `/hr/screening-log/:编号`，整屏一段对话

## 屏：单条初筛对话（`/hr/screening-log/:编号`）

- 返回栏 ‹ + 标题 = 代号
- 顶部一张结论卡：结果（通过 / 挡掉）+ 硬性核对清单（逐项 项/结果）
- 下方是双方代理的完整初筛对话，**复用 src/组件/阶段对话流.tsx**，
  只传一个分段（阶段='匿名初筛'，态='已完成'，默认展开=true），
  这样它与在谈详情 / 候选详情里的对话是同一种版式，不另画一套。
- 没有输入条：这是回看，不是进行中的单子。

## 数据：两条完整样本（写进 src/数据/企业端模拟数据.ts）

新增 `export const 本周初筛记录` 与 `export const 初筛对话表`。

**样本一 · 通过**（岗位 P-01 资深后端 · 交易网关）
代号 苏含章（复用现有 A-07 的画像：10 年 · Go / 中间件 · 阿里云），硬性 5/5，结果 通过。
对话覆盖完整一轮初筛：开场亮硬性 → 对方给年限与方向 → 核城市与办公方式 →
薪资只核「有没有交集」不交换数值 → 到岗档 → 5/5 收束、进入递交简历。
**这条初筛完成后进了在谈**，所以列表里要能对上现有的 A-07。

**样本二 · 挡掉**（岗位 P-01 同岗）
新造一条：代号 何砚清，画像「6 年 · Java / 电商中台 · 某电商平台」，硬性 3/5，结果 挡掉。
挡在两条硬性上：年限 6 年（要求 5 年+，这条过）、主栈 Java 非 Go（不过）、
常驻杭州不接受迁沪（不过）。对话要体现代理**当场挡掉、不把人推给委托人**的口径：
最后一句是我方代理说明按哪两条硬性挡掉、不再推进，且不会告知对方是哪家公司。

## 硬约束

- 双盲不破：全程只有代号与画像，没有真名；薪资只出现「有交集 / 落在区间内」这类结论，
  绝不出现任何具体数字。
- 不加自创解释性小文案。结果标只用「通过」/「挡掉」两个词。
- 对话条数据结构用现有的 `对话条`（编号 / 方 / 时间 / 内容），不新增字段。
- 挡掉的那条**不进在谈列表**，只在本记录里可见 —— 这正是它存在的意义。
