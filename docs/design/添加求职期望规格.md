排在最后一行。（若用户要求删，删这一行即可，其余不动。）

5. 底部固定按钮：新建态单个「保存」；编辑态「删除 + 保存」两键（沿用现状）。

## 弹层 C：薪资要求（底部双滚轮）

## 弹层 D：本意向底线（底部单滚轮）

复用现有 `数字滚轮层`，范围 3–100，单位「K」。

## 状态：意向草稿 slice

跳次级页再回来不能丢已填内容，也不能污染 onboarding 的 `引导预填`。
在 `应用状态` 新增 slice：

```ts
意向草稿: {
  编辑编号: string | null;   // null = 新建
  求职类型: '全职' | '兼职';
  工作城市: string;
  期望职位: string;
  感兴趣城市们: string[];    // ≤ 9
  薪资下限: number | null;   // 千元
  薪资上限: number | null;
  期望行业们: string[];      // ≤ 3
  底线: number | null;
}
```

动作：`开意向草稿(编号|null)`（进页面时重置或从已有意向拆回）、
`改意向草稿(补丁)`（次级页与本页共用）、`清意向草稿()`（保存或退出后）。

`/onboard/city` 与 `/onboard/job` 带 `?来源=意向` 时写 `改意向草稿` 并 `返回()`，
不带时保持现有写 `引导预填` 的行为不变 —— onboarding 流程零回归。

## 硬规则

- 不加自创解释性小文案；label 与占位一律用截图原词。
- 薪资数字只出现在求职者自己的配置页；不影响双盲（代理间仍只交换「有无交集」）。
- 两端同构不适用：这是求职端独有页面，企业端无对应。

## 经历屏的两条定稿（用户 2026-08-22 截图标注）

用户原话：「我们第一个标题写教育经历这个改一下吧，还有作品集放错位置，
也改到类似于实习或者工作经历的下面。是不是合理一点」

1. **`工作经历.tsx` 的屏标题不能用其中一个区块名**。这一屏装着四块：
   教育经历 / 工作经历（学生态叫实习经历）/ 专业技能 / 证书与语言。
   学生态原来标题写「教育经历」，下面却紧跟着实习经历，名不副实。
   标题要能涵盖全屏内容，且两态都说得通。不加解释性小文案。

2. **作品集链接归这一屏，排在经历区块下面**，与「专业技能」「证书与语言」并列。
   理由：作品集是「我做过什么」的证据，和经历同类 —— 经历是文字版，
   作品集是可点开的版本；而它原来待的「学生分流」屏填的是**求职偏好**
   （想找什么、何时到岗），把简历材料塞进偏好里是错位。
   另外作品集是**整个人一份**，不是每段经历各一份，所以是屏级独立区块，
   不塞进单段经历的编辑表单。

3. 连带：全项目原先没有任何「结束日期不能早于开始」的校验，
   工作/教育/实习三处都能存下 `2020.09 — 2018.06`。已补。
