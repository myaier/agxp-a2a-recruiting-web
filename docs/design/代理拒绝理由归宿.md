# 代理拒绝理由：两屏删除，洞察搬进代理简报（用户 2026-08-22 定 · 方案 C）

## 背景

求职端 `未通过说明`（`/rejected`）与招聘端 `候选未通过`（`/hr/rejected`）两屏早已写完，
但**全项目零入口**，只能手敲地址进；进去之后按返回会退到空白页、直接退出 app
（`返回` = `前往(-1)`，而它是历史第一格，前面没有可退的）。
没有来处 → 也没有去处，是同一个问题的两面。

用户问「这个是不是就没用，没用的话就删了吧」，随后选了 C。

## 三个选项与选择

| | 成本 | 结果 |
|---|---|---|
| A 全删 | 零 | 干净，但那条洞察也没了 |
| B 新建列表让它有入口 | 大 | 完整回看面 + 洞察 |
| **C 只把洞察搬进代理简报，两屏都删** | 小 | **选定** |

## 为什么两屏可以删

**招聘端 `候选未通过` 是真重复**：它的上半部分（硬性核对逐条 + 代理小结）
与 2026-08-21 新建的 `初筛记录 → 初筛对话` 讲同一件事、同一个候选。
接入口只会得到两个长得很像的页面。

**求职端 `未通过说明` 的解释部分价值有限**：用户不会主动去找「我被拒的记录」，
为它新建一个列表屏 + 扩数据 + 接撤销，不划算。

## 唯一要保住的东西

那张放宽卡 —— 它不是文案，是**聚合洞察 + 一个真动作**：

> 要不要松一档？近 7 天有 **4 个**岗位卡在「不接受大小周」。
> 若改成「可谈，但需额外补偿」，本周预计多 **3 个**可谈岗位。
> ［维持红线］［改成可谈］

点「改成可谈」会派发 `新增规则`（招聘端是 `企业新增规则`）写进代理规则库，
再跳规则库/代理设置让用户当场看到结果。这是全 app 里少有的
「代理在替你想，而不只是执行」的地方。

## 落点

搬进**代理简报**（求职端 `问AI代理` 的日报卡、招聘端 `企业问AI代理` 的日报卡）。
理由：用户打开代理就看见「你这条红线这周挡掉 4 个岗，要不要松」，
不需要先想到「我去哪看被拒的」。这条洞察本来就属于「代理主动汇报」，
不属于「用户主动回看」。

两端的 `新增规则` / `企业新增规则` 动作都已存在，不需要动状态层。

## 删除清单

- `src/屏幕/未通过说明.tsx` + `.module.css`
- `src/屏幕/候选未通过.tsx` + `.module.css`
- 路径表与 应用.tsx 里的两条路由
- 两份数据里只服务这两屏的部分（放宽卡的数据要保留，搬去简报用）

## 不要做的事

**以后再看到这两屏是孤儿，不要「给它接个入口」** —— 那正是本次否掉的方案 B。
它们已经被删除，洞察在代理简报里。
