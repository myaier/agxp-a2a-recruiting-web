  小字用内联样式（`--最弱` 次要弱色），与共用 CSS 的默认规则互不干扰。
- **`use后端详情动作.ts` S1 分支**（Task 5 的返回合同不变，填 `简历选择/披露确认` 两槽）：
  - 五动作卡（accept/decline/retry/replace/decide_resume_screening）从 `视图.actions` 映射
    交集出卡、标题/说明原样，经共用 `详情动作卡` 渲染；`写中` 期间 `执行:null`（真实 disabled）。
    retry 无阶段区 typed 附件时 `按钮们: []`（卡框架在、零控件零请求，fail closed）。
  - **键→真实文件版本映射**：`开始选择` 每次重跑 `准备候选委托简历`（多份开单选层、单份直达
    披露确认、空库轻提示+跳 `路径.我的简历`、null 静默返回），hook 持 `待选择.文件们
    (BFF附件简历[])`；`简历选择属性.文件们` 由控制投影为 `{键:file_id, 文件名:display_name,
    状态文:附件状态文案(条), 禁用说明:null}`；确认时按 `选中键` 找回所选行经既有
    `从附件行取选择值` 取真实 `{fileId,fileVersionId,displayName}` —— 展示永不推断坐标，

    'not_fit')`）三处文案与旧实现逐字一致；通过初筛仍直发 `决定S1(caseId,'continue')`。
  - 生命周期：复用 hook 既有 `代际`（卸载+换 case 递增）兼作委托准备栅栏 —— 迟到的权威库

## 自检结论（brief 完成标准）

- 真实 `file_id/file_version_id` 不由展示推断：✅ 展示只收 `键/文件名/状态文/禁用说明`；
  坐标映射（`从附件行取选择值` / 阶段区 typed 附件）全在控制层，同名不同版本用例钉住。

  确认；换 Case 迟到库结果代际作废用例钉住。
- 取消/遮罩/Esc 不提交：✅ 展示三路只走 `取消`，hook 取消收层零请求。
- 复用 `附件简历选择层.module.css` 不改默认规则：✅ CSS 文件零改动，`附件简历选择层` 本体
  与其测试零改动（102 例内全绿）。
- 不改 BFF schema/URL/decoder/授权/状态机：✅ 映射、decoder、操作层零改动。
